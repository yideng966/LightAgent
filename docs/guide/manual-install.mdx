## Source Code Deployment

### 1. Clone the project

```bash
git clone https://github.com/yideng966/LightAgent
cd LightAgent/
```

<Tip>
  For network issues, use the mirror: https://github.com/yideng966/LightAgent
</Tip>

### 2. Install dependencies

Core dependencies (required):

```bash
pip3 install -r requirements.txt
```

Optional dependencies (recommended):

```bash
pip3 install -r requirements-optional.txt
```

To connect a personal WeChat group from a source deployment, install Node.js and the sidecar dependencies:

```bash
cd channel/wechat_group/sidecar
npm install
cd ../../..
```

### 3. Install LightAgent CLI

Install the command-line tool for managing services and skills:

```bash
pip3 install -e .
```

Then use the `lightagent` command:

```bash
lightagent help
```

<Note>
  This step is recommended. After installation you can use `lightagent start`, `lightagent stop`, `lightagent update` to manage the service, and `lightagent skill` to manage skills. Without the CLI, you can use `./run.sh` or `python3 app.py` to run.
</Note>

### 4. Configure

Copy the config template and edit:

```bash
cp config-template.json config.json
```

Fill in model API keys, channel type, and other settings in `config.json`. See the [model docs](/models/index) for details.

### 5. Run

**Using LightAgent CLI (recommended):**

```bash
lightagent start
```

**Or run locally in foreground:**

```bash
python3 app.py
```

By default, the Web console starts. Access `http://localhost:9899` to chat.

**Background run on server (without CLI):**

```bash
nohup python3 app.py & tail -f nohup.out
```

<Tip>
  **Deploying on a server?** By default `web_host` only listens on `127.0.0.1` (local access). Set `web_host` to `0.0.0.0` in `config.json` to make the console reachable from outside, and set `web_password` to protect it. Don't forget to open port `9899` in your firewall or security group — ideally restricted to specific IPs.
</Tip>

## Docker Deployment

Docker deployment does not require cloning source code or installing Python, Node.js, or npm dependencies. The image includes `/usr/local/bin/node`, the personal WeChat group Wechaty sidecar, and its locked production dependencies. Use a source deployment only when Agent mode needs broader access to the host system.

<Note>
  Requires [Docker](https://docs.docker.com/engine/install/) and docker-compose.
</Note>

**1. Download Compose**

```bash
curl -O https://raw.githubusercontent.com/yideng966/LightAgent/master/docker/docker-compose.yml
```

You can start directly without creating `.env`. If `WEB_PASSWORD` is unset, the entrypoint generates a strong random password and persists it in `./config/config.json`. To choose a fixed password, copy `docker/.env.example` to `.env` beside the Compose file and edit it; never commit the real value to Git.

**2. Start container**

```bash
sudo docker compose up -d
sudo docker compose logs lightagent
```

The logs print the automatically managed Web console password. Open `http://localhost:9899`, sign in, configure a model, then go to **Channel Management -> Add Channel -> Personal WeChat Group** to scan the QR code. Docker users do not run the sidecar `npm install` on the host.

**3. View logs**

```bash
sudo docker logs -f lightagent
```

Compose uses two persistent directories relative to `docker-compose.yml`:

- `./config` mounts at `/home/agent/.lightagent`. It stores `config.json`, secrets, logs, plugin configuration and user-installed plugins, WeChat login state, media, and group databases. Despite its name, it is not only a configuration-file directory; back it up as a whole.
- `./data` mounts at `/home/agent/lightagent`. It stores the Agent workspace, memories, knowledge base, skills, MCP configuration, and scheduler data. Generated images are persisted in `./data/images` (`/home/agent/lightagent/images` inside the container).
- `/app` belongs to the image and contains application code, Playwright, and sidecar `node_modules`. Do not mount a volume over it.

Compose binds the Web service to `0.0.0.0` and generates a password when one is not supplied. Restrict inbound port `9899` in your firewall or security group when exposing it publicly. Restarting or recreating the container does not overwrite `./config` or `./data`.

## Core Configuration

```json
{
  "channel_type": "web",
  "model": "deepseek-v4-flash",
  "deepseek_api_key": "",
  "agent": true,
  "agent_workspace": "~/lightagent",
  "agent_max_context_tokens": 40000,
  "agent_max_context_turns": 30,
  "agent_max_steps": 15,
  "lightagent_lang": "auto"
}
```

| Parameter | Description | Default |
| --- | --- | --- |
| `channel_type` | Channel type | `web` |
| `model` | Model name | `deepseek-v4-flash` |
| `agent` | Enable Agent mode | `true` |
| `agent_workspace` | Agent workspace path | `~/lightagent` |
| `agent_max_context_tokens` | Max context tokens | `40000` |
| `agent_max_context_turns` | Max context turns | `30` |
| `agent_max_steps` | Max decision steps per task | `15` |
| `lightagent_lang` | Language for the UI, command text and system prompts; `auto` to detect, or set `zh` / `en` | `auto` |

<Tip>
  Full configuration options are in the project [`config.py`](https://github.com/yideng966/LightAgent/blob/master/config.py). For Docker, configure models and channels in the Web console; changes are persisted in `./config/config.json`. Do not inject empty API-key or model environment variables in Compose, because they override saved values.
</Tip>
