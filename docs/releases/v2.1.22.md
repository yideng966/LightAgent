> LightAgent - 多渠道 Agent Harness 与可长期运行的 AI 助手框架

本版本为个人微信群增加可灰度启用的上下文与会话引擎 V2。机器人现在能够区分群内现场、成员会话和短期话题线程，并在微信确认发送成功后再提交回复状态，减少新旧话题串线、迟到插话和失败回复污染历史的问题。

## 新增功能

- 新增分层群聊上下文：根据当前请求选择精简、最近、承接或历史召回模式；普通自然语言 @ 请求可以读取同一群内有界的最新对话现场，同时过滤当前消息、重复来源和不安全传输内容。
- 新增非破坏式话题线程：独立问题创建新线程，明确“继续”或引用机器人时恢复同群同成员的有效线程，普通自由接话保持只观察；切换话题不再清空此前会话。
- 新增按群回复协调、滚动摘要和安全工具续接。滚动摘要保留最近原文，工具续接只短时保存经过清洗的只读结果，不恢复原始工具链或跨群数据。
- Web 控制台“群聊 -> 拟人化上下文”新增 V2 模式、会话作用域、线程有效期、按群单路回复、滚动摘要和工具续接设置。

## 优化改进

- 同一个群的最终回复按顺序生成和发送，明确 @ 请求优先于尚未开始的自由接话；群现场已变化时，过时的自由回复会在发送前被抑制。
- 高频图片、总结、历史召回、链接、定时提醒和群记忆请求会收窄到相关工具，原有管理员权限和群成员写操作限制继续生效。
- 模型切换、进程重启或线程缓存淘汰后，可从本地保存的用户原文和最终答复恢复上下文，不依赖供应商连接或隐式服务端会话。

## Bug 修复

- 修复微信发送失败、回执未知、回复被清洗为空或过时自由回复被取消后，仍可能推进 Agent 历史、话题线程或工具续接状态的问题；这些状态现在只在 sidecar 明确确认发送成功后提交。

> Context Engine V2 本版本默认仍为 `legacy`，滚动摘要和工具续接也默认关闭。建议先在单个测试群灰度验证，再逐项启用；旧配置和其他渠道的会话行为保持不变。

## 安装

**Docker Hub：**

```bash
docker pull yideng966/lightagent:v2.1.22
```

**GitHub Container Registry：**

```bash
docker pull ghcr.io/yideng966/lightagent:v2.1.22
```

**完整技能镜像：**

```bash
docker pull yideng966/lightagent:v2.1.22-skills-full
docker pull ghcr.io/yideng966/lightagent:v2.1.22-skills-full
```
