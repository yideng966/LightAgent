title: 更新升级
description: LightAgent 的升级方式说明
---

## 命令升级（推荐）

使用 `lightagent update` 一键完成代码更新和服务重启：

```bash
lightagent update
```

该命令会自动完成以下流程：

1. 拉取最新代码（`git pull`）
2. 停止当前服务
3. 更新 Python 依赖
4. 重新安装 CLI
5. 启动服务

<Note>
  如果未安装 LightAgent CLI，也可以使用 `./run.sh update` 完成相同操作。
</Note>

## 手动升级

在项目根目录下执行：

```bash
git pull
pip3 install -r requirements.txt
pip3 install -e .
```

更新完成后重启服务：

```bash
# 使用 LightAgent CLI (推荐)
lightagent restart

# 或使用 run.sh
./run.sh restart

# 或使用 nohup 直接运行
kill $(ps -ef | grep app.py | grep -v grep | awk '{print $2}')
nohup python3 app.py & tail -f nohup.out
```

## Docker 升级

当前双目录 Compose 布局升级时，先停止容器并同时备份 `./config` 与 `./data`，再拉取镜像并重建：

```bash
sudo docker compose stop
cp -a config config.backup
cp -a data data.backup
sudo docker compose pull
sudo docker compose up -d
```

<Tip>
  `docker compose pull` 和 `docker compose up -d` 不会覆盖这两个 bind mount。`./config` 包含配置、密钥、日志、插件配置与用户插件、微信登录态、媒体和群数据库，`./data` 包含 Agent workspace、记忆、知识库、技能、MCP 和 scheduler；两者必须一起备份。不要备份或挂载 `/app`，该目录应随镜像升级。
</Tip>

如果从旧版单一 `./lightagent` 挂载迁移，替换 Compose 前应保留旧容器：把旧 `./lightagent` 内容复制到新的 `./data`，把容器内 `/app/config.json` 复制为 `./config/config.json`，把可识别的用户安装插件复制到 `./config/plugins`，并把 `/home/agent/.lightagent` 中的私有运行数据迁入 `./config`。不要复制同名内置插件覆盖新镜像。真实个人微信群登录态只有进入 `./config` 后，才能在容器重建后保留；完成备份与迁移后再执行 `docker compose up -d`。
