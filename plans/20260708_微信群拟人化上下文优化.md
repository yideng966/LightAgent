# 微信群拟人化上下文优化 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按 BaiLongmaPro 的“当轮厚上下文、历史不污染、回复像群成员”思路重构 CowAgent 个人微信群回复链路，让机器人更自然、更会承接上下文，同时保留 CowAgent 统一 Agent、工具、记忆和权限主链路。

**Architecture:** 允许删除、修改和重构当前微信群通道里的局部实现，但不新建独立 Agent loop、不绕过 `Bridge.fetch_agent_reply()`、不把模型调用搬进 `channel/wechat_group/`。核心改造参考 `D:\JiangShuai\SourceCode\BaiLongmaPro\src\social\wechat-groups.js` 的 `buildWeChatGroupCommandPrompt()`：当轮组装 mention / ambient / persona / quote / archive evidence / recent transcript / local summary 等厚上下文；在 CowAgent 中收口到 `WechatGroupHumanizedContextBuilder`，由它按触发来源和意图构造当轮增强消息；`AgentBridge` 在运行前预持久化用户原文，运行后清洗内存里的增强消息；Web 控制台重构为“群管理 -> 拟人化”单入口管理这些策略。

**Tech Stack:** Python、unittest、SQLite 消息归档、CowAgent `ChatChannel -> Bridge -> Agent` 主链路、Web 控制台 `channel/web/static/js/console.js`、配置中心 `config.py` / `config-template.json`

## 0. 修订说明

本文件是 2026-07-08 复核后的修订版，替代同名计划的旧版执行内容。旧版偏“增量加 prompt 块”，复核后发现它和现有逻辑存在这些冲突：

1. 自由回复判断依赖 `suppress_mention`，但该字段在 `_compose_context()` 之后才设置。
2. Agent 运行后内存消息清洗需要在 `agent.messages_lock` 内同步处理 `agent.messages` 和 `_last_run_new_messages`。
3. 归档证据构造发生在 `_record_inbound_message()` 之后，必须排除当前消息，否则会把用户本轮问题当证据。
4. 旧计划的 `archive_evidence_days` 语义是“检索天数”，实现却只取最近 N 条消息，产品语义不一致。
5. Web UI 只挂 `buildWechatGroupSettingsPanel()` 不够，当前主要管理入口是 `renderGroupsView()` 的群管理分栏。
6. 旧计划中的部分 `unittest` 示例是顶层函数，不能被当前测试命令发现。

本修订版按上述问题重新组织任务，并明确允许对现有功能做必要删除、修改和重构。

### 0.1 本轮方案定稿

用户确认由实现者直接确定方案，并允许重构现有 UI 与原有逻辑。最终方案采用以下取舍：

1. 行为蓝本采用 BaiLongmaPro 的 `buildWeChatGroupCommandPrompt()`：每轮都把当前触发来源、用户原文、去 @ 后请求、引用策略、归档证据、最近群聊和本地摘要组织成一个当轮厚上下文。
2. CowAgent 不照搬 BaiLongmaPro 的独立发送调度和工具调用方式；所有模型回复仍走 `ChatChannel -> Bridge.fetch_agent_reply() -> Agent`。
3. 增强上下文只服务本轮推理；对话库预持久化、Agent 内存历史和下一轮恢复都只保留用户原文。
4. Web 控制台允许重构旧控件归属：微信群拟人化配置只在“群管理 -> 拟人化”维护；通道卡片只保留连接、群选择、人设等轻量入口，避免同一配置双写。
5. 旧 recent context 行为不再作为运行时模式保留。`wechat_group_recent_context_*` 只作为按需注入的基础开关和窗口参数。
6. 块命名向 `AGENTS.md` 收敛：群长期记忆和画像块统一为 `<wechat-group-memory>`；旧 `<wechat-group-knowledge>` 只作为实现过渡兼容，不再作为新计划目标。

## 1. 目标行为

### 1.1 群聊效果

1. @ 机器人时直接回答，不说“你叫我了”“收到”“我来整理一下”。
2. 自由回复只在通过现有本地评分和 LLM judge 后短句接话，不默认 mention，不长篇解释。
3. 独立问题不强行携带大量旧群聊；只有“刚才、上面、谁说、总结、继续、引用、图片、链接”等上下文依赖请求才注入归档证据和摘要。
4. 问“刚才谁说的”时，答案基于当前群归档证据，并能说明候选发言人。
5. 问“总结上面”时，先用本地抽取摘要形成结构化事实，再让 LLM 组织自然语言。
6. 看图、引用、链接场景不暴露 `message_id`、XML、base64、本机路径、`media_path` 或 prompt 标签。
7. 多轮历史中只保留用户原文，不把上一轮 `<wechat-group-*>` 块带入下一轮。

### 1.2 架构边界

继续保留：

1. `ChatChannel` 的群白名单、@ 触发、引用触发、自由回复入口。
2. `Bridge.fetch_agent_reply()` 和 CowAgent 统一 Agent 主链路。
3. 现有管理员权限过滤、Agent 工具过滤、群记忆、画像、焦点栈、风格、情绪、多模态服务。

允许重构：

1. `WechatGroupChannel._compose_context()` 由大段拼装函数改成轻量编排函数。
2. 最近上下文从“默认总是注入大量 transcript”改成“按意图注入 slim transcript / evidence / summary”。
3. 删除或替换计划实施后不再需要的私有拼装 helper，但要保留外部测试仍需要的公共 formatter。
4. Web 群管理页新增拟人化分栏，并调整保存 payload。

不做：

1. 不新增独立模型调用。
2. 不把 Wechaty sidecar 变成业务 Agent。
3. 不做跨群画像合并。
4. 不改桌面端 UI。

## 5. 目标数据流

```text
sidecar event
  -> WechatGroupMessage
  -> WechatGroupChannel.handle_text()/handle_image()
  -> ChatChannel._compose_context()
  -> WechatGroupChannel 保存 room/sender/raw_user_content/trigger_source/is_free_reply
  -> _record_inbound_message()
  -> WechatGroupHumanizedContextBuilder.build()
       - resolve intent
       - build reply policy
       - build persona
       - search archive evidence with exclude_message_id
       - build local extractive summary with exclude_message_id
       - decide whether this turn actually needs recent transcript
       - reuse focus/memory/style/emotion/multimodal services
       - build reference policy
  -> context.content = enhanced_message + raw_user_content
  -> Bridge.fetch_agent_reply()
  -> AgentBridge select raw_user_content before pre-persist
  -> AgentBridge pre-persist raw_user_content
  -> Agent.run_stream(enhanced_message)
  -> AgentBridge lock and replace current user message in agent.messages / _last_run_new_messages
  -> WechatGroupChannel.send()
       - cleanup text
       - silent suppression
       - typing delay based on cleaned text
       - send_text / send_image / ...
       - archive final sent content
```

- [ ] **Step 2: 实现 `search_messages()`**

在 `WechatGroupArchive` 增加：

```python
def search_messages(
    self,
    room_id: str,
    query: str = "",
    since_ts: int = 0,
    until_ts: int = None,
    limit: int = 20,
    exclude_message_id: str = "",
) -> List[Dict[str, Any]]:
    ...
```

实现要求：

1. SQL 必须 `WHERE room_id = ?`。
2. 必须限制 `created_at >= since_ts` 和 `created_at <= until_ts`。
