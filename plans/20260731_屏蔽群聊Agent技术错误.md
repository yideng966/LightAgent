# 屏蔽群聊 Agent 技术错误开发计划

## 关联问题

- GitHub Issue：#26
- 标题：Agent 错误不应该发送到群聊

## 目标

微信群不得原样发送 `Agent error:`、Provider 异常类名、请求参数、状态码或反序列化细节。明确触发请求只返回简短用户提示，普通自由回复等 ambient 请求静默结束。

## 边界

- 只调整微信群发送边界，不改变 Web、CLI 或其他渠道当前错误展示策略。
- 保留管理员权限、配额等面向用户且可行动的业务错误。
- 覆盖 Issue 中 `reasoning_effort=none` 被兼容端点以 422 拒绝的实际错误形态。
- 技术错误仍写入日志用于排查，但不得进入群消息或群聊助手归档。

## 实施步骤

1. 核对 `ReplyType.ERROR` 从 Agent 到微信群发送层的现有分类和清洗逻辑。
2. 将 Provider 协议/参数/反序列化类错误统一归类为内部技术错误。
3. 对明确触发和 ambient 请求分别应用简短提示与静默策略。
4. 增加 Issue 原始错误文本、其他协议错误和业务错误不被误拦截的回归测试。
5. 更新当前文档、`AGENTS.md`、`CHANGES.md` 并回写本计划。
6. 以单独 Git 提交交付 Issue #26；全部发布引用推送成功后关联关闭问题。

## 实际改动与验证结果

- 将微信群发送边界中所有以 `Agent error:` 开头的 `ReplyType.ERROR` 统一识别为内部技术错误；限流、超时类仍使用现有 Token 提示，其余明确触发请求使用通用简短提示。
- 明确触发判定排除 `wechat_group_is_free_reply=True` 和 `wechat_group_trigger_source=free_reply`，避免自由回复因内部 `force_reply` 标记而向群内发送错误提示。
- 管理员权限等业务错误及不带 `Agent error:` 前缀的工具错误保持原发送行为。
- 新增 Issue 原始 422、未知 Agent 错误、两种 ambient 标记、业务错误、工具超时和限流提示回归覆盖。
