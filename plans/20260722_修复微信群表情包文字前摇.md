# 修复微信群表情包文字前摇实施计划

**状态：** 已完成（2026-07-22）

**目标：** 修复个人微信群通过 `wechat_group_sticker_send` 回复表情包时，先发送模型生成的文件名文字、再发送表情包的问题；表情包回复应只发送媒体消息。

## 根因

`AgentBridge` 将 Agent 调用表情包工具后的最终文本统一写入图片回复的 `text_content`。`ChatChannel._send_reply()` 对带 `text_content` 的 `IMAGE_URL` 会先发文字再发图片，因此模型返回的“（暴漫坏笑.gif）”被作为独立文字消息发送。

## 修改范围

1. 在 `AgentBridge._create_file_reply()` 中识别带 `sticker_id` 或 `online_id` 的微信群表情包文件，只返回图片回复，不附加 `text_content`。
2. 普通图片和文件继续保留现有图文回复能力。
3. 增加本地与在线表情包不附带文字、普通图片仍附带文字的回归测试。
4. 更新 `AGENTS.md` 与 `CHANGES.md`，记录行为边界和验证结果。

## 验证

- 运行 `python -m unittest tests.test_wechat_group_agent_bridge_tools tests.test_wechat_group_message tests.test_wechat_group_channel tests.test_wechat_group_web`。
- 运行 `python -m py_compile bridge/agent_bridge.py`。
- 运行 `git diff --check` 并检查提交范围。
- 推送后使用现有 `cow restart --no-logs` 方式重启，核对 `.cow.pid`、新进程命令行和启动日志。

## 回滚

回退本次提交即可恢复原有图文发送行为；不涉及配置、数据库或 sidecar 协议迁移。

## 实际改动

1. `bridge/agent_bridge.py` 在创建图片回复时，按当前 `channel_type = wechat_group` 与表情包 `sticker_id` / `online_id` 双重条件识别表情包回复，不再写入 `text_content`。
2. `tests/test_wechat_group_agent_bridge_tools.py` 覆盖本地表情包、在线表情包和普通图片，确认只抑制表情包附加文字。
3. `AGENTS.md` 固化表情包只发送媒体、普通图文保持原行为的协作边界。
4. `CHANGES.md` 记录本次修复及验证结果。
