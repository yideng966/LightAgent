# PR #15 微信群自由回复 Scorer 问题修复方案

## 目标

在保留 PR #15 “自由回复 Scorer 复用共享 `TextModelRouter.complete()`”总体方向的前提下，修复自定义 Provider 生命周期、运行时路由缓存、失败回落和请求级模型控制四类问题，确保：

- Scorer 只向用户明确选择且仍然有效的 Provider 发送群聊上下文。
- 模型管理修改凭据后，无需重启微信群通道即可对后续 Scorer 请求生效。
- Scorer 异常时不会把原本低于本地阈值的消息错误放行。
- 请求级禁用思考、结构化输出和 Token 上限按 Provider 能力明确生效，不影响主聊天模型配置与熔断状态。

## 当前结论

- PR 的主架构方向保留：Scorer 继续作为微信群渠道的判定适配层，调用共享文本模型路由；最终回复继续走 `WechatGroupChannel -> ChatChannel -> Bridge -> Agent` 主链路。
- 不恢复独立 API Base、API Key、HTTP 客户端或独立模型调用。
- 不修改桌面端，不新增全局依赖，不扩展微信群通道职责边界。

## 问题 1：自定义 Provider 删除后可能路由到错误凭据

### 原因

`ModelsHandler._handle_delete_custom_provider()` 删除自定义 Provider 时，只处理主聊天 `bot_type`，没有检查 `wechat_group_free_reply_scorer_provider`。路由层找不到 `custom:<id>` 时又会保留一个未按该 Provider 配置的 `ChatGPTBot`，存在使用主聊天或其他 Provider 凭据发送 Scorer 上下文的风险。

### 修改方案

1. 在 `channel/web/web_channel.py` 删除自定义 Provider 前检查 Scorer 引用。
2. 若 `wechat_group_free_reply_scorer_provider == custom:<待删除 id>`，拒绝删除并返回明确错误，提示用户先在「模型管理 -> LLM Scorer」切换 Provider。
3. 在 `bridge/agent_bridge.py` 增加防御性校验：显式 `custom:<id>` 不存在、缺少 API Base 或缺少必要凭据时直接抛出可识别配置错误，不得回退到全局聊天 Provider。
4. 保持 Scorer 失败闭合；配置错误只进入既定回落策略，不直接发送回复。

### 验证

- 删除未被 Scorer 使用的自定义 Provider 成功。
- 删除正被 Scorer 使用的 Provider 被拒绝，配置文件和内存配置均不变化。
- 手工构造不存在的 `custom:<id>` 时，Router 不创建使用主聊天凭据的请求。
- 日志和 Web 响应不回显 API Key。

## 问题 2：模型凭据更新后 Scorer 继续持有旧 Router

### 原因

`WechatGroupFreeReplyScorer` 在初始化时保存 `Bridge().get_text_model_router()`；模型管理更新 Provider 后虽然执行 `Bridge.reset_bot()`，已经创建的 Scorer 仍引用旧 Router，其 `_candidate_bots` 也继续缓存旧客户端。

### 修改方案

1. 调整 `WechatGroupFreeReplyScorer` 的 Router 获取方式：
   - 测试显式传入 `router` 时继续使用注入对象。
   - 生产环境未注入 Router 时，在每次评分前通过 `Bridge().get_text_model_router()` 获取当前共享实例。
2. 不在微信群通道中维护第二套路由刷新事件或全局缓存失效总线，避免扩大改动。
3. 保留 Router 内部按 Provider/模型缓存 Bot 的现有行为；模型管理执行 `Bridge.reset_bot()` 后，下一次 Scorer 请求自然使用新 Router 和新凭据。

### 验证

- 同一 Provider/模型修改 API Key 或 API Base 后，下一次评分使用新 Router。
- 未修改配置时，多次评分仍复用同一个共享 Router，不为每次请求创建独立 Bridge。
- 单元测试注入的 Fake Router 行为保持不变。
- 主聊天会话、主备路由和熔断状态不被 Scorer 覆盖请求修改。

## 问题 3：失败回落绕过本地阈值

### 原因

启用 Scorer 后，仅有 `below_threshold` 的消息会被临时放入 worker。Scorer 失败并允许回落时，如果旧 LLM Judge 已关闭，当前逻辑会直接批准消息，丢失 Scorer 介入前的本地判定结果。

### 修改方案

1. 在 `_should_enqueue_free_reply_message()` 中保留 Scorer 介入前的本地结果，例如 `local_rule_triggered`，不要只依赖随后被强制改写的 `triggered`。
2. Scorer 成功时继续以 Scorer 决策为准。
3. Scorer 失败且 `scorer_fallback_to_rules = false` 时继续失败闭合。
4. Scorer 失败且允许回落时：
   - `llm_judge_enabled = true`：进入原有共享 `TextModelRouter.complete()` Judge。
   - `llm_judge_enabled = false`：恢复本地规则结果；原本只有 `below_threshold` 的候选必须拒绝，原本已通过本地规则的候选可以批准。
5. 复读和显式强触发词继续沿用现有本地快路径，不改变禁言、冷却、黑名单、敏感内容和媒体等硬抑制。

### 验证

- `below_threshold + scorer_error + fallback=true + llm_judge=false` 必须拒绝。
- 本地规则原本通过的候选在相同配置下仍可批准。
- `fallback=false` 的模型错误、超时、无效 JSON 均失败闭合。
- 禁言和其他硬抑制不会因任何回落配置被绕过。

## 问题 4：请求级模型控制未覆盖全部 Provider

### 原因

Scorer 通过 `request_options` 传递 `reasoning_effort=none` 和 JSON Mode，但当前只有 `OpenAICompatibleBot` 明确展开这些参数。拥有原生 `call_with_tools()` 的 Provider 可能忽略嵌套选项，并继续读取全局思考配置或忽略 Scorer 的 Token 上限。

### 修改方案

1. 在 `TextModelRouter` 中明确请求级控制优先级：Scorer 的“禁用思考”必须覆盖全局 `enable_thinking`，但仅作用于当前请求。
2. 将请求意图分成 Provider 中立控制：
   - `thinking = disabled`
   - `max_tokens`
   - `structured_output = json_object`
3. 修改第三方 Provider 适配前先核对官方文档：
   - 支持原生 JSON Mode 的 Provider，由对应 Bot 转换为官方参数。
   - 不支持原生 JSON Mode 的 Provider 不发送未知参数，继续依赖严格 JSON Prompt 和解析失败闭合。
   - 支持思考开关的 Provider 显式关闭；不支持开关但模型强制思考时，模型管理 UI 应标记能力限制，不能宣称已禁用。
4. `OpenAICompatibleBot` 继续只转发白名单参数；不得把任意 `request_options` 透传到外部接口。
5. 更新 Web Scorer 能力返回值，提供结构化输出和思考控制支持状态；UI 对不完全支持的 Provider 显示简短状态，不隐藏错误，也不修改主模型设置。
6. 修正 `CHANGES.md` 和中文文档，不再笼统声称所有 Provider 都保证使用同一种 JSON Mode 参数。

### 验证

- OpenAI 和有效 `custom:<id>` 请求包含白名单 JSON Mode 与请求级禁用思考参数。
- DeepSeek 等原生 Bot 在全局思考开启时，Scorer 请求仍显式禁用思考；普通聊天请求继续遵循全局配置。
- 不支持 JSON Mode 的 Provider 不收到未知参数，返回非 JSON 时由严格解析和回落策略处理。
- 所有支持的 Provider 都正确使用 Scorer `max_tokens`，且主聊天请求参数不受污染。

## 实际改动

- `bridge/agent_bridge.py`：显式校验自定义 Provider，支持 legacy `custom` 配置，并让请求级 `reasoning_effort=none` 仅对当前调用关闭思考。
- `channel/wechat_group/wechat_group_free_reply_scorer.py`：生产请求每次获取当前共享 Router，测试注入 Router 的行为保持不变。
- `channel/wechat_group/wechat_group_channel.py`、`channel/wechat_group/wechat_group_free_reply_judge.py`：保留 `local_rule_triggered`，Scorer 失败且旧 Judge 关闭时恢复原本地判定。
- `channel/web/web_channel.py`、`channel/web/static/js/console.js`：阻止删除 Scorer 正在使用的自定义 Provider，返回结构化输出模式，并提示非 OpenAI-compatible Provider 使用严格 JSON Prompt 与失败回落。
- 补充模型路由、模型管理、控制台、Scorer、Judge 和微信群通道回归测试；同步更新项目规则、Web 文档与变更记录。
