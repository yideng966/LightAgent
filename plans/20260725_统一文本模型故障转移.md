# 统一文本模型故障转移开发计划

## 目标

将已有的主模型、备用模型、连续失败熔断和半开探测能力，从 Agent 推理扩展到普通聊天、会话标题及依赖聊天会话的旧插件；图片、视觉、语音和翻译继续使用各自独立 Provider。

## 实施步骤

- [x] 抽取共享 `TextModelRouter`，复用既有候选模型、临时错误识别、fallback、熔断和恢复逻辑。
- [x] 普通文本聊天改用 Provider-neutral 会话历史，失败候选不写入历史，成功回复只提交一次。
- [x] 会话标题生成和旧会话插件接入共享文本路由。
- [x] Web 模型页支持备用模型拖拽/按钮排序，并保存连续失败阈值。
- [x] 保持图片、视觉、语音和翻译的独立路由边界。
- [x] 增加路由、历史原子提交、无状态补全、配置保存和界面合同测试。
- [x] 完成全量 Python 回归并回写最终结果。

## 验收标准

1. 普通聊天和 Agent 使用同一主备模型顺序与熔断状态。
2. 主模型临时失败、备用模型成功时，会话历史只记录用户消息和最终成功回复。
3. 会话标题生成不污染聊天历史。
4. 清除记忆命令不触发模型请求。
5. 非文本能力不进入文本 fallback 链。
6. 控制台可以调整备用模型优先级，并仅接受 3、4、5 三档连续失败阈值。
