# 微信群图片理解统一优化实施计划

> **面向执行 Agent 的要求：** 实施本计划时先使用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans`，按任务逐项推进。每个任务完成后更新本文的进度、实际改动、验证结果与剩余事项。步骤使用 checkbox (`- [ ]`) 语法跟踪。

**目标：** 在已完成的全局多模态上下文注入基础上，收敛微信群图片理解遗留双轨逻辑，确保图片选择、摘要、缓存、路径脱敏和回复门控都走统一架构。

**架构：** `WechatGroupChannel` 只负责消息归档、回复门控和进入主回复链路；`WechatGroupMultimodalContextService` 统一负责多模态候选选择、Vision 摘要、摘要缓存和 prompt 块格式化。自由回复只决定“是否接话”，不直接理解图片；已经决定回复的消息统一在 `_compose_context()` 阶段注入 `<wechat-group-multimodal>`。

**技术栈：** Python `unittest`、现有 `channel/wechat_group` 渠道层、现有 `agent.tools.vision.vision.Vision`、现有 Web 控制台配置接口。

---

## 背景与当前事实

GitHub issue #14 反馈的是微信群图片理解体验问题：最近图片追问不稳定、同图重复分析未统一复用缓存、非 @ 图片可能强制回复。`plans/20260706_微信群多模态上下文全局注入.md` 已完成第一阶段，把图片理解接入 `_compose_context()` 的 `<wechat-group-multimodal>`。

当前仍有二阶段优化空间：

- `channel/wechat_group/wechat_group_channel.py` 仍保留 `_build_recent_image_understanding_content()` 与 `_build_image_understanding_content()`，其中包含独立最近图片查找、独立 Vision 摘要和独立缓存。
- `tests/test_wechat_group_channel.py` 仍有直接调用 `_build_image_understanding_content()` 的测试，会鼓励后续继续使用旧入口。
- 图片理解默认 fallback 文案在部分硬编码处存在编码异常文本，可能直接进入当前用户消息。
- 多模态服务已经是统一承载点，但缺少明确的架构守护测试，无法防止后续再次在 `handle_text()` 或自由回复 worker 中补点状图片逻辑。

## 不做范围

- 不新增视觉模型 Provider，不修改 `Vision` 工具内部实现。
- 不修改 Electron 桌面端 UI。
- 不扩大自由回复默认行为；`wechat_group_multimodal_free_reply_image_context_enabled` 继续默认关闭。
- 不改变 sidecar 下载媒体的协议和文件存储方式。
- 不做全仓编码清洗，只修正本计划触达的图片理解硬编码文案。

## 文件职责

- `channel/wechat_group/wechat_group_channel.py`：保留回复门控、`_compose_context()` 上下文编排、发送适配；移除图片理解旧 builder 和旧图片摘要缓存状态。
- `channel/wechat_group/wechat_group_multimodal_context_service.py`：唯一的微信群多模态上下文装配服务，负责图片候选选择、Vision 调用、摘要缓存、路径脱敏和诊断信息。
- `tests/test_wechat_group_multimodal_context_service.py`：覆盖候选选择、缓存复用、失败降级、路径脱敏和诊断信息。
- `tests/test_wechat_group_channel.py`：覆盖通道层只做门控和统一注入，不直接调用旧图片理解 builder。
- `tests/test_wechat_group_context.py`：继续守护 recent transcript 不泄露本机媒体路径。
- `CHANGES.md`：执行代码变更时记录实际改动和验证结果；本计划文档创建阶段不更新。

## 验收标准

- 代码中不再存在 `WechatGroupChannel._build_recent_image_understanding_content()` 和 `WechatGroupChannel._build_image_understanding_content()`。
- 通道层图片回复、@ 文本追问、引用图片追问、自由回复通过后的图片追问，都通过 `WechatGroupMultimodalContextService.build_context()` 注入。
- `Vision().execute()` 只在多模态服务中调用，通道层不直接调用 Vision。
- 同一 `image_path + question` 的摘要缓存由多模态服务统一复用。
- `<wechat-group-multimodal>` 和 `<recent-wechat-group-transcript>` 不输出本机绝对媒体路径。
- 非 @ 图片默认只归档；自由回复图片理解仍受 `wechat_group_free_reply_image_understanding_enabled` 独立开关控制。

## 手动验证建议

1. 启动 CowAgent，进入 Web 控制台通道管理，连接个人微信群。
2. 在测试群直接 `@机器人` 发送一张图片，确认回复基于图片内容且真实 mention 发送者。
3. 同一用户先发图片，再 `@机器人 这是真的吗`，确认绑定同一群最近图片。
4. 引用某张图片后问 `这张图看看`，确认优先绑定被引用图片。
5. 群里多人连续发多张图片，再用不明确短句追问，确认机器人不乱认图。
6. 不开启自由回复图片理解时，普通非 @ 图片只归档不回复。
7. 开启自由回复图片理解并限制到测试群后，普通非 @ 图片只有通过自由回复门控和 LLM judge 后才回复，且默认不 mention 原发送者。

## 回退方案

- 配置级回退：设置 `wechat_group_multimodal_context_enabled = false`，关闭全局多模态上下文注入。
- 图片摘要级回退：设置 `wechat_group_multimodal_image_understanding_context_enabled = false`，保留引用/转发/视频元信息但不做图片摘要。
- 自由回复近图绑定回退：设置 `wechat_group_multimodal_free_reply_image_context_enabled = false`。
- 代码级回退：恢复本计划涉及的 `wechat_group_channel.py`、`wechat_group_multimodal_context_service.py` 和对应测试改动；不需要修改 sidecar 协议。
