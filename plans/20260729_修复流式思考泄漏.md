# 修复流式思考泄漏计划

## 背景

远端 `v2.1.17` 在微信群 Agent 回复中出现模型思考过程与 `</think>` 标签被当作普通正文发送的问题。只读日志确认该请求在主模型因 429 熔断后使用备用模型，备用模型将思考块写入流式 `content`；现有过滤逻辑逐分片执行无状态正则，无法识别跨分片的 `<think>...</think>`。

## 目标

- IM 渠道不发送或持久化内嵌 `<think>` 思考内容。
- 支持开始标签、结束标签及标签本身跨任意 SSE 分片。
- Web 保持现有行为：保留内嵌思考正文，但不显示原始标签。
- 标准 `reasoning_content` 继续与最终正文隔离。

## 风险控制

- 不调整模型配置、故障转移顺序或思考开关语义。
- 不修改渠道发送协议，只修正进入普通正文前的解析结果。
- 未闭合思考块在 IM 渠道按 fail closed 处理，避免残余思考内容继续外泄。

## 实际改动

- 在 `agent/protocol/agent_stream.py` 新增 `_ThinkTagStreamFilter`，跨分片保存标签前缀与思考块状态。
- IM 渠道只输出思考块之外的正文；Web 开启思考时保留块内正文，但两者都不输出原始标签。
- 流式结束和取消路径均处理待定标签前缀；正常结束时重新净化完整原始正文，净化结果作为最终回复与持久化内容。
- 新增 `tests/test_agent_stream_thinking_filter.py`，覆盖线上泄漏形态及相关边界。
