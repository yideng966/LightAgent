# 发布版本元数据同步计划

## 背景

当前发布构建只更新部分版本来源：Docker 标签构建会写入 `cli/VERSION`，但 `pyproject.toml` 仍保留 `1.0.0`；桌面发布也未在打包 Python 后端前同步这两个文件。因此，`pip show lightagent` 与 Web/API、CLI 展示的版本可能不一致。

## 目标

- 使用发布标签或手动构建版本作为本次构建的唯一版本值。
- 在 Docker 安装 Python 包和桌面后端打包前，同时写入 `cli/VERSION` 与 `pyproject.toml`。
- 对版本格式、目标字段和工作流执行顺序增加最小回归验证。

## 实施步骤

- [x] 核对当前版本来源、Docker 发布流程和桌面发布流程。
- [x] 新增统一版本写入脚本，并接入两条发布工作流。
- [x] 补充脚本行为与工作流顺序测试。
- [x] 更新协作规则和变更记录。
- [x] 完成测试、静态检查、Git 提交与推送。

## 修改边界

- 不改变现有标签命名、镜像标签、桌面包版本和 Release 创建规则。
- 不在普通开发启动流程中自动改写版本文件。
- 不创建或推送新标签，仅提交发布构建修复。

## 当前状态

已完成。Docker 与桌面发布会在 Python 安装或打包前同步两个版本来源；14 项发布相关测试、Python 编译、脚本入口、工作流 YAML 解析和差异检查均已通过。
