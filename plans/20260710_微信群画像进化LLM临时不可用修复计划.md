# 微信群画像进化 LLM 临时不可用修复计划

> **面向执行 Agent 的要求：** 实施本计划时先使用 `superpowers:systematic-debugging` 复核根因，再使用 `superpowers:test-driven-development` 按测试先行推进。步骤使用 checkbox (`- [ ]`) 跟踪；完成后必须回写本文的实际改动、验证结果与剩余事项。

**目标：** 当画像自主进化调用 LLM 时遇到 HTTP 503、429、超时等临时供应商故障，系统应明确记录为“LLM 临时不可用”，避免误报为“画像抽取响应不是 JSON”，并降低自动触发器的重复重试噪声。

**架构：** 保持微信群画像进化现有链路不变：`WechatGroupProfileEvolutionTrigger` 仍负责空闲触发，`WechatGroupProfileEvolutionExecutor` 仍负责批次运行，`WechatGroupProfileLlmExtractor` 仍负责提示词、模型调用和 JSON 归一化。最小改造是在 extractor 识别模型错误 envelope 并抛出可分类异常，executor 记录清晰失败原因，trigger 对临时故障使用现有 idle 窗口退避。

**技术栈：** Python、`unittest`、现有 `AgentLLMModel` / `OpenAICompatibleBot` 调用链、SQLite 画像进化运行记录。

## 2. 日志现象

用户提供的日志发生在同一秒：

```text
[ERROR][2026-07-10 16:27:50][openai_compatible_bot.py:169] - [ChatGPTBot] sync response error: HTTP 503: Error from provider (Console): Inference is temporarily unavailable
[WARNING][2026-07-10 16:27:50][wechat_group_profile_evolution_executor.py:119] - [wechat_group] profile evolution failed for room wgr_7e7f4529991b46fa98e342b291bc37d6: LLM profile extraction response is not JSON
[WARNING][2026-07-10 16:27:50][wechat_group_profile_evolution_trigger.py:78] - [wechat_group] profile evolution trigger failed for room wgr_7e7f4529991b46fa98e342b291bc37d6: LLM profile extraction response is not JSON
```

结论：

- 第一条是根因级错误：OpenAI 兼容供应商返回 HTTP 503，明确说明推理临时不可用。
- 第二条是下游误分类：画像抽取器拿到错误消息后按 JSON 解析，失败后只报“response is not JSON”。
- 第三条是自动触发器对同一个异常的二次日志，不是新的独立错误。

## 3. 根因链路

代码链路如下：

```text
WechatGroupProfileEvolutionTrigger.scan_once()
  -> WechatGroupProfileEvolutionExecutor.run_once()
  -> WechatGroupProfileLlmExtractor.extract()
  -> WechatGroupProfileLlmExtractor._call_model()
  -> AgentLLMModel.call()
  -> OpenAICompatibleBot.call_with_tools()
  -> OpenAICompatibleBot._handle_sync_response()
  -> OpenAIHTTPError(status_code=503)
  -> return {"error": True, "message": "...Inference is temporarily unavailable", "status_code": 503}
  -> AgentLLMModel._format_response() 原样返回 dict
  -> _extract_model_text() 从 dict["message"] 提取错误文本
  -> _parse_json() 尝试把错误文本解析为画像 JSON
  -> ValueError("LLM profile extraction response is not JSON")
```

对应代码证据：

- `models/openai_compatible_bot.py:162-177`：`OpenAIHTTPError` 被捕获后记录 HTTP 状态，并返回 `{"error": True, "message": ..., "status_code": ...}`。
- `bridge/agent_bridge.py:188-189` 与 `bridge/agent_bridge.py:263-266`：`AgentLLMModel.call()` 调用 `bot.call_with_tools()` 后由 `_format_response()` 原样透传。
- `channel/wechat_group/wechat_group_profile_llm_extractor.py:20-31`：extractor 通过 `model.call(LLMRequest(...))` 获取响应。
- `channel/wechat_group/wechat_group_profile_llm_extractor.py:145-154`：`_extract_model_text()` 会从 dict 的 `message` 字段提取文本。
- `channel/wechat_group/wechat_group_profile_llm_extractor.py:88-99`：非 JSON 文本被统一转成 `ValueError("LLM profile extraction response is not JSON")`。
- `channel/wechat_group/wechat_group_profile_evolution_executor.py:116-134`：executor 记录失败 run 和 status 后重新抛出异常。
- `channel/wechat_group/wechat_group_profile_evolution_trigger.py:74-80`：trigger 捕获同一异常并再次 warning。

## 4. 影响判断

- 画像数据未被错误写入：executor 在 extractor 抛错后不会调用 merger。
- 处理游标不会前进：`last_archive_row_id` 保持失败前位置，后续仍可重新处理这一批消息。
- 错误可观测性不足：运行记录和日志把供应商临时不可用伪装成 JSON 格式问题，排查方向会被带偏。
- 自动触发可能重复刷 warning：失败后 `_last_triggered_observed_row_ids` 不更新，`last_signal_at` 也不后移；如果供应商持续不可用，满足 idle 与 pending 条件后会继续重复触发同一批次。

## 6. 验收标准

- 当模型返回 `{"error": True, "message": "...", "status_code": 503}` 时，extractor 抛出可分类异常，而不是 `LLM profile extraction response is not JSON`。
- executor 的 run 与 status 中记录清晰失败原因，包含 `LLM provider temporarily unavailable` 和 HTTP 状态码。
- 临时故障时 `last_archive_row_id` 不前进，后续供应商恢复后仍可重试同一批消息。
- 临时故障时 merger 不执行，不产生画像 diff。
- trigger 对临时故障使用 idle 退避，避免下一次 scan 立即重复触发同一批次。
- 原有严格 JSON 解析失败仍保留为 JSON 格式问题，不被误标为供应商不可用。
- 定向 Python 测试通过。

```python
def _raise_if_model_error(response: Any) -> None:
    if not isinstance(response, dict) or not response.get("error"):
        return
    status_code = int(response.get("status_code") or 0)
    raw_message = str(response.get("message") or "LLM provider returned an error").strip()
    if status_code in _TRANSIENT_LLM_STATUS_CODES:
        message = "LLM provider temporarily unavailable"
        transient = True
    else:
        message = "LLM provider error"
        transient = False
    if status_code:
        message = "{} (HTTP {}): {}".format(message, status_code, raw_message)
    else:
        message = "{}: {}".format(message, raw_message)
    raise WechatGroupProfileExtractionError(
        message,
        status_code=status_code,
        transient=transient,
    )
```

```python
def test_scan_backs_off_after_transient_llm_failure(self):
    from channel.wechat_group.wechat_group_profile_llm_extractor import (
        WechatGroupProfileExtractionError,
    )

    class FailingExecutor:
        def __init__(self):
            self.calls = []
            self.batch_message_limit = 20

        def run_once(self, room_id, trigger_source="idle"):
            self.calls.append((room_id, trigger_source))
            raise WechatGroupProfileExtractionError(
                "LLM provider temporarily unavailable (HTTP 503): Inference is temporarily unavailable",
                status_code=503,
                transient=True,
            )

    executor = FailingExecutor()
    trigger = WechatGroupProfileEvolutionTrigger(
        evolution_store=self.store,
        executor=executor,
        config_getter=lambda key, default=None: self.config.get(key, default),
    )
    trigger.note_message("room@@a", archive_row_id=1, now=100)
    trigger.note_message("room@@a", archive_row_id=2, now=101)

    trigger.scan_once(now=500)
    trigger.scan_once(now=501)

    self.assertEqual([("room@@a", "idle")], executor.calls)
    status = self.store.get_status("room@@a")
    self.assertEqual(500, status["last_signal_at"])
    self.assertIn("LLM provider temporarily unavailable", status["last_failed_reason"])
```
