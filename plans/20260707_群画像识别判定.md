# 群画像识别判定开发计划

> 状态：待用户确认后执行。
> 关联 issue：<https://github.com/yideng966/CowAgent/issues/25>

## 目标

确认个人微信群“群画像别名”的入库规则、链路与混淆风险，并用最小改动补齐可验证防护，避免群聊内容中的泛称或非目标称呼被误写成某个成员 alias。

## 当前核验结论

1. issue #25 当前为打开状态，标题为“[Feature] 群画像识别判定”，诉求是确认群画像别名入库逻辑、规则、链路，并分析是否会因群聊内容造成混淆。
2. 代码已具备基础防混淆约束：
   - sidecar 在 `channel/wechat_group/sidecar/wechaty-sidecar.mjs` 中通过 `message.mentionList()` 上报 `at_list`，同时上报原始 `text`。
   - Python 通道在 `channel/wechat_group/wechat_group_channel.py` 归档消息时，把 `at_list`、`self_id`、`self_display_name` 写入消息 `metadata`。
   - `channel/wechat_group/wechat_group_learner.py` 的 `_learn_mentioned_aliases()` 只处理文本消息；`_resolve_single_mentioned_alias()` 会排除发言人和机器人自身，且要求剩余非机器人 mention 目标必须唯一。
   - 正文别名只从显式 `@称呼` 片段提取；如果正文中非机器人显式称呼不是唯一值，则放弃学习。
   - `channel/wechat_group/wechat_group_profile_service.py` 通过 `merge_learned_aliases()` 写入画像，并以 `source_kind=learning` 写入 `wechat_group_profile_name_records`。
3. 当前风险不是“大范围从自然语言猜别名”，而是边界场景覆盖不够明确：
   - 缺少测试证明“普通文本里出现称呼但没有显式 @ 片段”不会入库。
   - 缺少测试证明“正文里只有机器人 @，没有非机器人实际 mention 目标”不会入库。
   - 缺少测试覆盖 `@所有人`、`@大家`、`@all` 等群体泛称；当前逻辑可能在 `at_list` 只剩 1 个非机器人目标时，把这类泛称误当成该成员 alias。
4. 已执行现有相关测试：
   - `python -m unittest tests.test_wechat_group_learner tests.test_wechat_group_context tests.test_wechat_group_memory_tools`
   - 结果：29 个测试通过。
