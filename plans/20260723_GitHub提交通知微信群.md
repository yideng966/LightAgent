# GitHub 提交通知微信群开发计划

## 目标

当指定 GitHub 仓库的目标分支产生 `push` 事件时，由 LightAgent 接收经过 HMAC-SHA256 验签的 Webhook，将本次推送中的 commit 聚合为一条固定文本消息，并通过当前已登录的个人微信群通道发送到指定稳定群。

## 已确认边界

- 用户已有公网 HTTPS 地址，采用 GitHub 原生 Webhook，不实现 REST API 定时轮询。
- Webhook 只处理 `push` 与 `ping`，仓库、分支和目标稳定群均由本地配置限定。
- 通知内容使用确定性模板，不调用 LLM，不进入 Agent 主链路。
- 一次 push 聚合成一条消息，限制展开的 commit 数与最终字符数，避免群内刷屏。
- 发送复用现有 scheduler 与 `WechatGroupChannel.send()`，不直接调用 sidecar。
- Webhook Secret 可由 Web 控制台保存到本地数据目录配置；`LIGHTAGENT_GITHUB_WEBHOOK_SECRET` 环境变量存在时优先使用，任何真实 Secret 都不得写入仓库。
- WebUI 固定放在「群聊 -> 基础设置」，目标群使用已选择稳定群的单选下拉，不修改 Electron 桌面端。
- 配置默认关闭；仓库与稳定群为空时拒绝入队，避免误投递。

## 验收标准

- 未启用、缺少 Secret、签名错误、请求过大或 JSON 非法时不创建任务。
- `ping` 返回成功但不创建通知任务。
- 非 `push`、非目标仓库、非目标分支、标签推送和删除分支均被安全忽略。
- 相同 `X-GitHub-Delivery` 重复请求最多创建一个 scheduler 任务。
- scheduler 任务携带目标 stable room，并在发送前解析当前 runtime room。
- 群未登录或身份尚未恢复时任务继续重试，超过配置的通知有效期后才过期。
- 通知不真实 mention 群成员，不包含 Secret、原始 payload 或本机路径。
- 配置 API 不返回真实 Secret；环境变量存在时页面 Secret 输入框禁用。
- GitHub 通知配置位于「群聊 -> 基础设置」，目标群通过已选择稳定群的下拉框配置。
