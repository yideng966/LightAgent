# 按群设置自由回复档位设计说明

## 1. 背景与目标

GitHub Issue #3 要求在 Web 控制台的“自由回复群”列表中，为每个群提供独立的活跃档位选择。现有实现已经支持 `quiet`、`normal`、`active`、`crazy` 四档，但 `wechat_group_free_reply_activity_level` 是全局单值，所有群共用同一档位。

本次目标是在不改变现有自由回复主链路、评分规则和档位参数结构的前提下，让已启用自由回复的稳定群可以覆盖全局默认档位。

## 2. 已确认需求

- 保留 `wechat_group_free_reply_activity_level`，作为旧配置和未单独配置群的默认档位。
- 每个自由回复群可以从“安静、普通、活跃、高频”中选择一个档位。
- 下拉框位于对应群勾选项右侧，并随群选择状态一起保存。
- 单群只选择档位，不增加按群自定义阈值、冷却、小时上限或连续上限。
- 仅修改 Web 控制台，不修改 Electron 桌面端。
- 长期配置使用 stable room ID，不使用群名或 runtime room ID 建立新的权限或行为作用域。

## 3. 方案选择

采用独立映射配置：

```json
"wechat_group_free_reply_stable_room_activity_levels": {
  "wgr_example_a": "quiet",
  "wgr_example_b": "active"
}
```

没有采用以下方案：

- 不把 `wechat_group_free_reply_stable_room_ids` 改成对象数组，避免破坏现有配置结构和兼容逻辑。
- 不为四个档位分别增加群 ID 列表，避免同一群被重复配置到多个档位。

## 4. 配置与兼容规则

- 默认配置和配置模板新增空映射 `wechat_group_free_reply_stable_room_activity_levels`。
- 映射只保留 `wgr_` 开头的 stable room ID。
- 映射值只允许 `quiet`、`normal`、`active`、`crazy`。
- 空键、非 stable room ID、非法档位和非字典输入在归一化时丢弃。
- 运行时解析顺序为：当前 stable room ID 的有效覆盖值 → 全局 `wechat_group_free_reply_activity_level` → `normal`。
- 旧配置缺少映射时，所有群继续使用原全局档位，行为不变。
- Web 保存时只保留当前已勾选且可选择的稳定群映射；取消勾选会同时移除该群档位覆盖。

## 5. 后端数据流

1. `get_wechat_group_free_reply_config()` 读取并归一化全局档位、稳定群列表和单群档位映射。
2. `evaluate_wechat_group_free_reply()` 根据本轮 `room_id` 解析实际生效档位。
3. 评分、玩梗分值、阈值、冷却和上限统一使用实际生效档位对应的全局 profile。
4. 判定结果中的 `activity_level` 返回实际生效档位，供日志和 Web 最近判定展示。
5. 当前通道已优先传入 stable room scope；稳定身份不可用的 legacy 消息不会命中新映射，自动回退全局档位。

该设计不新增回复引擎、不改变 worker、LLM 二次判定、情绪修正或 `@` 必回链路。

## 6. Web 控制台交互

- 每个可选择群的行包含：自由回复复选框、群名与 stable room ID、活跃档位原生下拉框。
- 已勾选群的下拉框可操作；未勾选群或身份未确认群的下拉框禁用并显示明确禁用状态。
- 新映射没有该群记录时，下拉框显示全局默认档位。
- 复选框变化时立即同步同一行下拉框的禁用状态，不发送网络请求；仍由页面统一“保存”按钮持久化。
- 下拉框具有与群名关联的可访问名称、可见键盘焦点和原生键盘操作能力。
- 小屏宽度下允许群信息和下拉框换行，避免横向滚动；桌面宽度下下拉框保持在行右侧。
- 原全局档位区继续用于选择默认档位并编辑四套共享 profile，文案明确为“默认活跃档位与档位参数”。

## 7. 服务端保存校验

- `/api/channels` 的微信群配置白名单增加新配置键。
- 保存时调用与运行时相同的归一化函数，避免 Web 和手工配置产生不同规则。
- 服务端不信任前端提交内容；无效 stable room ID 和档位不会写入配置。
- 新配置不包含密钥、用户输入正文或跨群成员信息。

## 8. 测试设计

- 默认配置：新映射为空，旧全局默认档位仍为 `normal`。
- 归一化：保留合法 stable room ID 和档位，丢弃非法 ID、非法档位和错误类型。
- 群隔离：相同消息在两个 stable room ID 中使用各自档位，并产生对应阈值或触发结果。
- 兼容回退：未映射群使用全局档位；非法全局档位最终回退 `normal`。
- Web API：保存新映射并验证非法项被清理。
- Web UI：验证每行存在档位下拉框、保存字段、复选框联动和默认档位文案。
- 回归：运行微信群消息、通道和 Web 测试，确认 `@` 必回、自由回复群范围和旧配置不受影响。

## 9. 非目标

- 不增加自定义档位或第五档。
- 不允许每个群单独编辑 profile 数值。
- 不修改自由回复启用范围、群名候选逻辑或稳定身份确认流程。
- 不修改桌面端、sidecar 协议、数据库或长期记忆结构。
- 不新增依赖。

## 10. 回退方式

本次只有向后兼容的新配置键。回退对应 Git 提交后，旧版本会忽略该键并继续读取全局 `wechat_group_free_reply_activity_level`；无需数据迁移或清理运行数据。
