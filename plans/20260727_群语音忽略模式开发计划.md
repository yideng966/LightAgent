# 微信群语音忽略模式开发计划

## 1. 任务背景

个人微信群现有 `wechat_group_voice_interaction_mode` 只支持“强制回复”和“依赖自由回复规则”。两种模式都会先下载并转写群语音，无法满足收到语音后不转写、不调用模型、不回复的需求。

本次在不修改桌面端、Wechaty JSON Lines 协议、媒体目录和归档生命周期的前提下，为 Web 控制台增加全局“忽略语音”模式。

## 2. 验收标准

- Web 控制台「群聊 -> 语音交互」提供“忽略语音”选项。
- `wechat_group_voice_interaction_mode = ignore` 对全部已选微信群生效。
- `voice` 和 `audio` 消息仍由 sidecar 下载并写入当前群归档，但不进入音频转换、ASR、自由回复、Agent、LLM、TTS 或发送链路。
- 普通群语音、@ 机器人语音和引用机器人语音行为一致。
- 默认值继续为 `force_reply`，旧配置无需迁移，非法值仍回退为 `force_reply`。
- 不复用 `group_speech_recognition` 或 `wechat_group_voice_reply_enabled`，避免混淆通用 ASR/TTS 策略。

## 3. 技术方案

继续使用现有配置键，只扩展枚举：

```json
{
  "wechat_group_voice_interaction_mode": "ignore"
}
```

运行链路保持为 sidecar 下载并上报、Python 完成身份解析和消息归档，随后 `WechatGroupChannel.handle_text()` 在情绪观察和上下文构造前识别 `ContextType.VOICE + ignore`，记录忽略日志后返回。`_handle_voice_transcription()` 同时增加防御性短路，避免运行中配置切换将 `ignore` 落入自由回复分支。

Web 配置详情、保存归一化和前端读取统一接受 `ignore`；界面使用现有单选卡片样式展示第三种模式。

## 7. 风险与回退

- sidecar 会在 Python 判断前下载语音；本次明确保留这一行为，不承诺零下载或自动删除媒体文件。
- 忽略门禁位于归档之后，确保群聊统计和历史记录仍能看到语音消息，但不会触发后续智能处理。
- 本次不新增依赖、数据库迁移或协议字段。回退对应提交即可恢复原有双模式行为，旧配置不受影响。
