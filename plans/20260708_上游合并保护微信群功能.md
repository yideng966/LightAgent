# 上游合并保护个人微信群功能 Implementation Plan

> **面向 Agent 执行者：** 实施本计划时建议先使用 `superpowers:using-git-worktrees` 创建隔离工作树，再使用 `superpowers:executing-plans` 按任务逐项执行。步骤使用复选框语法跟踪进度。

**Goal:** 将 `upstream/master` 的安全修复、桌面端修复、MCP 工具检索和多语言改动合并进本 fork，同时不破坏本地新增的个人微信群通道、群聊管理 UI、群记忆、群友画像、自由回复、多模态和表情包链路。

**Architecture:** 以 `origin/master` 作为本 fork 当前基线，在隔离分支合并 `upstream/master`。保留本地 `channel/wechat_group/`、微信群 Web API、群聊管理页面和 Agent 权限过滤逻辑，手工吸收上游在共享配置、Agent 执行器、Web 控制台、桌面端和安全工具上的改动。所有冲突解决后用定向回归测试先覆盖高风险链路，再运行桌面构建和必要的全量测试。

**Tech Stack:** Python `unittest`、Git merge/worktree、PowerShell、Web 控制台原生 JS/CSS、Electron + Vite + React、Node.js sidecar。

## 2. 合并策略

### 保留本地优先的能力

以下能力属于本 fork 的个人微信群核心能力，冲突解决时必须保留：

- `channel/wechat_group/` 下所有 Python 适配、sidecar 协议、归档、焦点栈、情绪、自由回复、群记忆、群友画像、图片理解、表情包和权限控制。
- `bridge/agent_bridge.py` 中微信群管理员工具过滤、微信群作用域记忆工具、表情包工具和系统提示 suffix。
- `channel/web/web_channel.py` 中 `/api/wechat_group/qrlogin`、`/api/wechat-group/*` API、微信群通道配置读写、群列表与成员查询。
- `channel/web/static/js/console.js` 中 `groups` 视图、微信群二维码登录、群聊管理页面、群管理员、自由回复、焦点栈、风格、情绪、表情包、永久记忆、全局画像、图片与生图配置。
- `desktop/src/renderer/src/pages/GroupsPage.tsx` 及其在桌面导航、类型和 i18n 中的入口。
- `config.py` 与 `config-template.json` 中所有 `wechat_group_*` 配置项。
- 本地 `tools.web_search` 嵌套配置，尤其是 `provider`、`bocha_api_key`、`serper_api_key`、`jina_api_key`。

### 吸收上游优先的能力

以下上游改动有独立价值，应吸收：

- `config.py` 的安全解析修复和 duplicate key 合并逻辑。
- `deep_dream_enabled` 默认配置项。
- `mcp_tool_retrieval_*` 默认配置项。
- MCP 工具检索相关新增文件与 `ToolManager` 改动。
- `Read`、`Edit`、`Bash` 工具修复及对应测试。
- `common/i18n.py` 和 Web/桌面繁体中文支持。
- 桌面端发布、更新、安装路径、文件消息渲染相关修复。
- `bridge/agent_bridge.py` 中 `_create_file_reply()` 对远程 URL 的 passthrough 支持。

### 不应做的事

- 不删除或重命名 `channel/wechat_group/`。
- 不把微信群逻辑改写成上游通用通道逻辑。
- 不删除 `groups` 页面入口来换取上游 `channels` 页面改动。
- 不把上游 `config-template.json` 直接覆盖本地模板，因为会丢失大量 `wechat_group_*` 和 `tools.web_search` 配置。
- 不在冲突解决中顺手重构 Web 控制台大文件。
- 不在合并提交中引入真实 token、cookie、密钥或本地代理地址。

## 4. 风险清单

- `agent/protocol/agent_stream.py` 是最高风险文件。错误合并会影响所有 Agent 工具调用、MCP 工具注入、scheduler 保护、工具禁用重试和微信群 Agent 主链路。
- `channel/web/static/js/console.js` 体量很大，且双方都改了动态视图刷新。错误合并会导致 `groups` 页面消失、语言切换后页面不刷新或通道管理不可用。
- `config.py` / `config-template.json` 不能用任一侧整体覆盖，必须做配置键并集。尤其要避免重复顶层 `tools`，否则 Web 搜索配置或 MCP 检索配置会丢失。
- `bridge/agent_bridge.py` 虽可自动合并，但要确认远程文件 URL 支持与微信群表情包元数据同时存在。
- 桌面端 auto-merge 后必须构建，因为 `i18n.ts`、`NavRail.tsx`、`types.ts` 同时涉及上游桌面更新和本地群聊页入口。

## 5. 最终合并判断

可以合并上游变更。理由是上游没有直接修改个人微信群主体目录和测试文件，核心冲突集中在共享配置、Web 控制台和 Agent 执行器；这些冲突可以通过保留本地微信群语义并吸收上游独立修复来解决。

合并方式必须是手工合并，不建议直接 `git merge upstream/master` 后粗暴选择 ours/theirs。最小安全路径是：从 `origin/master` 建隔离工作树，解决 5 个内容冲突，复核 7 个自动合并文件，完成微信群和上游新增安全/工具测试，再提交合并。
