# 模型列表获取与模糊检索开发计划

## 一、任务背景

当前 Web 控制台“模型管理”页面已经按厂商和能力拆分配置，并通过 `GET /api/models` 返回厂商、当前模型及内置候选目录。七类目标能力均已具备模型选择入口：

- 主模型（`chat`）
- LLM Scorer（`scorer`）
- 图像理解（`vision`）
- 图像生成（`image`）
- 语音识别（`asr`）
- 语音合成（`tts`）
- 向量（`embedding`）

但现有候选主要来自 `channel/web/web_channel.py` 中的静态模型目录。前端 `cfg-dropdown` 仅支持点击选择，目录之外的模型需要进入“自定义”分支后手工填写，不支持搜索，也不会根据当前选中的已配置厂商主动请求其 Models API。

本任务要在保留任意模型 ID 手工填写能力的前提下，为上述七类模型字段提供统一的可编辑下拉框，并在模型字段最右侧增加“获取模型”按钮。用户点击按钮后，由后端使用当前已配置厂商的凭据和 Base URL 请求该厂商的模型列表接口，前端可按中文或英文关键词模糊检索并选择返回的模型。

## 二、现状核查结论

1. 模型管理的 Web 路由当前统一为 `/api/models`，`ModelsHandler.POST()` 使用 `action` 分发厂商保存、能力保存等操作，适合以新 action 扩展按需获取模型，不必新增一组平行路由。
2. `ConfigHandler.PROVIDER_MODELS` 已集中维护内置厂商的 Key 字段、Base URL 字段、默认 Base URL和静态模型；`models/custom_provider.py` 已集中解析 `custom` 与 `custom:<id>` 配置，可以复用，不能让浏览器提交任意目标 URL。
3. 前端七类能力都由 `MODELS_CAPABILITY_DEFS` 和 `renderCapabilityBody()` 统一渲染，模型候选由 `rebuildCapabilityModelDropdown()` 组装；这是实现一次、覆盖七类能力的最小入口。
4. 现有 `initDropdown()` 是通用点击式下拉框，没有输入搜索、方向键导航、`role="combobox"`、`aria-expanded` 或 `aria-activedescendant`，不宜直接把远端大目录塞入现有实现。
5. 当前模型下拉通过 `__custom__` 选项再显示第二个文本框。新交互应改为一个可编辑组合框：输入值本身就是最终模型 ID，既能自由填写，也能过滤和选择候选，避免两个控件表达同一个配置值。
6. 厂商协议并不完全一致，不能统一按 `base + /models + Bearer Token` 猜测：
   - OpenAI 官方模型列表返回 `data[].id`。
   - Anthropic 官方为 `GET /v1/models`，使用 `x-api-key` 与 `anthropic-version`，返回 `data[].id`、`display_name`，并使用游标分页。
   - Gemini 官方为 `GET /v1beta/models`，使用 `x-goog-api-key`，返回 `models[].name`、`displayName`、支持动作及 `nextPageToken`。
   - DeepSeek、智谱、豆包、月之暗面、百度千帆、小米 MiMo、MiniMax、DashScope、LinkAI 及自定义 Provider 的运行时代码存在 OpenAI-compatible 用法，但“聊天接口兼容”不等于一定开放 `/models`；实施前必须按官方文档或真实只读请求逐项确认，未确认前不得硬编码猜测。
7. `requests` 已是项目依赖，无需新增第三方包；全局 `proxy` 配置也应沿用，避免模型调用可联网但模型目录获取不可联网。
8. 工作区已有与本任务无关的未提交修改，本任务实施时必须保持隔离，不覆盖或回退这些内容。

## 三、目标与验收标准

### 3.1 功能目标

- 七类目标能力的模型字段统一使用“可编辑输入 + 候选下拉”组合框。
- 输入任意非空模型 ID 后可按现有保存流程持久化，不要求该值必须来自下拉列表。
- 模型字段右侧固定显示“获取模型”按钮；仅当已选择并已配置有效厂商时可触发。
- 点击按钮才发起远端请求；页面加载、切换能力或切换厂商时不自动请求第三方接口。
- 获取成功后合并当前静态候选、远端候选和当前已保存模型，按模型 ID 去重，当前输入值不被覆盖。
- 下拉搜索同时匹配模型 ID、厂商返回的英文展示名、厂商返回或项目已有的中文别名/说明。
- 中文按 Unicode 原文匹配，英文按 Unicode 规范化后的不区分大小写匹配；支持空格分词后逐词包含匹配。首版不引入拼音转换、机器翻译或 Fuse.js 等额外依赖。
- 获取失败、超时、鉴权失败、接口不支持或响应无有效模型时，保留当前输入和静态候选，并给出可重试的就地错误状态。

### 3.2 交互验收

- 桌面端模型输入占据剩余宽度，“获取模型”按钮位于同一行最右侧。
- 375px 移动端无横向滚动，按钮和模型输入不互相遮挡；按钮触控区不小于 44 x 44 像素。
- 请求中按钮禁用并显示加载状态，阻止重复请求；成功或失败结果通过 `aria-live` 状态区反馈。
- 组合框支持鼠标、触摸和键盘：`ArrowUp`、`ArrowDown`、`Enter`、`Escape`、`Tab`；焦点环清晰，展开状态与 `aria-expanded` 一致。
- 输入中文或英文关键词时只过滤本地已获取数据，不在每次按键时请求后端。
- 下拉项显示技术模型 ID；若存在 `display_name`、`displayName` 或现有 `hint`，作为第二检索字段和辅助展示，不用中文名替换实际保存值。
- 远端列表过大时只渲染首批匹配项，并保留精确搜索能力，避免一次创建数百至上千个 DOM 节点。

### 3.3 兼容性验收

- 不改变七类能力现有 Provider 白名单、自动模式、保存字段、Bridge 刷新和向量模型变更确认流程。
- 不改变 TTS 音色下拉与模型联动；选择 TTS 模型后仍按原规则刷新对应音色目录。
- 不删除后端静态能力模型目录；远端获取失败或厂商不支持 Models API 时仍可使用静态候选和手工输入。
- 当前已保存但不在静态或远端目录中的模型必须原样回显并可再次保存。
- 中英文界面均提供完整按钮、加载、成功、空结果、接口不支持和错误文案。

## 四、范围边界

### 4.1 本次范围

- Web 控制台“模型管理”页面的七类模型字段。
- 已配置内置厂商、legacy `custom` 和多自定义 `custom:<id>` 的模型目录获取。
- 后端模型目录请求、不同协议响应归一化、分页上限、超时与错误映射。
- 模型组合框的中英文模糊检索、键盘操作、移动端与深色模式。
- 相关中英文 Web 文档、自动化测试、`CHANGES.md` 和本计划实施结果回写。

### 4.2 不在本次范围

- 不修改历史归档 `desktop/`。
- 不修改联网搜索能力卡，因为它没有模型字段。
- 不为模型增加价格、上下文长度、发布日期、推荐排序或自动能力判定。
- 不自动翻译厂商返回的模型名，也不实现拼音首字母搜索。
- 不定时刷新、不后台同步、不把远端模型目录写入 `config.json` 或数据库。
- 不改变主模型的备用模型列表 `model_fallbacks`；本次仅覆盖主模型卡中的当前模型字段。若备用模型也需要相同交互，应另行确认后再纳入。
- 不因名称包含 `image`、`embedding`、`tts` 等关键词就猜测模型能力并强过滤；仅在厂商响应提供明确能力元数据时使用元数据，否则展示厂商返回目录，由现有能力 Provider 白名单控制厂商范围。

## 五、总体设计

```text
用户选择能力卡中的厂商
        |
        v
点击“获取模型”按钮
        |
        v
POST /api/models
action=fetch_provider_models
provider_id + capability
        |
        v
后端只按 provider_id 读取服务端已保存配置
        |
        v
按厂商协议构造 Models API 请求并归一化
        |
        v
{ models: [{ id, label, hint, capabilities }] }
        |
        v
前端合并静态目录 + 远端目录 + 当前输入值
        |
        v
可编辑组合框按中英文关键词本地过滤并选择
```

核心原则是“浏览器只提交厂商 ID 和能力 ID，后端决定 URL、鉴权头与解析器”。这样既复用已配置凭据，也避免把密钥暴露到浏览器或让请求参数变成通用 SSRF 代理。

## 六、后端实施方案

### 6.1 新增模型目录服务

建议新增 `channel/web/model_catalog.py`，把第三方网络请求从体积已经较大的 `ModelsHandler` 中隔离出来。模块只承担以下职责：

- 校验 `provider_id` 和 `capability`。
- 从当前配置解析该厂商的 API Key、Base URL、默认 Base URL及协议类型。
- 为 `custom:<id>` 复用 `resolve_custom_provider_config()`，未知 ID 不回退到 legacy 自定义配置。
- 构造受控请求、解析分页、归一化模型对象、去重并返回稳定错误码。
- 不负责配置写入、能力保存或 UI 静态目录维护。

建议统一返回内部结构：

```python
{
    "id": "gpt-5.4-mini",
    "label": "gpt-5.4-mini",
    "hint": "",
    "capabilities": [],
}
```

其中 `id` 是唯一持久化值；`label`/`hint` 仅用于展示和检索；`capabilities` 只有在厂商提供明确元数据时填写。

### 6.2 厂商适配策略

先建立显式适配表，不按域名或响应内容动态猜协议：

| 协议适配器 | 已确认请求/响应 | 首批目标厂商 | 备注 |
|---|---|---|---|
| OpenAI-compatible | `GET {base}/models`，Bearer；解析 `data[].id` | OpenAI、自定义 Provider | OpenAI 官方接口已核对；其他兼容厂商必须逐项验证后再加入映射 |
| Anthropic | `GET {base}/models`，`x-api-key`、`anthropic-version`；解析 `data[].id/display_name` | Claude | 处理 `has_more`、`last_id` 游标，设置总页数上限 |
| Gemini | `GET {base}/v1beta/models`，`x-goog-api-key`；解析 `models[].name/displayName` | Gemini | 去掉资源名前缀 `models/`，处理 `nextPageToken` |

实施阶段需要为 DeepSeek、智谱、豆包、月之暗面、百度千帆、小米 MiMo、MiniMax、DashScope、LinkAI 分别完成官方文档或真实只读请求核验：

- 若确认支持兼容 Models API，则加入 OpenAI-compatible 映射，并使用项目当前运行时相同的默认 Base URL。
- 若需要不同路径、请求头或响应结构，则增加明确的小型适配器。
- 若厂商没有开放模型列表接口，则返回稳定的 `models_api_unsupported`，前端继续保留静态候选和手工输入，不伪造远端结果。

不得因为某厂商的 `/chat/completions` 兼容 OpenAI 就直接断言 `/models` 同样兼容。

### 6.3 ModelsHandler 接口扩展

在现有 `POST /api/models` action 分发中新增：

```json
{
  "action": "fetch_provider_models",
  "provider_id": "openai",
  "capability": "vision"
}
```

成功响应：

```json
{
  "status": "success",
  "provider_id": "openai",
  "capability": "vision",
  "models": [
    {"id": "gpt-5.4-mini", "label": "gpt-5.4-mini", "hint": "", "capabilities": []}
  ]
}
```

失败响应只返回安全错误码和本地化所需参数，不返回 API Key、完整响应体或带凭据的请求头。建议错误码至少覆盖：

- `provider_not_found`
- `provider_not_configured`
- `provider_not_allowed_for_capability`
- `models_api_unsupported`
- `models_api_unauthorized`
- `models_api_timeout`
- `models_api_unavailable`
- `models_api_invalid_response`
- `models_api_empty`

`ModelsHandler` 必须再次核对所选 Provider 是否属于目标能力现有 `providers` 列表，防止绕过 UI 为不支持的能力调用任意已配置厂商。

### 6.4 请求安全与资源边界

- 请求目标只能来自服务端已有 Provider 元数据或已保存的自定义 Provider Base URL，禁止请求体覆盖 Base URL、路径、鉴权头或代理。
- 只允许 `http`/`https`；沿用项目 `validate_url_safe()` 的现有开关语义，以兼容管理员明确配置的本地 vLLM/Ollama/LAN 网关。
- 禁止自动重定向，避免密钥被 3xx 带到另一个源；需要变更地址时由管理员修改厂商 Base URL。
- 使用有限连接/读取超时，例如 `(5, 10)` 秒；沿用全局 `proxy`。
- 使用流式读取或响应长度检查，限制响应体、最大分页数和最大模型数；建议上限为 5 页、1000 个模型、2 MiB 响应体，超过即截断或返回受控错误。
- 不记录 API Key、Authorization、完整第三方响应或用户自定义 Base URL中的敏感查询参数；日志只记录 Provider ID、协议类型、HTTP 状态、耗时和安全错误摘要。
- 不做服务端长期缓存。每次点击都执行一次明确刷新；前端仅在当前页面会话中保存已获取结果。

## 七、前端实施方案

### 7.1 统一可编辑模型组合框

在 `channel/web/static/js/console.js` 增加只服务于模型字段的 `initModelCombobox()`，不改变其他配置页正在使用的 `initDropdown()` 默认行为。该组件在七类能力卡中复用，并维护一个真实文本输入作为唯一值源。

组件职责：

- 输入即最终模型 ID，支持任意自定义值。
- 聚焦或点击展开候选；输入时在浏览器本地过滤。
- 规范化 `id + label + hint` 后执行中英文匹配。
- 精确 ID 优先，其余保持“当前值、静态候选、远端候选”的稳定顺序并去重。
- 支持方向键、Enter 选中、Escape 关闭、点击外部关闭和焦点离开处理。
- 使用 `role="combobox"`、`role="listbox"`、`role="option"`、`aria-controls`、`aria-expanded`、`aria-activedescendant`。
- 不再依赖 `__custom__` 和第二个自定义输入框；`getCapabilityModelValue()` 直接读取组合框输入值。

模糊检索建议使用无依赖实现：

```javascript
const normalize = value => String(value || '')
    .normalize('NFKC')
    .toLocaleLowerCase();
```

将查询按连续空白拆词，所有词都能在 `id/label/hint` 拼接文本中命中即保留。该规则可直接处理中文子串和英文大小写，不引入不可控的翻译或拼音歧义。

### 7.2 “获取模型”按钮

修改 `renderCapabilityBody()` 的模型区域：

- 模型输入和按钮放入 `minmax(0, 1fr) auto` 的稳定布局。
- 按钮显示刷新/下载类现有 Font Awesome 图标和“获取模型”文本，不使用只有图标的不可发现操作。
- Provider 为空、能力处于自动模式、厂商未配置或请求进行中时禁用。
- 点击后调用 `fetchProviderModels(def.id)`，请求只携带当前能力和当前 Provider ID。
- 按钮加载时不改变外框尺寸，避免卡片布局跳动。
- 成功后更新当前能力组合框候选并自动展开，但不自动改写当前输入。
- 失败后组合框及当前值保持不变，状态区显示明确原因；再次点击即可重试。

### 7.3 前端状态与候选合并

新增页面级临时状态，例如：

```javascript
const modelsCatalogState = {
    // key: `${capability}:${providerId}`
    entries: new Map(),
    loading: new Set(),
    errors: new Map(),
};
```

按“能力 + Provider”隔离，避免从主模型获取的目录错误覆盖同一厂商下图像、语音或向量能力的静态说明。远端模型可复用原始结果，但最终候选合并必须在能力作用域内完成。

Provider 变化时：

- 立即切换到新 Provider 的静态/已获取候选。
- 沿用现有逻辑清理旧 Provider 的默认选择，不自动发起网络请求。
- TTS 同步刷新音色下拉。
- 切回已获取过的 Provider 时可复用当前页面会话内结果；再次点击“获取模型”仍强制刷新。

### 7.4 样式与国际化

在 `channel/web/static/css/console.css` 增加模型组合框专用样式，沿用现有浅色/深色主题 token、8px 圆角、40px 输入高度和绿色焦点环，不重新设计模型管理页面。

在 `channel/web/static/js/console.js` 的中英文词典增加：

- 获取模型 / Fetch models
- 正在获取 / Fetching
- 已获取模型数量
- 输入关键词搜索模型
- 未找到匹配模型
- 厂商未配置
- 厂商不支持模型列表接口
- 鉴权失败、请求超时、服务不可用、响应无效、空结果

状态文案放入现有状态区或组合框空状态，不新增说明型卡片。

## 九、测试方案

### 9.1 后端单元测试

`tests/test_model_catalog.py` 使用 mock，不访问真实第三方服务：

- OpenAI-compatible：URL 斜杠归一化、Bearer Header、`data[].id` 解析、去重。
- Anthropic：`x-api-key`、`anthropic-version`、`display_name` 和游标分页。
- Gemini：`x-goog-api-key`、`models/` 前缀清理、`displayName`、支持动作和 `nextPageToken`。
- 自定义 Provider：精确解析 `custom:<id>`；未知 ID 不回退；legacy `custom` 行为保持兼容。
- 未配置 Key/Base、未知 Provider、未知能力、能力不允许该 Provider 时不发请求。
- 401/403、404/405、429、5xx、超时、网络异常、非 JSON、错误 JSON 结构、空数组均映射为稳定错误码。
- 不跟随重定向；请求体不能覆盖 URL 或 Header；返回与日志不含 API Key。
- 最大页数、最大模型数和响应体限制生效。

## 十一、风险与回退

1. **厂商接口差异**：通过显式适配器隔离；未核验厂商不猜测协议，失败时保留手工输入。
2. **模型目录不等于能力目录**：不做名称启发式强过滤，避免遗漏新模型；仅使用厂商明确能力元数据和现有 Provider 能力白名单。
3. **密钥泄露与 SSRF**：浏览器不能传 URL/Header，后端不跟随重定向、不回显凭据，并限制响应与分页。
4. **本地自定义网关兼容**：保留现有 SSRF 配置开关语义，不无条件阻断管理员配置的内网 Provider。
5. **大目录卡顿**：输入搜索在本地执行，但限制单次渲染数量；不在页面初始化时自动拉取。
6. **旧自定义值丢失**：当前输入值始终单独并入候选，远端成功、失败和 Provider 切换都不得静默覆盖已保存值。
7. **回退路径**：后端 action 和前端获取按钮均为增量能力；若远端目录实现需要回退，可移除获取 action 与按钮，保留静态候选、可编辑输入和原有保存契约，不涉及配置数据迁移。
