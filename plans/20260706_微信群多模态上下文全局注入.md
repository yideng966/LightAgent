# 微信群多模态上下文全局注入实施计划

> **面向执行 Agent 的要求：** 实施本计划时先使用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans`，按任务逐项推进。每个任务完成后更新本文件复盘段落。

**目标：** 将微信群图片理解从分散在 direct reply / 自由回复图片分支里的点状逻辑，升级为 `_compose_context()` 阶段的全局多模态上下文注入能力。任何已经进入回复链路的微信群消息，都应通过同一套上下文服务判断是否注入图片、引用、转发、视频等多模态上下文。

**架构：** 新增 `WechatGroupMultimodalContextService`，挂接到现有 `_build_multimodal_context_block()`。该服务只负责“给本轮回复装配哪些多模态上下文”，不决定是否接话，不替代自由回复评分器，不绕过 `Vision()`、`ChatChannel`、`Bridge` 或 Agent 主链路。

**技术栈：** Python `unittest`、现有 `channel/wechat_group` 渠道层、现有 Web 控制台配置接口、既有 `agent.tools.vision.vision.Vision`。

---

## 设计修正

上一版 P0b 方案把问题写成了“自由回复文本通过后，在 `_submit_free_reply_after_judge()` 里绑定最近图片”。这个方向过窄，属于指哪打哪的点位修复。

正确边界应该是：微信群通道的全局上下文注入层本来就在 `_compose_context()` 中统一追加：

- `<wechat-group-persona>`
- `<recent-wechat-group-transcript>`
- `<wechat-group-knowledge>`
- `<wechat-group-style>`
- `<wechat-group-emotion>`
- `<wechat-group-multimodal>`

因此图片理解也应该进入 `<wechat-group-multimodal>` 的全局装配流程。自由回复只是触发来源之一，不应该拥有一套单独的图片绑定逻辑。

## 当前失败链路

本机归档证据：

```text
DB: C:\Users\clancy\.cow\wechat_group\wechat_group_archive.db

2026-07-06 15:42:36
room: PT站看片狂魔小群
sender: @216d9...
message_type: image
media_path: C:\Users\clancy\.cow\wechat_group\media\...\4354591147918...

2026-07-06 15:42:38
same sender
message_type: text
text: 这是真的吗

2026-07-06 15:42:47
assistant reply:
鱼哥你发了张啥图我没看到内容啊，再发一次或者描述下？[捂脸]
```

根因不是图片未下载、未归档或跨群查不到。根因是当前图片理解没有进入全局上下文装配：

- 当前 `_compose_context()` 已经调用 `_build_multimodal_context_block()`，但该块目前只包含引用、转发、视频等元信息。
- 引用图片或最近图片不会在这个全局块里生成视觉摘要。
- direct reply 文本靠 `_build_recent_image_understanding_content()` 单独查最近图片。
- 自由回复文本通过 worker 后只带纯文本进入 `_compose_context()`，没有统一的图片摘要注入。

所以 Agent 在那次回复里只看到 `这是真的吗` 和普通最近群聊文本，看不到上一张图片的视觉摘要。

## 目标链路

### 全局回复上下文

统一后的链路应该是：

```text
任意微信群消息已经决定要回复
-> WechatGroupChannel._compose_context()
   -> persona block
   -> recent transcript block
   -> knowledge block
   -> style block
   -> emotion block
   -> multimodal context service
      - 当前消息图片
      - 引用图片
      - 引用发送者最近图片
      - 同发送者短窗口追问图片
      - 群内唯一近图
      - 转发/视频元信息
      - Vision 摘要缓存
   -> <wechat-group-multimodal>
-> Bridge / Agent
```

### 自由回复只负责触发

自由回复链路仍然是：

```text
普通非 @ 文本
-> evaluate_wechat_group_free_reply()
-> WechatGroupFreeReplyScheduler.evaluate()       # P0，可关闭
-> WechatGroupFreeReplyWorkerPool / LLM judge
-> _compose_context(wechat_group_force_reply=True, wechat_group_trigger_source="free_reply")
-> 全局 multimodal context service 决定是否注入图片摘要
-> Bridge / Agent
```

`_submit_free_reply_after_judge()` 不应该自己查最近图片。它只需要把触发来源传给 context，例如 `wechat_group_trigger_source = "free_reply"`。

## 全局多模态服务职责

新增 `channel/wechat_group/wechat_group_multimodal_context_service.py`。

### 输入

- 当前 `WechatGroupMessage`。
- 当前原始 query/content。
- `trigger_source`：`direct_reply`、`free_reply`、`quote_self`、`image_message`、`normal`。
- 当前 `room_id`。
- `WechatGroupArchive.get_recent_messages()` / `get_message_by_id()`。
- 当前时间：优先 `msg.create_time`。
- 配置：开关、窗口、最大候选数、缓存分钟数。

### 输出

返回：

```python
{
    "block": "<wechat-group-multimodal>...</wechat-group-multimodal>",
    "matched_images": [
        {
            "reason": "same_sender_recent_image",
            "message_id": "8050",
            "sender_id": "@216d9...",
            "sender_name": "鱼哥",
            "summary": "Vision 返回的视觉摘要",
        }
    ],
    "diagnostics": {
        "enabled": True,
        "reason": "same_sender_recent_image",
        "skipped_reason": "",
    },
}
```

不命中时返回空 `block` 和可诊断的 `skipped_reason`。

## 图片候选优先级

全局服务只在本轮已经进入回复链路时工作，不会让机器人“见图就说话”。

1. **当前消息就是图片**
   如果本轮回复是由图片消息触发，优先理解当前图片。

2. **引用图片精确绑定**
   如果当前文本引用了一张图片，按 `room_id + quote.message_id` 精确查归档图片。

3. **引用发送者最近图片**
   如果引用消息 ID 查不到图片，但引用里有 `sender_id` 或 `sender_name`，在当前群最近 30 分钟内倒序找该发送者最近图片。

4. **同发送者短窗口追问**
   如果同一发送者在短窗口内刚发过图片，又发送 `这是真的吗`、`这个是真的吗`、`真的假的`、`真吗`、`靠谱吗`、`这啥`、`这个呢`、`啥意思`、`怎么样` 等视觉指代短问，绑定该发送者最近图片。默认窗口建议 120 秒。

5. **群内唯一近图 + 明确指代问题**
   如果当前群短窗口内只有一张图片，且文本是明显指代问题，可以绑定这张图。默认窗口建议 120 秒。

6. **多图不明确不绑定**
   如果短窗口内多人连续发图，且文本没有引用、没有同发送者强绑定，也没有唯一近图，必须不绑定，避免答错图。

## Prompt 格式

新的图片上下文放在 `<wechat-group-multimodal>` 内，不再给 LLM 暴露本机绝对路径：

```text
<wechat-group-multimodal>
[image_understanding]
message_id: 8050
sender: 鱼哥 (@216d9...)
reason: same_sender_recent_image
created_at: 2026-07-06 15:42:36
summary: ...

[quoted_message]
...
</wechat-group-multimodal>
```

真实 `media_path` 只传给：

```python
Vision().execute({"image": image_path, "question": question})
```

`<recent-wechat-group-transcript>` 中也不应该继续输出本机媒体绝对路径。图片消息可以显示为 `[image message_id=...]`，视觉摘要只放在 `<wechat-group-multimodal>`。

## 成本与安全边界

- 不预先理解群里所有图片，默认只在本轮已经要回复且存在明确候选图片时调用 `Vision()`。
- Vision 摘要按 `image_path + question` 缓存，沿用现有 `wechat_group_image_understanding_cache_minutes`。
- 所有候选查找必须带 `room_id`。
- 不把本机 `C:\Users\...`、`D:\...` 路径写进 LLM prompt、Web 状态或日志摘要。
- 多图不明确时宁可不注入，也不要误认。

## 配置与 UI

只修改 Web 控制台，不修改 Electron 桌面端。

### 后端配置

新增配置建议：

```json
{
  "wechat_group_multimodal_context_enabled": true,
  "wechat_group_multimodal_image_understanding_context_enabled": true,
  "wechat_group_multimodal_free_reply_image_context_enabled": false,
  "wechat_group_multimodal_same_sender_window_seconds": 120,
  "wechat_group_multimodal_unique_image_window_seconds": 120,
  "wechat_group_multimodal_quote_sender_window_minutes": 30,
  "wechat_group_multimodal_max_recent_messages": 20
}
```

说明：

- `wechat_group_multimodal_context_enabled`：总开关，控制 `<wechat-group-multimodal>` 全局注入。
- `wechat_group_multimodal_image_understanding_context_enabled`：控制图片视觉摘要注入。
- `wechat_group_multimodal_free_reply_image_context_enabled`：控制自由回复文本是否允许绑定最近图片，默认关闭以控制成本和行为变化。
- direct reply 图片理解继续受现有 `wechat_group_image_understanding_enabled` 控制；实施时可以兼容旧配置并逐步迁移。

取值边界：

- `same_sender_window_seconds`: 5 到 600。
- `unique_image_window_seconds`: 5 到 600。
- `quote_sender_window_minutes`: 1 到 120。
- `max_recent_messages`: 1 到 100。

路径脱敏强制开启，不提供关闭项。
