# 微信群成员黑名单开发计划

## 目标

在现有“群与管理员”能力基础上增加按群生效的成员黑名单。Web UI 支持参考群管理员选择群成员并保存黑名单；黑名单成员在当前群主动 @ bot、引用 bot、拍一拍 bot、图片/视频直接触发，以及普通消息进入自由回复判定时，都静默跳过回复。

## 范围

- 新增主配置 `wechat_group_blacklist_members`，结构参考 `wechat_group_admin_members`，按 `stable_room_id + stable_member_id` 精确生效。
- 保留旧配置 `wechat_group_blocked_stable_member_ids` 与 `wechat_group_blocked_sender_ids` 作为兼容 fallback，不作为新 UI 默认写入目标。
- Web 控制台只改 Web 群管理页，不改桌面端。
- 黑名单只影响“是否响应”；不做消息删除、踢人、全局禁言、跨群合并或 sidecar 协议改造。
- 命中黑名单时静默跳过，不向群里发送拒绝文案，避免制造额外打扰。

## 设计

### 配置与判断

- 在 `channel/wechat_group/wechat_group_permissions.py` 增加：
  - `normalize_wechat_group_blacklist_members(value)`
  - `get_wechat_group_blacklist_members(config=None)`
  - `is_wechat_group_blacklisted(room_id, sender_id, config=None)`
  - `build_wechat_group_blocked_sender_ids(room_id, sender_id, runtime_sender_id, config=None)`
- 新结构只认可 confirmed 成员；`identity_status` 为空时按兼容数据处理。
- 旧 flat 字段仅用于 fallback：`blocked_stable_member_ids` 按 stable member 匹配，`blocked_sender_ids` 按 runtime sender 匹配。

### Web 控制台

- `ChannelsHandler._wechat_group_extra()` 在 `extra.admin` 中返回 `blacklist_members`，同时继续返回旧 flat 字段用于兼容展示/诊断。
- `_apply_wechat_group_config()` 允许并归一化保存 `wechat_group_blacklist_members`。
- `console.js` 在“群管理员”面板旁增加“群黑名单”面板：
  - 复用同一群选择与 `/api/wechat-group/members` 成员搜索接口。
  - 只能保存已确认 stable member。
  - 删除时按 `room_id + sender_id` 精确删除。
  - 保存配置时写入 `wechat_group_blacklist_members`。

### 通道响应链路

- 在 `WechatGroupChannel.handle_text()` 开头、自由回复禁言命令之后，执行黑名单硬门禁。
- 命中黑名单后：
  - direct reply、引用、拍一拍、图片/视频触发均直接 return。
  - 普通自由回复候选不入队。
- `_should_enqueue_free_reply_message()` 改为使用新 helper 生成 blocked sender 集合，确保旧测试仍保留。

  - `tests/test_wechat_group_channel.py`：黑名单成员 @bot 静默跳过、自由回复命中 blocked_sender。
  - `tests/test_wechat_group_web.py`：extra 返回黑名单、保存黑名单、控制台包含黑名单 UI 与保存字段。
