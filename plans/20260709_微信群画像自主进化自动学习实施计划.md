# 微信群画像自主进化自动学习 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将微信群画像学习升级为自动触发、LLM 结构化提取、服务端自动合并、Web 可观察和可回滚的自主进化链路。

**Architecture:** 新增微信群画像专用 evolution 存储、合并器、提取器、执行器和触发器；复用现有归档、画像服务、Web 控制台和 Agent 模型配置，但不让通用 self-evolution executor 直接写群画像。所有读写以 `room_id + sender_id` 为边界。

**Tech Stack:** Python `unittest`、SQLite、现有 `WechatGroupArchive` / `WechatGroupProfileService` / `WechatGroupMemoriesHandler`、Web 控制台原生 JS。

## 实际改动说明

- 自动学习触发：`WechatGroupProfileEvolutionTrigger` 在收到当前群归档 signal 后记录 `latest_observed_row_id`，后台扫描满足“已启用 + 群空闲 + 新消息阈值”或“超过最大间隔且有待处理消息”时调用 executor。
- LLM 抽取：executor 复用项目当前 Agent 模型包装 `AgentLLMModel(Bridge())`，不新增独立模型配置；extractor 只把脱敏后的当前群消息和已有画像交给模型。
- 群画像隔离：归档读取、status、runs、diffs、合并和 UI 查询均以 `room_id` 为入口，画像合并时按当前 `room_id + sender_id` 写入 name record 来源。
- 自动合并：不引入人工审核队列；高置信字段直接合并并记录 diff，低置信或缺证据字段丢弃。
- 回滚范围：当前版本按 diff `before` 快照恢复画像主体字段；`name_record_rollback` 返回 `not_pruned`，暂不物理删除别名记录，避免误删同一成员其他来源的名称记录。
- UI 展示：群记忆“学习运行”页新增群画像自主学习卡片，包含开关、idle、最小消息数、最大间隔、批大小、状态、运行列表、详情和回滚按钮。
