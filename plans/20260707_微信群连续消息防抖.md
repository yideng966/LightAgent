# 微信群连续消息防抖

## 背景

GitHub issue #19 反馈：个人微信群自由回复在同一话题下短时间连续消息到达时，可能逐条触发 bot 回复，造成刷屏感。显式触发消息（@ 机器人、引用机器人回复）仍必须保持及时响应。

## 目标

- 同一 room 的普通非显式触发自由回复候选在短时间窗口内只保留最新一条。
- 不同 room 的自由回复候选互不影响。
- @ 机器人、引用机器人回复等显式触发路径不进入自由回复防抖。
- 修复后补充回归测试，并更新 `CHANGES.md`。

## 实际改动

- `channel/wechat_group/wechat_group_free_reply_worker.py`：新增可选 `debounce_seconds`，按 `room_id` 暂存 pending 候选；同 room 窗口内替换为最新任务，不同 room 独立进入队列。
- `channel/wechat_group/wechat_group_channel.py`：自由回复入队时不再提前记录冷却；worker 判定通过并进入回复上下文后再 `mark_triggered()`。
- `tests/test_wechat_group_free_reply_worker.py`：覆盖同 room 合并与跨 room 隔离。
- `tests/test_wechat_group_channel.py`：覆盖连续候选不会被入队时冷却提前拦截。
- `AGENTS.md`：补充自由回复 worker 的 room 级防抖、跨群隔离和冷却记录时机维护约束。
