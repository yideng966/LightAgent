# 按群设置自由回复档位开发计划

## 1. 任务背景

GitHub Issue [#3](https://github.com/yideng966/LightAgent/issues/3) 要求个人微信群的自由回复档位支持按群选择。当前系统已有“安静、普通、活跃、高频”四套全局共享档位参数，但所有自由回复群只能使用同一个 `wechat_group_free_reply_activity_level`。

本次目标是在不改变现有评分规则、档位参数和自由回复主链路的前提下，让每个已启用自由回复的稳定微信群可以覆盖全局默认档位。

## 2. 需求分析与验收标准

- 在 Web 控制台“自由回复群”的每个群勾选项右侧提供档位下拉框。
- 群只选择四个既有档位之一，不允许按群修改阈值、冷却、小时上限或连续上限。
- 保留全局 `wechat_group_free_reply_activity_level` 和四套 profile 参数；未配置单群档位时完全沿用全局行为。
- 新映射只接受稳定群 ID，runtime room ID、群名、空键和非法档位不得持久化或生效。
- 取消自由回复群勾选后，不再保存该群的档位覆盖。
- 已勾选群的下拉框可用，未勾选或稳定身份未确认的群禁用；键盘焦点、小屏换行和暗色模式沿用现有控制台样式。
- 不修改 Electron 桌面端、Wechaty sidecar、自由回复 worker、LLM 二次判定、情绪调节或 `@` 必回链路。

## 3. 技术方案

新增向后兼容的独立配置映射：

```json
"wechat_group_free_reply_stable_room_activity_levels": {
  "wgr_example_a": "quiet",
  "wgr_example_b": "active"
}
```

运行时解析顺序：当前 `stable_room_id` 的有效映射值 -> 全局 `wechat_group_free_reply_activity_level` -> `normal`。四套 `wechat_group_free_reply_profiles` 继续作为全局共享模板，实际评分、玩梗分值、阈值、冷却和上限使用解析后的档位。

Web 保存接口与运行时复用同一归一化函数，避免手工配置和页面保存产生不同校验规则。前端只收集当前已勾选、稳定身份已确认且档位合法的群映射。

## 4. 改动范围

- `config.py`、`config-template.json`：增加空映射默认值。
- `channel/wechat_group/wechat_group_free_reply.py`：归一化映射并按稳定群解析实际档位。
- `channel/web/web_channel.py`：允许并校验新配置键。
- `channel/web/static/js/console.js`、`channel/web/static/css/console.css`：渲染、联动和保存每群档位，并适配小屏布局。
- `tests/test_wechat_group_free_reply.py`、`tests/test_wechat_group_web.py`：覆盖后端行为、Web 保存和 UI 合同。
- `README.md`、`AGENTS.md`、`CHANGES.md`：补充用户说明、维护约束与交付记录。

## 7. 风险与回退

- 风险集中在旧配置兼容、错误 room ID 扩大作用域、前端保存时误删映射和小屏布局拥挤。
- 通过 stable-only 服务端校验、未映射全局回退、只保存已勾选群和定向 UI 合同测试隔离风险。
- 本次不新增依赖、数据库或迁移脚本。回退对应提交后，旧版本会忽略新配置键并继续使用全局档位。
