# 模型故障熔断与界面说明开发计划

**目标：** 在现有 Agent 模型备用链基础上增加跨请求的连续故障熔断与自动恢复，避免每次 LLM 调用重复撞击已故障主模型；同时在 Web 控制台模型管理区域向用户明确展示实际切换规则。

**状态：** 已完成

## 设计结论

1. 当前请求的主模型首次出现 408、429、5xx、timeout、rate limit 等临时故障时，仍立即按配置顺序尝试备用模型，不等待累计三次，保证当轮响应速度。
2. 主模型按 `bot_type + model` 记录连续临时故障；默认连续 3 次后打开熔断。
3. 熔断状态保存在当前进程的 `AgentBridge`/`Bridge` 运行时中，跨会话共享，不修改 `model`、`bot_type` 或用户配置文件。
4. 默认熔断 300 秒。熔断期间后续 LLM 请求跳过主模型，直接从备用模型开始。
5. 冷却结束后只允许一个并发请求试探主模型；成功则恢复主模型并清零计数，临时失败则重新进入冷却。
6. 主模型成功响应或返回非临时故障会中断连续临时故障计数。
7. 备用候选全部失败后标记为 fallback exhausted，Agent 外层不再等待 30/45/60 秒重复整条候选链。
8. Web 控制台只展示规则说明和当前生效参数，不新增复杂开关，不修改桌面端。

## 配置

新增默认配置：

```json
"model_failover_failure_threshold": 3,
"model_failover_cooldown_seconds": 300
```

- `model_failover_failure_threshold`：打开熔断前的连续临时故障次数，最小值 1。
- `model_failover_cooldown_seconds`：熔断冷却秒数，最小值 1。

## 风险与回退

- 熔断只处理已定义的临时模型故障；400、鉴权、参数错误等非临时错误保持原行为。
- 熔断仅在存在备用模型时生效；没有备用模型时继续使用现有主模型错误处理。
- 自动状态不持久化，重启服务或重置 Bridge 即恢复从主模型开始，回退风险有限。
- 若需回退，可删除新增熔断状态调用并保留原有逐次 fallback，不影响备用模型配置格式。

## 实施结果

- `AgentLLMModel` 使用线程安全的 `_ModelFailoverState`，同一 Bridge 下的不同会话共享主模型健康状态；状态键为 `bot_type + model`。
- 每次主模型临时故障仍立即尝试备用模型；第三次连续临时故障后打开熔断，熔断期间候选列表排除主模型。
- 冷却到期后第一个请求获得半开试探权，其他并发请求继续使用备用模型；试探成功清零状态，失败重新开始 300 秒冷却。
- 主模型正常响应或非临时错误会清除连续临时故障计数；未配置备用模型时不启用熔断。
- 备用链全部返回临时故障时增加 `model_fallback_exhausted` 标记，Agent 外层将其识别为不可重试，避免整链重复 4 轮。
- Web 模型管理 API 返回实际阈值与冷却秒数；备用模型区域展示当前请求、连续故障与自动恢复三段规则，不提供额外复杂开关。
- UI 采用现有模型卡片的排版、颜色和 Font Awesome 图标，支持中英文、浅色/深色模式与移动端自然换行。
