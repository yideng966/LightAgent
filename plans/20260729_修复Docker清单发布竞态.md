# 修复 Docker 清单发布竞态并发布 2.1.21

## 状态

发布准备中

## 发布信息

- 上一稳定版本：`v2.1.20`
- 目标版本：`v2.1.21`
- 发布范围：Docker 清单清理竞态修复，不包含新的业务功能。

## 背景

`v2.1.20` 的四个平台镜像均构建并推送成功，基础版多架构清单也已发布，但完整技能版在向 GHCR 创建清单时提示 OCI 子 manifest 不存在。远端日志显示，基础版清单任务在完整技能版仍读取 canonical digest 时执行了 `actions/delete-package-versions@v4`，删除了 16 个尚未被最终标签引用的未标记版本，导致完整技能版发布失败。

## 目标

- 保持基础版与完整技能版 manifest 并行发布能力。
- 仅在两个变体均成功发布后清理 GHCR 未标记版本。
- 任一 manifest 发布失败时跳过清理，保留可供重试和排障的 canonical digest。
- 不改变 Docker Hub、GHCR、版本标签、浮动标签和原生双架构构建方式。

## 验收标准

- `publish-manifest` 的任一矩阵实例都不直接删除 GHCR 未标记版本。
- 独立清理任务显式依赖整个 `publish-manifest` 矩阵成功。
- 清理失败不可能中断仍在运行的基础版或完整技能版 manifest 组装。
- 现有原生 AMD64/ARM64、双 Registry、基础版与完整技能版标签契约保持不变。

## 故障证据

- `v2.1.20` 运行 `30441772391` 的四个 `build-and-push-image` 任务全部成功。
- 基础版 GHCR manifest 于 `2026-07-29T10:00:32.292Z` 完成。
- 基础版任务中的清理动作于 `2026-07-29T10:00:32.880Z` 报告已删除 16 个版本。
- 完整技能版 GHCR manifest 随后于 `2026-07-29T10:00:46.722Z` 因子 manifest `sha256:652ba2b89a86111abd6474d881326f0756ab7bbcae7fb286be3c96127859cc23` 不存在而失败。
- 当前 GHCR 基础版 `v2.1.20` 可正常解析，`v2.1.20-skills-full` 不存在；失败发生在发布清单阶段，不是镜像构建阶段。

## 实际改动

- 从 `publish-manifest` 的基础版矩阵实例中移除 `actions/delete-package-versions@v4`，避免其与完整技能版并行发布。
- 新增 `cleanup-ghcr` Job，显式依赖 `publish-manifest`，并要求整个矩阵结果为 `success` 后才执行未标记版本清理。
- 在 Docker 发布契约测试中固定清理任务的位置、依赖和成功条件，防止后续改动重新引入竞态。
