## 一、最新需求基线

本节是当前需求的权威口径。与 Issue 原文、旧版计划或早期 UI 稿冲突时，一律以本节为准。

### 1.1 保留能力

1. 对已选择微信群持续归档消息，保存稳定群 ID、稳定成员 ID、当前群昵称、消息类型、安全正文和发言时间。
2. 支持上一自然日、上一自然周、上一自然月和显式自定义时间范围。
3. 成员改名后继续按稳定成员 ID 合并统计，报告展示当前群昵称。
4. 所有查询、报告、记忆和发送目标按稳定群 ID 隔离。
5. 支持群内手动输出、Web 预览/发送和 scheduler 定时发送。
6. 支持按群配置仅管理员可手动输出报告。
7. 支持将日报重点话题保存到当前群作用域每日记忆。
8. 支持纯文本、仅图片、图片优先且失败回退纯文本三档输出；图片支持 Skill 模板并将当前赛博智能 UI 作为仓库随附默认 Skill，纯文本支持内置/自定义文字模板。

### 1.2 明确删除

- 不实现实时在群成员检测或离群状态机。
- 不排除已离群成员；排行以统计周期内的归档发言事实为准。
- 不统计未发言人员名单。
- 不保存“最近成员目录”，不展示成员快照人数、快照活跃率或目录采集时间。

### 1.3 群聊报告六个固定模块

所有内置文字模板、自定义文字模板、内置图片模板和 Skill 图片模板必须消费同一份结构化数据，并完整展示以下六个模块。模板只能改变视觉与排版，不能删除字段或改变统计事实。

#### 模块 1：报告抬头

- 群名；
- 统计周期，必须展示明确起止时间；
- 发言人数；
- 消息数量。

统计周期使用服务器配置时区，默认 `Asia/Shanghai`，统一采用半开区间 `[start_at, end_at)`。

#### 模块 2：核心统计

- 总发言数；
- 榜一成员的当前群昵称；
- 重点话题数量。

榜一成员同时属于排行榜第一名。若榜首并列，按当前群昵称、稳定成员 ID 做确定性排序；稳定成员 ID 不进入报告正文。

#### 模块 3：发言排行榜

- 固定展示前五名；
- 每项展示排名、当前群昵称和发言数量；
- 改名前后消息必须按 canonical stable member 合并；
- 少于五名时只展示实际成员，不虚构占位成员。

#### 模块 4：重点话题

- 固定提供三个话题槽位；
- 每项展示话题标题、话题热度和内容概括；
- 热度由服务端根据证据消息数、参与人数和持续时间确定性计算，不允许 LLM 随意填写；
- 有效话题不足三个时明确显示“本周期有效话题不足”，不得编造内容。

#### 模块 5：精彩发言

- 固定提供三个精彩发言槽位；
- 每项展示当前群昵称、安全截断后的原发言和调侃式点评；
- 点评可以轻松、有梗，但不得侮辱、骚扰、歧视、色情化，不推断健康、政治、宗教、收入等敏感属性；
- 原发言必须能回溯到当前群、当前周期的真实归档消息，模型不得杜撰；
- 有效发言不足三条时明确提示，不用其他群或其他周期内容补足。

#### 模块 6：群聊链接收集

- 收集当前群、当前统计周期内出现的全部合法 HTTP/HTTPS 链接；
- 按规范化 URL 去重，并保留首次出现顺序；
- 每项展示站点域名、原始 URL、链接提供人的当前群昵称和链接内容概括；
- 同一 URL 被多名成员重复提供时，按 stable member 去重后展示全部提供人当前群昵称；
- 链接过多时允许长图继续增高或按章节边界拆成多张图，不得静默丢弃；
- 无链接时显示“本周期未收集到链接”。

链接内容概括必须建立在安全抓取结果之上。抓取失败、被 SSRF 策略拒绝、需要登录、超时或正文为空时，展示明确状态，不允许模型根据 URL 猜测网页内容。

### 1.4 报告页脚

页脚不是额外业务模块，只用于显示生成时间、时区、归档覆盖数量和无法稳定归属的消息数量。正文不得出现 stable/runtime ID、微信号、本机路径、XML、base64、媒体路径或内部错误 envelope。

可借鉴机制：

| 机制 | 参考做法 | LightAgent 采用方式 |
| --- | --- | --- |
| 日/周/月排行 | 独立 SQL 按发送者聚合 | 统一为半开时间区间聚合接口 |
| 报告总结 | LLM 输出结构化数据后渲染 | 统计事实、LLM 内容、模板渲染三层分离 |
| 图片报告 | HTML 模板截图 | 独立实现受控 HTML/CSS 长图渲染 |
| 定时任务 | 自建 gocron | 复用 LightAgent scheduler |
| 群级配置 | 群设置控制任务 | 按 stable room 保存报告配置 |

不直接照搬：

1. 不接入参考仓库未开源的 iPad 协议服务，继续使用 Wechaty sidecar。
2. 不复制受许可证约束的模板或代码，只借鉴数据流和职责划分。
3. 不直接调用 OpenAI SDK，继续复用 `Bridge` 和当前模型路由。
4. 不引入 MySQL、GORM 或第二套 cron。
5. 不迁移成员 `is_leaved` 状态机和成员同步任务。

## 三、当前能力与缺口

| 能力 | 当前状态 | 本次处理 |
| --- | --- | --- |
| 消息归档 | `wechat_group_messages` 已保存 stable/runtime 群成员字段、昵称、类型、正文和时间 | 补范围聚合、链接抽取和必要索引 |
| 多时段排行 | 现有成员列表只能粗略计数 | 增加日/周/月/custom 通用统计服务 |
| 改名合并 | 已有 stable member 与 canonical redirect | 聚合后再解析当前群昵称 |
| 重点话题 | 有归档证据和本地摘要 | 增加固定三个槽位、证据校验和确定性热度 |
| 精彩发言 | 无结构化选取和安全点评 | 增加真实消息绑定、三条选择和语气安全规则 |
| 链接收集 | 归档正文可包含 URL，但没有周期汇总 | 增加 URL 抽取、去重、安全抓取和概括 |
| 输出方式与文字模板 | 当前没有报告三档投递或安全自定义文字模板 | 增加 text/image/image_preferred 和安全 Formatter |
| 图片报告 | 无报告长图渲染链路 | 增加 941px 宽、自动增高的 HTML/CSS 渲染 |
| 管理员/调度 | 已有稳定群管理员和 scheduler | 增加报告专用适配，不创建并行体系 |

“全量保存”只指功能启用后、已选择群的实时入站消息，不承诺补抓启用前历史或未选择群消息。当前归档默认长期保留，实施文档必须说明磁盘、隐私和备份责任。

### 3.1 需求复盘发现

现有需求方向可行，但原计划仍有以下会影响真实落地的问题：

| 优先级 | 问题 | 当前事实 | 处理结论 |
| --- | --- | --- | --- |
| P0 | 图片发送成功无法精确确认 | sidecar 的 `send_result` 没有请求 ID，`send_image` 还复用 `send_file` 结果，Python 通道未消费该事件 | 先扩展 JSON Lines 发送确认协议，再实现图片失败回退；否则无法可靠区分失败、未知和部分成功 |
| P0 | 普通文本链路会清理和截断回复 | `WechatGroupChannel.send()` 默认应用聊天回复清理和长度限制 | 报告使用专用分段投递服务，不经过普通聊天回复截断；每段单独确认和审计 |
| P0 | 同步 Web 请求不适合长任务 | 链接抓取、LLM、长图截图和发送可能持续数十秒 | 预览、生成和发送改为后台任务，HTTP 返回任务 ID，UI 轮询状态 |
| P0 | 权限主体混淆 | 群成员、Web 控制台用户和 scheduler 没有相同的身份字段 | 群内手动请求按 stable room/member 校验；Web 按 `_require_auth()`；scheduler 使用受信系统主体 |
| P1 | 按群大配置不适合直接塞入 `config.json` | 自定义模板可达 64 KiB，且保存设置还要同步 scheduler 的 JSON Store | 全局默认放配置中心，按群设置放报告 SQLite Store；scheduler 通过可重试 reconciliation 同步 |
| P1 | 报告链接不能依赖可关闭的 SSRF 总开关 | `validate_url_safe()` 默认可被全局配置关闭 | 报告链接抓取使用强制严格模式，初始 URL、DNS 和每跳重定向始终校验公网地址 |
| P1 | “当前昵称”与已删除的实时成员检测存在潜在冲突 | 当前群成员列表依赖在线 sidecar，需求已明确不做实时成员检测 | 昵称从稳定身份库和当前群最后归档昵称解析，不把在线成员刷新作为报告生成前置条件 |
| P1 | 当前报告唯一键不支持审计式重生成 | 同周期可能因迟到消息、模型重试或人工强制刷新产生新快照 | 报告快照增加 revision/source watermark，已发送快照保持不可变 |
| P2 | 设计稿排行榜有头像，但需求和归档没有头像字段 | sidecar 成员数据未提供持久化头像 | 首版使用昵称首字/默认头像，不新增头像抓取、保存或实时成员同步 |
| P2 | “消息数量”和“总发言数”容易产生两套口径 | 当前六模块同时展示两个名称 | 两者明确复用同一个 `total_messages`，只是展示位置不同 |
| P2 | 大群全部链接会放大耗时和成本 | 需求要求全部列出，单周期可能有大量 URL | 全部合法 URL 都保留并逐项处理；抓取使用受控并发和单链接超时，任务可较长但不按数量截断或静默丢弃 |

### 3.2 推荐默认决策

1. `total_messages` 统计所有可计数入站消息，包括稳定成员未解析消息；`active_speaker_count` 和排行只统计已解析 stable member，未解析数量放页脚诊断。
2. 当前群昵称解析顺序为：当前群稳定身份记录的最新有效昵称、当前周期最后一次非空归档昵称、当前群历史最后一次非空归档昵称、确定性的“未命名群友 N”；正文永不回退展示 stable/runtime ID。
3. Web 控制台登录用户可以配置、预览和立即发送；`manual_admin_only` 只约束群内成员触发报告，不阻止 scheduler 或已登录 Web 管理员。
4. 报告任务全部异步执行；重复点击按幂等键合并，UI 展示进行中任务，不并行生成同群同周期同 revision。
5. 图片排行榜首版使用确定性首字头像或统一默认头像；不为视觉效果恢复已删除的实时成员检测需求。
6. 报告时区首版使用全局 `wechat_group_report_timezone`，默认 `Asia/Shanghai`；统计区间使用 `zoneinfo` 计算，scheduler 触发时间与该时区在 UI 中同时展示。
7. 日报话题在结构化报告达到 `ready` 后幂等写入群作用域记忆，投递失败不回滚已验证话题；报告生成失败则不写入。
8. Skill 图片模板只加载带标准模板 manifest 的本地 Skill 静态资源，不执行 Skill 中的任意脚本或模型工作流；当前赛博智能确认稿作为仓库随附的默认 Skill 模板。

## 四、总体架构

```text
Wechaty 群消息
  -> 现有稳定身份解析
  -> WechatGroupArchive 按原始消息归档

报告触发（群内 / Web / scheduler）
  -> 服务端绑定 stable_room_id、时间范围和管理员状态
  -> 确定性统计总量、人数、榜一和前五排行
  -> 当前群昵称装配
  -> 当前群当前周期证据分页
  -> URL 抽取、规范化、去重和安全抓取
  -> LLM 生成三个话题概括、三个精彩发言点评和链接概括
  -> 服务端完成证据、数量、热度、URL 和安全校验
  -> 保存结构化报告快照
  -> 根据 output_mode 渲染安全纯文本或内置/Skill 手机长图
  -> 按模式发送、审计实际输出与 fallback；可选保存日报重点话题到群作用域记忆
```

原则：微信群通道只做作用域、协议和发送适配；模型调用、工具、记忆、知识库和 scheduler 继续走 LightAgent 既有主链路。

### 4.1 后台模块职责

| 模块 | 职责 | 明确不负责 |
| --- | --- | --- |
| `WechatGroupStatisticsService` | 时间范围、计数、stable member 合并、排行、证据水位 | 不调用 LLM、不渲染模板 |
| `WechatGroupReportContentService` | 分批提取话题候选、精彩发言和有证据的概括 | 不计算统计数字、不接受模型返回的 ID 作为真实 ID |
| `WechatGroupReportLinkService` | URL 抽取、规范化、严格 SSRF 抓取、正文清洗、链接概括 | 不携带 Cookie/Authorization，不访问本地或内网 |
| `WechatGroupReportStore` | 按群设置、不可变报告 revision、任务状态、delivery 和分片状态 | 不发送微信消息 |
| `WechatGroupReportTemplateRegistry` | 内置模板和兼容 Skill 模板发现、校验、版本哈希 | 不执行 Skill 脚本或任意代码 |
| `WechatGroupReportRenderer` | 安全文本、受控 HTML/CSS 和 PNG 分片渲染 | 不查询归档、不调用 LLM |
| `WechatGroupReportDeliveryService` | stable room 恢复、分片顺序发送、确认、回退和重试 | 不重新生成报告事实 |
| `WechatGroupReportJobRunner` | 有界后台队列、同 key 去重、阶段状态和启动恢复 | 不另建 cron；定时触发仍来自现有 scheduler |
| `WechatGroupReportsHandler` | Web 鉴权、参数校验、任务提交、状态和预览资源输出 | 不在 HTTP 线程同步完成长任务 |
| `WechatGroupReportTool` | 把群内意图转换为当前 stable scope 的报告请求 | 不允许模型传入其他群 ID、管理员状态或任意 SQL |

核心服务入口建议固定为以下形状，Web、Tool 和 scheduler 只调用这些入口，不各自拼装流程：

```python
get_settings(stable_room_id) -> ResolvedReportSettings
save_settings(stable_room_id, settings, expected_version, actor) -> SavedReportSettings

submit_generation(
    stable_room_id, report_type, period_start, period_end,
    actor, draft_settings=None, force_regenerate=False,
) -> JobHandle

get_job_status(job_id, stable_room_id) -> JobStatus
create_delivery(report_id, output_settings, actor) -> DeliveryHandle
send_delivery(delivery_id) -> DeliveryStatus
retry_incomplete_delivery(delivery_id, actor) -> DeliveryStatus
reconcile_report_tasks(stable_room_id=None) -> ReconcileResult
```

所有公开入口第一步都校验 stable room 归属和 actor；Store 层仍要求显式 `stable_room_id`，不能依赖线程全局或最近一次消息上下文。

### 4.2 生成与投递状态机

报告生成和消息投递分开建模，避免“报告已生成但发送失败”被误判为全部失败：

```text
generation:
queued -> collecting -> summarizing -> validating -> ready
                                      \-> failed

delivery:
pending -> rendering -> sending -> sent
                    |          \-> fallback_sending -> fallback_sent
                    |          \-> partial_failed
                    |          \-> delivery_unknown
                    \-> failed
```

- `POST preview/send` 只负责校验并提交任务，返回 `202 + job_id`；UI 通过状态接口轮询。
- 生成进度记录 `stage`、`completed_items`、`total_items` 和脱敏 `error_code`，不把异常堆栈或供应商 envelope 返回前端。
- 同一 `stable_room_id + report_type + period + source_watermark + content_version` 只运行一个生成任务；并发请求复用现有 `job_id`。
- 预览可使用未保存的 draft 模板设置，但 draft 只随本次任务存在，不写按群配置，不触发真实发送或 scheduler 变更。
- 发送必须引用一个 `ready` 报告 revision；模板变更只新建 delivery，不重复调用 LLM。

### 4.3 微信发送确认协议

三档回退成立的前提是发送结果可确认，需先同步扩展 `protocol.py`、Python client/channel 和 sidecar：

1. `send_text`、`send_image`、`send_file`、`send_audio` 命令增加唯一 `request_id`，保留原始 `command_type`。
2. sidecar 无论成功或失败都返回 `send_result`，携带 `request_id`、`command_type`、`room_id`、`ok` 和脱敏错误码。
3. Python client 维护有超时清理的 pending request 映射，提供 `send_*_confirmed(...)->sent|failed|unknown`；现有无需确认的调用保持兼容。
4. 报告图片和文字分片逐片发送并等待确认；前一片未确认前不发送下一片。
5. `unknown` 表示 sidecar/平台结果无法判断，不等同于失败；此时停止后续分片且不触发全文 fallback。
6. delivery part 持久化 `request_id`、序号、类型、文件哈希、状态、尝试次数和时间，重试只处理未成功分片。
7. 报告纯文本不经过 `WechatGroupChannel.send()` 的普通回复清理与 800 字限制，由投递服务按平台安全长度和段落边界拆分。

### 4.4 大数据量与模型调用

- 统计和链接抽取全程分页，不一次性把整个周期消息载入内存。
- 话题采用分批候选再合并：每批仅向模型提供带临时 token 的安全文本，最终三个话题仍需服务端证据校验。
- 精彩发言候选按时间段和成员做确定性分层采样，避免只从最后一页或发言最多者中选择。
- 链接全部进入结果；抓取默认并发 4、单链接连接/读取超时分别建议 3/8 秒、正文上限建议 1 MiB、最多 5 次重定向，数值作为服务端常量并覆盖边界测试。
- 链接阶段不设置会丢项的数量上限或总预算；后台任务按进度处理全部合法 URL，单链接超时或失败只影响该条。
- 模型失败时保留确定性抬头、核心统计、排行和链接状态；话题/点评/链接概括显示可理解的降级文案。

## 五、统计与内容生成

### 5.1 时间范围

| 报告类型 | 默认区间 |
| --- | --- |
| `daily` | 上一自然日 00:00 至当日 00:00 |
| `weekly` | 上一自然周周一 00:00 至本周周一 00:00 |
| `monthly` | 上一自然月 1 日 00:00 至本月 1 日 00:00 |
| `custom` | 服务端校验后的显式起止时间 |

任务迟到、服务重启补跑或人工重试时，区间由逻辑基准时间计算，不能简单使用“当前时间减 N 天”。

### 5.2 确定性统计

扩展 `WechatGroupArchive`：

```python
aggregate_member_activity(
    stable_room_id,
    start_at,
    end_at,
    countable_types,
) -> {
    "total_messages": int,
    "active_speaker_count": int,
    "ranking": [
        {"stable_member_id": str, "message_count": int}
    ],
    "unresolved_message_count": int,
}
```

约束：

- 已绑定 stable room 的归档严格匹配 `stable_room_id`；只有记录自身没有 stable room 时才允许已确认的 legacy alias 兼容读取。
- 排除系统事件、机器人自身回复和内部事件；首版统计文本、图片、贴纸、语音、文件、视频和安全投影后的分享消息。
- SQL 先按 stable member 聚合，服务层再应用 canonical redirect 合并。
- 无法解析 stable member 的消息只进入完整性诊断，不按昵称猜测归属。
- 排行同数量时按当前群昵称、stable member ID 稳定排序；最终只返回前五名。
- `total_messages` 同时作为抬头“消息数量”和核心统计“总发言数”的唯一数据源，不维护第二套计数。
- `active_speaker_count` 只计算 canonical stable member；无法稳定归属的消息仍计入总消息数，并通过 `unresolved_message_count` 在页脚说明。

### 5.3 话题与热度

LLM 从当前群、当前周期的安全证据中返回最多三个话题及证据 token。服务端验证 token 后计算热度：

```text
heat = normalize(
  evidence_message_count,
  unique_participant_count,
  discussion_duration
) -> 0..100
```

建议首版固定为 `round(50 * min(messages/20, 1) + 30 * min(participants/10, 1) + 20 * min(duration_minutes/180, 1))`。证据少于两条不构成有效话题；权重、上限和最小证据在阶段 0 固化为服务端常量并测试，不开放给模型或模板修改。LLM 只负责归纳标题与内容，不负责最终热度数字。

### 5.4 精彩发言

模型只能从服务端提供的临时消息 token 中选择三条。返回结构包含：

```json
{
  "message_token": "m_...",
  "speaker_token": "u_...",
  "commentary": "轻松但不冒犯的调侃点评"
}
```

服务端根据 token 回填当前群昵称和安全原文，并校验消息确属当前 stable room 和统计周期。点评失败或违规时进行一次受控重试；仍失败则显示原发言和中性说明，不发送供应商错误正文。

### 5.5 链接收集与安全概括

1. 从安全投影后的消息正文和已支持的分享消息字段中提取 HTTP/HTTPS URL。
2. 使用结构化 URL 解析器规范化 scheme、host、port、path 和 fragment；按规范化 URL 去重。
3. 保留全部合法链接、首次出现时间、证据消息 token 和提供人 stable member token，禁止跨周期或跨群补充。
4. 渲染前按 canonical stable member 合并提供人，并解析为当前群昵称；stable member ID 不进入报告正文。
5. 复用 `agent/tools/web_fetch/` 的 SSRF 防护，逐次校验初始 URL、DNS 解析和每一次重定向。
6. 禁止访问 loopback、link-local、私网、保留网段、非 HTTP/HTTPS scheme 和本机文件。
7. 使用超时、响应体上限、正文清洗和受控并发，禁止携带 LightAgent Cookie、Authorization 或用户登录态。
8. 仅将安全页面标题和正文摘要交给 LLM 生成一至两句概括。
9. 抓取失败时记录 `blocked` / `timeout` / `login_required` / `empty` / `failed`，在摘要正文中展示状态而非虚构内容；链接条目右侧位置保留给提供人昵称。

对模型开放的 message/member token 只在单次任务内有效。报告 Store 可在内部审计字段保存当前群归档 row ID 和内容哈希，但这些证据引用不得进入模板、Web 响应或微信群正文。

报告相关数据继续使用 `WechatGroupArchive` 相同的数据根目录，但由 `WechatGroupReportStore` 管理以下表：

| 表 | 关键字段与约束 |
| --- | --- |
| `wechat_group_report_settings` | `stable_room_id` 主键、开关、时区、三档输出、文字/图片模板来源、三类调度设置、记忆开关、`version`、scheduler 同步状态；不保存 runtime room ID |
| `wechat_group_report_jobs` | `job_id`、幂等键、任务类型、阶段、进度、状态、脱敏错误、创建/开始/结束时间；服务重启后将运行中任务恢复为可重试状态 |
| `wechat_group_reports` | `report_id`、逻辑 `report_key`、`revision`、source watermark、内容版本、统计/话题/精彩发言/链接 JSON、状态和生成时间；唯一约束为 `report_key + revision` |
| `wechat_group_report_deliveries` | `delivery_id`、`report_id`、触发主体、配置输出档位、实际输出、模板 ID/版本、fallback 原因、状态和发送时间 |
| `wechat_group_report_delivery_parts` | `delivery_id + part_index` 唯一，记录文本/图片、相对路径或内容哈希、sidecar request ID、确认状态、尝试次数和脱敏错误 |

持久化规则：

- `report_key = stable_room_id + report_type + period_start + period_end`；相同周期首次生成 revision 1。
- 同一 source watermark 和内容版本默认复用 ready revision；`force_regenerate=true` 或归档水位变化时创建新 revision。
- 已被 delivery 引用的报告 revision 不再原地修改，确保发送审计可回溯；新 revision 通过 `supersedes_report_id` 关联旧版本。
- 模板切换只创建新 delivery 并复用同一事实快照，不重复抓取链接或调用 LLM。
- 自定义文字模板保存在按群 settings 表；配置中心只提供全局默认值，避免大模板进入 `config.json`。
- 所有 JSON 反序列化后必须经过 schema/version 校验；未知版本拒绝发送并保留可读错误码。
- 报告图片仅保存相对 `agent_workspace/images/wechat_group_reports` 的路径；Web 和日志均不得返回宿主机绝对路径。

### 7.2 三档输出模式

Web UI 使用三段式单选控件，按群保存以下三种互斥模式：

| `output_mode` | UI 名称 | 行为 |
| --- | --- | --- |
| `text` | 纯文本 | 只渲染并发送文字报告，不启动图片渲染器 |
| `image` | 图片 | 只渲染并发送图片；图片渲染或发送失败时记录失败，不发送纯文本 |
| `image_preferred` | 图片优先，失败转纯文本 | 优先发送图片；在确认图片未成功发送时，使用所选文字模板发送纯文本 |

UI 交互约束：

- 设置项名称为“报告输出形式”，三个选项使用互斥的三段式单选控件，不得实现为可同时开启的三个开关。
- 默认选中“图片优先，失败转纯文本”，每个选项下方提供一句结果导向的说明，明确是否会在图片故障时发送文字。
- 切换输出形式只改变当前生效和展示的配置，不清空已经保存的文字模板或图片模板，避免用户往返切换时丢失编辑内容。
- 选择“纯文本”时只展示文字模板设置；选择“图片”时只展示图片模板设置；选择“图片优先，失败转纯文本”时依次展示图片模板和标记为“故障兜底”的文字模板设置。
- 只有具备当前群报告配置权限的用户可以修改并保存输出形式；预览和立即发送继续遵循既有管理员权限规则。

状态与幂等约束：

1. delivery 同时记录 `output_mode`、`actual_output=text|image` 和 `fallback_reason`。
2. `image_preferred` 只有在图片渲染失败、浏览器不可用、图片文件校验失败，或平台明确拒绝且尚未接受任何图片分片时才允许回退文本。
3. 图片发送结果超时且是否成功不可判定时，不立即回退文本，避免同一群收到图片和全文两份重复报告；标记 `delivery_unknown` 等待查询或人工重试。
4. 多分片图片已有任一分片发送成功后，后续分片失败不得再发送整份纯文本；标记 `partial_failed` 并只重试未完成分片。
5. `image` 模式的失败必须在 Web 状态和日志中可见，定时任务按既有重试策略处理，不能静默切换输出类型。
6. 预览严格按当前档位生成：纯文本返回文字预览，图片与图片优先返回图片预览；图片优先的预览失败同时返回将使用的纯文本 fallback 预览和原因，但不执行发送。

### 7.3 纯文本与自定义文字模板

纯文本渲染消费与图片完全相同的六模块结构化报告。提供一个内置 `standard_text` 模板，并允许管理员按群编辑自定义文字模板。

文字模板设置使用“内置模板 / 自定义模板”单选项。选择自定义模板后显示多行编辑器、可用占位符插入菜单、校验结果、恢复默认和纯文本预览；选择内置模板时编辑器只读或隐藏。预览必须使用当前未保存内容渲染，但不得触发真实发送。该设置同时服务 `text` 的正式输出和 `image_preferred` 的故障兜底，`image` 模式不读取文字模板。

可用占位符固定为：

```text
{room_name}
{report_type}
{period_start}
{period_end}
{timezone}
{active_speaker_count}
{total_messages}
{top_speaker_name}
{top_speaker_message_count}
{topic_count}
{ranking_block}
{topics_block}
{highlights_block}
{links_block}
{archive_message_count}
{unresolved_message_count}
{generated_at}
```

其中排行、话题、精彩发言和链接由服务端先渲染为安全文本块，模板不开放循环或表达式。规则：

- 使用 Python `string.Formatter` 或等价安全解析器，只允许上述简单字段。
- 禁止属性访问、下标、函数、过滤器、循环、条件、模板继承和任意代码执行。
- 保存前校验未知字段、未闭合花括号、UTF-8、模板大小和空模板；建议模板上限 64 KiB。
- 自定义模板不得删除六模块和页脚必需字段；后端至少校验 `{room_name}`、`{period_start}`、`{period_end}`、`{active_speaker_count}`、`{total_messages}`、`{top_speaker_name}`、`{topic_count}`、`{ranking_block}`、`{topics_block}`、`{highlights_block}`、`{links_block}`、`{archive_message_count}`、`{unresolved_message_count}`、`{generated_at}` 均存在。
- 渲染结果按微信群文本消息上限在段落边界安全分段，保持顺序并记录分片状态。
- `text` 模式直接使用该模板；`image_preferred` 的 fallback 使用同一模板，保证管理员预览内容与故障回退内容一致。
- 自定义模板校验失败时不保存配置；运行时模板丢失或损坏时使用 `standard_text` 并记录原因。

- HTML 标签、属性、CSS 属性和占位符使用白名单。
- 渲染浏览器拦截全部网络请求并设置严格 CSP。
- 渲染前把已批准的 HTML/CSS/字体/图片资产复制到一次性沙箱目录，只允许读取该目录；Skill 原目录、用户目录和其他本机路径不可被模板引用。
- manifest 的路径字段必须是 `assets/` 内相对路径；模板 ID、Skill 名称和版本进入 delivery 审计与缓存哈希。
- Template Registry 只读取 SkillManager 已完成 builtin/custom 优先级合并后的 entry 和真实 `base_dir`，不自行扫描任意磁盘目录。
- 默认 Skill 放在项目根 `skills/`，随 Docker `ADD .` 进入镜像，并沿用 `app._sync_builtin_skills()` 把完整目录和 assets 同步到 workspace；同步后再次校验 manifest 和资源哈希。
- Skill 列表只展示 manifest 校验通过且版本兼容的模板；校验失败项显示原因但不可选择。
- 默认 Skill 的 `SKILL.md` 保持简短，只说明该 Skill 为群聊报告提供赛博智能图片模板及其资源位置；渲染逻辑归 Report Renderer，不在 Skill 中放执行脚本。
- Skill 不可用时：`image` 模式失败；`image_preferred` 模式回退所选文字模板；手动图片预览返回明确错误。

### 7.5 图片渲染与持久化

- 使用本地 HTML/CSS 和可选 Playwright/Chromium 渲染 PNG。
- 浏览器不可用、`INSTALL_BROWSER=false` 或截图失败时按 `output_mode` 执行：`image` 失败，`image_preferred` 回退纯文本，`text` 不调用浏览器。
- 输出写入 `agent_workspace` 的持久化图片目录；Docker 固定使用 `/home/agent/lightagent/images`，不得写入 `/app`。
- 文件名包含 report ID、模板版本和分片序号；重复任务复用幂等产物。
- 预览和失败临时文件按保留期清理，已发送报告按配置保留。
- 浏览器启动时执行中文字体和 941px 截图能力预检；缺少中文字体时图片模式明确不可用，不能生成方框字图片。
- 单片最大高度、PNG 字节数和微信实发限制在阶段 0 通过真实链路测定后固化；超过限制只在模块或条目边界分片，不缩小字号硬塞。
- Web 预览通过鉴权后的报告资源接口按 delivery/part 读取，不暴露绝对文件路径，也不扩大通用文件服务根目录。

## 八、权限、调度与记忆

### 8.1 管理员门禁

默认 `manual_admin_only=true`。不同触发来源使用不同的可信身份，不能要求 Web 或 scheduler 伪造群成员：

| 触发来源 | 身份与权限 | 允许范围 |
| --- | --- | --- |
| 群内手动请求 | 当前消息中已确认的 `stable_room_id + stable_member_id`；开启 `manual_admin_only` 时必须是本群管理员 | 只能生成/查询当前群报告，不能覆盖 room ID 或发送目标 |
| Web 控制台 | 现有 `_require_auth()` 登录会话 | 可配置已选择且身份确认的群、预览、立即发送和重试；不要求绑定某个群成员 ID |
| scheduler | 服务端受信系统主体 + 任务中固定的 stable room | 只能执行预先保存的当前群报告设置，不能由模型动态修改目标 |

群内请求执行三层门禁：

1. 通道层按当前 stable room/member 拒绝无权限的完整报告请求。
2. 报告 Tool 再次校验 stable room/member 和配置。
3. Prompt/Skill 只作辅助提示，不能替代服务端门禁。

报告 Tool 不接收 `stable_room_id` 参数，群作用域由服务端上下文绑定。模型不得覆盖 room ID、member ID、SQL、数据库路径、管理员状态、Web 身份、scheduler 主体或发送目标。

### 8.2 定时发送

复用 `agent/tools/scheduler/`，按群和报告类型 upsert 确定性任务 ID：

```text
wechat_group_report:<stable_room_id>:daily
wechat_group_report:<stable_room_id>:weekly
wechat_group_report:<stable_room_id>:monthly
```

默认 cron 为日报 `0 9 * * *`、周报 `0 9 * * 1`、月报 `0 9 1 * *`，任务默认关闭。执行时通过 stable room 恢复当前 runtime 目标，不允许按同名群或过期 runtime ID 强发。

实现约束：

- UI 首版只让用户选择发送时间，周报固定上一自然周并于周一发送，月报固定上一自然月并于每月 1 日发送；后端生成 cron，不向普通设置页暴露原始 cron 编辑器。
- 报告 task 的 schedule 增加可选 `timezone`；`SchedulerService` 只在字段存在时用 `zoneinfo` 计算 next run，旧任务没有该字段时保持当前宿主机本地时间行为。
- scheduler action 使用专用 `wechat_group_report` 类型或受控 tool call，持久化 `stable_receiver`、`report_type` 和设置版本，不保存过期 runtime receiver。
- 为 `TaskStore` 增加锁内完成的 `upsert_task()`，避免 `load -> add/update -> save` 并发覆盖其他任务；不让 Web Handler 直接改 `tasks.json`。
- 按群设置保存成功后执行 scheduler reconciliation；同步失败时设置仍保留，但标记 `schedule_sync_status=failed`，UI 显示“重试同步”，启动时再次统一校准。
- scheduler 只负责按时提交幂等后台任务，不在调度线程内等待链接、LLM、截图或微信发送完成。
- 区间由计划触发时间和报告时区计算；迟到补跑仍生成对应上一自然周期，不把实际执行时刻当作区间起点。

### 8.3 每日群话题记忆

- 仅日报支持自动保存，默认关闭。
- 使用当前群作用域 Store，`source_kind=chat_report_daily`。
- `memory_id` 由 stable room + period start 确定，重复生成 upsert。
- 只保存校验后的三个话题和重要结论，不保存完整原文、精彩发言、链接正文或成员 ID。
- 不写共享 `MEMORY.md` 或共享 `memory/YYYY-MM-DD.md`。

在现有 Web 控制台“群聊”左侧导航中，于“群组与管理员”之后增加一级项“群聊报告”；移动端同步加入 `groups-section-select`。继续使用现有 Web 控制台布局、色彩、字体、表单和状态反馈，不把赛博长图视觉套到管理后台。

### 9.3 顶部工具栏与群选择

- 群选择器只展示 `wechat_group_stable_room_ids` 中身份已确认的群；显示群名和连接状态，不显示 stable/runtime ID。
- 切换群前如有未保存改动，弹出“保存 / 放弃 / 取消”确认；取消后保持当前群。
- 总开关是当前群的报告开关。关闭时禁用 scheduler、群内报告 Tool 和日报话题记忆，但仍允许查看已有状态和预览历史 ready 快照。
- 保存按钮是页面唯一主操作；保存中禁用重复点击，成功后更新 settings version 和 scheduler 同步状态。
- 微信未连接时仍可基于归档预览，禁用“立即发送”并说明需要恢复连接；不能把未连接误报成无归档。

### 9.4 定时报告区

- 日报、周报、月报使用三行紧凑设置表，每行包含开关、统计周期说明、发送时间、下次执行和最近状态。
- 用户只编辑 `HH:mm`；周报固定周一发送，月报固定每月 1 日发送。界面明确显示报告时区。
- 开启行但当前群总开关关闭时保留配置并显示“随总开关暂停”，不静默清除。
- scheduler 同步失败在对应行显示错误说明和“重试同步”，颜色之外同时使用图标和文字。
- 首版不提供任意 cron、补发策略编辑或多个同类型定时任务。

### 9.5 输出形式与模板区

- “报告输出形式”使用互斥三段控件；宽度不足时换行成三项单选列表，文本不得截断。
- 纯文本模式只显示文字模板；图片模式只显示图片模板；图片优先同时显示图片模板和带“故障兜底”标识的文字模板。
- 自定义文字模板编辑器提供字段插入菜单、当前字符数、失焦校验、错误定位、恢复内置模板和预览；错误显示在编辑器下方并将保存按钮置为不可提交状态。
- 切换模板来源或输出形式不清除草稿；“恢复默认”只修改当前草稿，仍需点击保存。
- 图片模板选择器默认选中并标记“默认”的 `赛博智能` Skill，使用当前确认稿作为缩略图；同时展示模板名称、Skill 来源、版本和兼容状态，其他 Skill 校验失败项禁用并展示原因。
- 管理后台图标沿用项目现有图标库；报告长图继续使用已确认的统一 Lucide 线性图标，不混用 emoji。

### 9.6 手动预览与发送

- 周期选择支持上一自然日、上一自然周、上一自然月和自定义范围；自定义结束时间必须晚于开始时间，并限制在当前群已有归档范围内。
- “生成预览”使用当前页面草稿，提交异步任务后展示阶段、进度和可取消轮询；按钮在同幂等任务运行时显示加载状态。
- 纯文本预览按真实分段展示；图片预览在手机宽度视窗中按比例适配，并提供放大、缩小、适应宽度和逐分片切换图标按钮。
- 图片优先预览若图片渲染失败，同时显示失败原因和实际会使用的文字 fallback，不执行真实发送。
- “立即发送”是次级危险操作：必须先存在当前条件对应的 ready 预览，点击后再次确认群名、周期和输出形式，避免误发到错误群。
- delivery 为 `unknown` 或 `partial_failed` 时显示“查询状态 / 重试未完成分片”，不提供“一键重发全部”。

### 9.7 页面状态、响应式与可访问性

- 完整覆盖：无已选群、无归档、加载中、生成中、ready、模型降级、图片不可用、发送失败、结果未知、部分成功和 scheduler 同步失败。
- 所有字段使用可见 label 和 helper text；错误紧邻字段，页面顶部仅汇总并链接到首个错误。
- 三段控件、模板选项和状态徽章不能只靠颜色表达；支持键盘焦点、`aria-selected` / `aria-live` 和 44px 最小点击区域。
- 在 375、768、1024 和 1440px 验证；移动端使用现有群聊 section 下拉，不新增第二套导航。
- 长 URL、中文长昵称和长错误文案允许换行；状态和按钮保持稳定尺寸，加载状态不能推动周围布局。
- 中英文 I18N key 同步补齐；本次不修改 Electron `desktop/`。

### 9.8 Web API 详细契约

统一注册 `/api/wechat-group/reports/(.*)` 到 `WechatGroupReportsHandler`，所有接口先执行 `_require_auth()`，再使用现有 stable identity mixin 校验群作用域：

| 方法与 action | 输入 | 成功结果 | 关键错误 |
| --- | --- | --- | --- |
| `GET settings` | `stable_room_id` | resolved settings、version、能力、scheduler 状态 | `400 invalid_room`、`404 room_not_selected` |
| `POST settings` | stable room、完整设置、`expected_version` | 新 version、规范化设置、scheduler 同步状态 | `400 validation_failed`、`409 version_conflict` |
| `GET templates` | 可选 stable room | 内置文字/图片模板、兼容 Skill 模板及校验状态 | 单个 Skill 失败不拖垮整个列表 |
| `POST preview` | stable room、周期、可选自定义范围、draft settings | `202 {job_id, report_id?}` | `400 invalid_period`、`409 job_already_running` |
| `POST send` | ready `report_id`、draft/已存输出设置、确认 token | `202 {delivery_id}` | `409 stale_preview`、`503 channel_not_ready` |
| `GET status` | `job_id` 或 `delivery_id` | 阶段、进度、状态、可恢复动作、预览元数据 | `404 not_found` |
| `POST retry` | delivery ID、只允许 `failed/partial_failed` | 新尝试状态；只重试未完成分片 | `409 delivery_unknown` 不允许盲目重发 |
| `GET asset` | delivery ID、part index | 鉴权后的 PNG 内容 | 路径逃逸、非当前 delivery 文件一律 `404` |

API 响应只返回稳定业务 ID、群展示名、相对预览 URL 和错误码，不返回数据库路径、宿主机路径、runtime ID、模型 envelope 或堆栈。POST 请求使用一次性 CSRF/确认 token 或复用控制台现有同源保护；立即发送必须防止刷新页面重复提交。

首版仍不增加报告历史中心、交互式 BI 仪表盘、任意 cron 编辑器或桌面端页面。

## 十三、风险与回退

| 风险 | 控制措施 | 回退 |
| --- | --- | --- |
| 大群归档查询慢 | 时间索引、SQL 聚合、证据分页、实施前基准 | 降低单次证据窗口，不改原始归档 |
| 模型编造话题或发言 | 临时 token、真实证据回填、数量和作用域校验 | 只发送确定性统计和可验证内容 |
| 调侃点评冒犯成员 | 安全规则、结构校验、一次受控重试 | 使用中性说明或省略点评 |
| 恶意链接触发 SSRF | 复用安全抓取、逐跳校验、无凭据请求 | 标记 blocked，不抓取不概括 |
| 全局 SSRF 开关关闭导致报告放行内网 | 报告使用强制严格校验入口和独立回归测试 | 禁用链接抓取，只保留 URL/提供人和 blocked 状态 |
| 后台任务积压或进程重启 | 有界队列、同 key 去重、阶段心跳和启动恢复 | 将无心跳任务标记可重试，不在 HTTP/scheduler 线程阻塞 |
| 设置已保存但 scheduler 同步失败 | settings version、同步状态和启动 reconciliation | 保留设置并暂停对应任务，UI 提供重试同步 |
| sidecar 结果无法关联具体分片 | request ID、逐片等待和 part 审计 | 标记 unknown 并停止，不回退全文或重发全部 |
| 链接过多导致超高图片 | 自动增高、按模块分片、图片大小验证 | 分多张发送；仅 `image_preferred` 且图片尚未发送时可回退文字 |
| Chromium 不可用 | 启动能力检测、明确日志、模式化处理 | `image` 失败；`image_preferred` 回退文字；`text` 不受影响 |
| 图片结果未知造成重复报告 | 平台确认状态、delivery 幂等键、未知状态不自动 fallback | 等待查询或人工重试，不追加全文文本 |
| 图片分片部分成功后失败 | 逐分片状态与序号幂等 | 只重试未完成图片分片，不发送整份文本 |
| Skill 模板注入或逃逸 | 路径、HTML、CSS、CSP 和网络白名单 | `image` 失败；`image_preferred` 使用文字 fallback |
| 默认赛博智能 Skill 未打包、未同步或被禁用 | 根 `skills/` 随源码/Docker发布、启动同步、manifest/hash 能力检测 | UI 标记默认模板不可用；`image` 失败，`image_preferred` 回退文字，不复制隐式内置模板 |
| 自定义文字模板错误或注入 | 固定占位符、安全 Formatter、必需块和大小校验 | 拒绝保存；运行时回退 `standard_text` |
| 重复定时发送 | 周期唯一键、任务确定性 ID、发送状态机 | 禁用任务并保留快照审计 |
| 跨群数据或记忆泄露 | stable room 强绑定和碰撞测试 | 关闭报告/记忆写入，保留归档 |
| 报告图片和快照持续增长 | 90 天默认产物保留、引用检查和定期清理 | 只清理过期渲染产物，不删除原始归档或仍被 delivery 引用的文件 |

当前群总开关关闭后立即禁用该群报告 Tool、scheduler 任务和日报记忆写入；保留原始归档与历史报告，确保可回退且不丢数据。

- 仅处理已选择且 stable identity 已确认的微信群。
- 每个群的报告能力默认关闭；按群启用后才注册调度并允许群内触发。
- 报告时区默认 `Asia/Shanghai`，设置页明确显示。
- 默认输出方式 `image_preferred`，即图片优先，确定失败时回退纯文本。
- 默认文字模板为内置 `standard_text`；默认图片模板来源为 Skill `wechat-group-report-cyber-intelligence`，模板 ID `cyber_intelligence`，输出宽度 941px、高度自动增长。
- 排行头像默认使用昵称首字/默认头像，不采集微信头像。
- 排行固定前五；话题和精彩发言各三个槽位，不足时明确提示且不编造。
- 群内全部合法链接进入报告；安全抓取失败显示状态。
- 报告链接抓取始终启用严格 SSRF 校验，默认并发 4，具体超时和微信文件上限以阶段 0 探针结果为准。
- `manual_admin_only=true`。
- 日报、周报、月报任务默认关闭，开启后的默认发送时间为 09:00。
- 每日话题写入群记忆默认关闭。
- Skill 图片模板不可用时：`image` 模式失败，`image_preferred` 使用当前文字模板回退；预览返回明确原因。
- LLM 失败时保留确定性统计、排行和链接清单，不伪造生成内容。
- 按群设置写 SQLite Store，配置中心只保存全局默认；报告渲染产物默认保留 90 天。
- 不实时检测成员、不维护离群状态、不统计未发言名单或成员快照。
- 不修改桌面端。
