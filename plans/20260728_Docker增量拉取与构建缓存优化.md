# Docker 增量拉取与构建缓存优化计划

## 状态

已完成。代码提交 `48362181`、`master` 与 `v2.1.14` 标签均已推送；标签事件已触发正式镜像构建。

## 背景与证据

- 当前 `linux/amd64` 的 `yideng966/lightagent:latest` 压缩层总量约为 764.88 MiB，其中系统、Python、Playwright Chromium 与能力包安装层约为 618.30 MiB。
- 对比 Docker Hub 的 `v2.1.8` 至 `v2.1.13`，相邻版本此前只复用了约 44.04 MiB 的基础层；`v2.1.12` 升级至 `v2.1.13` 需要下载约 720.84 MiB。`v2.1.13` 的 Dockerfile 重排与跨标签 Registry Cache 是新的缓存基线，因此这次迁移无法避免。
- `v2.1.13` 已在发布工作流中按 `variant + arch` 使用 GHCR Registry Cache。该缓存标签可访问，后续发布应复用未变更的重依赖构建结果。
- 当前最终阶段在复制应用源码后才复制 Node.js、npm 与微信群侧车 `node_modules`。应用源码变化会使这些后续重层失去直接的构建缓存命中机会。

## 目标

1. 不改变 `latest` 的开箱即用能力：继续包含 Chromium、音视频能力、语音能力和微信群侧车。
2. 已拉取过当前基线镜像的用户，在仅业务源码、配置模板、文档或版本号变更后拉取新版时，只下载必要的应用层与元数据，不重复下载浏览器、Python 依赖和侧车依赖大层。
3. 保持 AMD64、ARM64 原生 Runner 构建、跨标签 Registry Cache 和并行多架构发布，避免以缩小拉取量换取更长的 GitHub Actions 构建时间。

## 实施步骤

1. 调整最终镜像层顺序
   - 保持依赖清单、系统/Python/Playwright Chromium 安装位于应用源码复制之前。
   - 将稳定的 Node.js、npm 与侧车 `node_modules` 复制移动到应用源码复制之前。
   - 保持 `pip install --no-deps -e .` 位于应用源码复制之后，确保版本元数据与源码仍正确安装。

2. 保护现有重依赖缓存边界
   - 本次不修改 `v2.1.13` 已生成的系统、Python 与 Playwright Chromium 安装指令，确保 `v2.1.14` 可以直接命中现有约 618 MiB 重依赖层，而不是再次建立新的大层基线。
   - 保持基础版与 `skills-full` 的缓存作用域隔离，避免能力包差异污染基础版缓存。
   - 进一步拆分浏览器与 Python 依赖会改变现有大层摘要，且递归调整 `/usr/local/lib` 所有权可能在 OverlayFS 中复制大量文件；在没有独立收益验证前不纳入本次最小修改。

3. 保持并验证构建缓存
   - 继续使用 `type=registry`、`mode=max` 的 `variant + arch` 独立 BuildKit Registry Cache。
   - 不引入 QEMU，不合并原生 AMD64/ARM64 构建任务，也不在每次发布强制刷新基础镜像。
   - 本次不固定基础镜像摘要，继续接收上游基础镜像的必要安全更新；基础镜像真实变化时允许缓存按预期失效。

4. 缩小应用源码层
   - 核实运行时必需文件后，扩展 `.dockerignore` 排除测试、文档、历史桌面端、计划文件和 CI 元数据等不参与运行的内容。
   - 不排除运行时配置模板、内置技能、Web 静态资源、Python 包和微信群侧车源码。

5. 回归与发布后验收
   - 更新 Docker 发布契约测试，断言稳定重层位于应用源码层之前，且 Registry Cache 配置保持不变。
   - 运行相关 Python 测试和 Dockerfile 静态检查。
   - 发布 `v2.1.14` 后比对 `v2.1.13` 与新版本 OCI manifest：验证 618 MiB 依赖层、Node.js 层和侧车依赖层摘要复用；仅应用源码层、可编辑安装层及配置元数据为新增下载。

## 预期效果与边界

- 对不涉及依赖、浏览器、基础镜像或侧车锁文件的常规发布，后续拉取量应从数百 MiB 降至应用源码层及其后续小层的量级。
- 修改 `requirements*.txt`、`package-lock.json`、Playwright 版本、能力包、基础镜像或 Dockerfile 中对应安装指令时，相关层仍需重新构建和下载；这是保证功能与安全更新正确生效的必要成本。
- `cache-to` 缩短 CI 构建时间，稳定层摘要复用缩小用户增量拉取量；两者共同依赖稳定的 Dockerfile 层顺序，不互相冲突。

## 实际改动

- 保留 `v2.1.13` 的系统、Python、Playwright Chromium 重依赖安装指令不变，避免本次发布主动使约 618 MiB 依赖层失效。
- 将 Node.js、npm、npx、npm 运行库和微信群 sidecar `node_modules` 移至应用源码复制之前，并将最终镜像的 Node 导入校验拆到稳定层中。
- `.dockerignore` 新增测试、文档、计划、历史桌面端、开发工具状态、运行日志和服务器访问信息等排除项，缩小每次变化的源码层。
- 保持原生 AMD64/ARM64 Runner、canonical digest manifest 汇集和按 `variant + arch` 隔离的 GHCR Registry Cache 不变。
- 更新 Docker 发布契约、根目录协作规则、变更记录、`2.1.14` 版本来源和 `v2.1.14` 发行说明。
