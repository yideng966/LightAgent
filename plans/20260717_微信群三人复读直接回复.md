# 微信群三人复读直接回复开发方案

## 任务背景

当前 `repeater_message` 规则要求 3 个及以上不同成员发送相同文本，但命中后只跳过自由回复 LLM Judge，最终仍通过 `produce(context)` 进入 Agent/LLM，导致机器人没有原文复读。

## 目标与边界

- 保持 3 个不同成员的复读阈值不变。
- 命中 `repeater_message` 后直接发送第三名成员的原始文本。
- 复用现有回复发送管线，保留文本清理、归档、情绪状态和异常处理。
- 不改变普通自由回复、图片、语音及其他触发规则。

## 实施步骤

- [已完成] 调整复读命中后的发送分支，绕过 Agent/LLM。
- [已完成] 增加回归测试，验证直接原文发送且不调用 `produce()`。
- [已完成] 运行微信群相关最小测试并记录结果。

## 风险与回退

- 风险：直接回复仍可能被现有微信群文本清理规则处理；普通复读文本不受影响，且统一发送行为更符合渠道约束。
- 回退：移除复读专用分支即可恢复原有 Agent/LLM 回复链路。

## 实际改动与验证

- `channel/wechat_group/wechat_group_channel.py`：命中 `repeater_message` 后通过现有 `_send_reply()` 管线直接发送复读原文并提前返回，不再调用 `produce()`。
- `tests/test_wechat_group_channel.py`：新增三人复读直接发送回归测试，锁定回复类型、原文内容、免 mention、冷却记录及不进入 Agent 的行为。
- `channel/wechat_group/wechat_group_free_reply.py`：历史发送者优先按 `stable_member_id` 去重，避免本轮成员的 stable/runtime ID 被重复计数而造成两人误触发。
- `tests/test_wechat_group_free_reply.py`：补充本轮消息已归档场景下的两人不触发、三人触发边界测试。
- 3 人阈值及复读冷却规则保持不变。

验证结果：

- `python -m unittest tests.test_wechat_group_free_reply tests.test_wechat_group_free_reply_worker tests.test_wechat_group_channel tests.test_wechat_group_message tests.test_wechat_group_web`：通过，239 个测试 OK。
- stable/runtime 去重修复后运行 `python -m unittest tests.test_wechat_group_free_reply tests.test_wechat_group_free_reply_worker tests.test_wechat_group_channel.WechatGroupChannelTest.test_approved_three_sender_repeater_sends_original_text_without_agent`：通过，42 个测试 OK。
