# 微信群聊时间范围总结 Skill 开发计划

> 状态：待实施
>
> 创建日期：2026-07-13
>
> 目标：把“总结今天 6 点到现在的群聊”等请求路由到独立 Skill，由主 Agent 解析时间范围、服务端绑定当前稳定群并读取真实归档，最终输出可核验、完整性明确的群聊总结。
>
> UI 范围：仅修改 Web 控制台技能管理页，不修改 Electron 桌面端。
>
> 数据边界：只读当前 `stable_room_id` 的群聊归档，不新增跨群读取，不写入群记忆、群友画像、知识库或 workspace。

## 一、任务背景

当前微信群通道已经能够把包含“总结”的请求判定为上下文依赖请求，但后续仍复用归档证据、焦点栈、本地摘要和最近上下文等通用注入链路，没有把用户表达的时间范围转换为精确归档查询。

2026-07-13 的真实问题复盘如下：

1. 用户在 14:50 请求“总结一下本群上午聊了什么”。
2. 用户在 14:57 再次请求“总结今天 6 点到现在的群聊”。
3. 第二次请求指定区间内实际归档了 358 条消息，其中 320 条文本。
4. 当前焦点上下文实际只注入了 14:56:45 至 14:57:17 的 8 条消息。
5. 当前归档证据检索失败后仅回退了 14:55:17 至 14:57:17 的 15 条消息。
6. 当前本地抽取摘要因为按时间升序后直接 `LIMIT 100`，实际取到了前一天 15:18 至 23:50 的旧消息。
7. 第二次回复主要复述了第一次回复的“台风、骑行、充值卡”等内容，再拼接最后一分钟的倒计时和撤回消息，证明模型没有重新读取指定区间的完整归档。

核心问题不是“归档没有数据”，而是“时间范围没有被解析为精确查询，真实归档没有作为本轮唯一事实来源进入 Agent”。

## 二、已确认设计结论

### 2.1 推荐主链路

```text
微信群消息
  -> 正则识别群聊总结候选
  -> 检查 wechat-group-chat-summary Skill 是否启用
  -> 标记总结意图并跳过通用历史注入
  -> 以隔离历史模式运行当前主 Agent
  -> 强制只暴露并加载总结 Skill
  -> LLM 把自然语言时间表达解析为结构化范围
  -> 服务端按当前消息时间、时区和安全上限复核范围
  -> 当前 stable_room_id 绑定工具读取真实归档
  -> 清洗传输 XML、路径、内部 ID 和当前总结命令
  -> 在配置上限内分页读取并完成分段归纳
  -> 合并为最终总结并附带覆盖范围、消息数量和完整性状态
  -> 只持久化用户原文和最终总结，不持久化原始工具数据
```

### 2.2 Skill 与代码职责边界

遵循现有 CowAgent Skill 体系和 `skill-creator` 的精简原则：

- Skill 只描述触发场景、执行步骤、工具使用要求、事实约束和输出格式。
- 正则识别、时间校验、当前群绑定、SQLite 查询、分页、数据清洗和权限隔离必须由 Python 代码实现。
- Skill 不直接打开 SQLite 文件，不携带数据库脚本，不接收模型提供的 `room_id`。
- 不在 `channel/wechat_group/` 内新增独立 Agent loop、独立聊天模型路由或第二套长期记忆。
- LLM 时间解析复用当前主 Agent，不额外增加一次独立的小模型请求。
- 常见明确时间表达由服务端规则复算；LLM 只承担自然语言理解和模糊范围判断。

### 2.3 首版产品默认值

首版按以下默认值规划，实施前如无新决策则直接采用：

| 配置 | 默认值 | 说明 |
| --- | ---: | --- |
| 未指定时间时的默认范围 | 最近 120 分钟 | 避免高活跃群默认读取全天数据 |
| 最大总结范围 | 24 小时 | 超出时要求用户缩小范围 |
| 最大消息数 | 1000 条 | 超出时不得静默截断或声称完整 |
| 输出详细程度 | `standard` | 输出主要话题、结论、行动项和未决事项 |
| 最大输出长度 | 1800 字符 | 覆盖当前微信群统一 800 字符限制 |
| 是否包含机器人历史回复 | 否 | 避免旧总结反向污染新总结 |
| 是否包含媒体语义占位符 | 是 | 只保留安全语义，不读取原始 XML 和本机路径 |
| 普通群成员是否可用 | 是 | 只读当前群归档，符合普通成员读取/总结权限 |

“上午”首版按当前本地时区的 06:00 至 12:00 解析；“今天 6 点到现在”以当前消息的 `create_time` 作为结束时间，不使用处理完成时的系统时间。

## 三、范围与非目标

### 3.1 本次范围

- 为微信群文本消息增加群聊总结候选识别。
- 支持明确和常见的中文时间范围表达。
- 增加当前群绑定的只读聊天历史工具。
- 增加内置 `wechat-group-chat-summary` Skill。
- 为总结轮次增加旧会话隔离和临时工具结果清理。
- 在 Web 技能管理页增加该 Skill 的启停和配置入口。
- 为总结回复设置独立输出长度，并在截断或超限时明确提示。
- 增加日志、诊断元数据、自动化测试和真实群手动验收步骤。

### 3.2 非目标

- 不修改桌面端 `desktop/`。
- 不新增独立于 CowAgent Agent 主链路的群聊总结机器人。
- 不把群聊总结结果自动写入群永久记忆、群友画像或知识库。
- 不让普通成员读取其他群、其他账号或任意时间范围的原始归档。
- 不在首版实现小时摘要缓存、日报中心、总结历史管理或定时自动推送。
- 不在首版对历史图片逐张调用 Vision；媒体仅使用已有安全语义或占位符。
- 不开放原始正则、内部分页大小和数据库参数给 Web UI。
- 不把 `wechat_group_recent_context_limit` 或焦点栈上限简单调大作为修复方案。

## 四、现有链路与改造点

### 4.1 当前链路

1. `WechatGroupChannel._compose_context()` 记录当前消息并调用 `WechatGroupHumanizedContextBuilder`。
2. `should_include_contextual_history()` 因文本中出现“总结”而返回 `True`。
3. Builder 依次注入归档证据、本地摘要、焦点栈和 recent transcript。
4. 焦点栈存在消息时优先替代普通 recent transcript，且默认只保留 8 条。
5. Agent 继续携带当前用户会话的旧 assistant 回复，因此可能复述上一轮错误总结。
6. 发送阶段统一使用 `wechat_group_response_cleanup_max_chars=800` 截断文本。

### 4.2 改造原则

- 总结候选一旦确认，不再注入通用归档证据、本地摘要、焦点消息和 recent transcript。
- 管理员策略、触发验证、人设、回复策略等非事实性上下文可以继续保留。
- 总结事实只能来自本轮 `wechat_group_chat_history` 工具返回的数据。
- 总结轮次不得读取旧 assistant 总结作为事实来源。
- 最终回复必须声明真实覆盖范围和数据完整性。

## 五、详细设计

### 5.1 群聊总结候选识别

新增 `channel/wechat_group/wechat_group_summary_intent.py`，提供无副作用的候选判断函数。

动作词和群聊对象词采用双条件匹配：

```python
SUMMARY_ACTION_PATTERN = r"总结|汇总|归纳|复盘|梳理|概括"
GROUP_SCOPE_PATTERN = r"群聊|聊天记录|本群|群里|大家.{0,8}聊|聊了什么"
SUMMARY_NEGATION_PATTERN = r"(?:不要|不用|别|无需).{0,6}(?:总结|汇总|归纳|复盘|梳理|概括)"
```

候选成立条件：

1. 当前渠道必须是 `wechat_group`。
2. 当前消息必须通过既有群范围、@、引用或其他合法触发门禁。
3. 文本同时命中动作词和群聊对象词。
4. 文本不得命中明确否定表达。
5. 纯元讨论不得直接执行真实总结，例如“总结群聊功能为什么不工作”“帮我写一个群聊总结正则”。此类候选交给 Skill/LLM 做最终意图判断，不能仅靠正则执行数据库读取。

建议覆盖的正例：

- `总结今天6点到现在的群聊`
- `汇总一下本群上午聊了什么`
- `把最近两小时群里的聊天记录梳理一下`
- `复盘一下大家刚才聊的内容`

建议覆盖的反例：

- `总结这篇文章`
- `群聊功能怎么配置`
- `不要总结群聊`
- `给“总结群聊”写一个正则`

候选命中后写入当前 `Context`：

```text
wechat_group_summary_intent = true
wechat_group_summary_request = 去除开头 @ 后的用户原文
wechat_group_summary_request_time = 当前消息 create_time
wechat_group_summary_isolated_history = true
```

### 5.2 Skill 启用状态与强制选择

新增内置 Skill：

```text
skills/wechat-group-chat-summary/SKILL.md
```

实施要求：

- 使用现有 `skills/skill-creator/scripts/init_skill.py` 初始化目录，再删除不需要的占位资源。
- Skill 名称固定为 `wechat-group-chat-summary`，目录名与 frontmatter `name` 一致。
- `description` 明确覆盖“总结微信群、本群聊天记录、按时间范围复盘群聊”等触发场景。
- SKILL.md 保持精简，不增加 README、CHANGELOG 或数据库脚本。
- 使用 `skills/skill-creator/scripts/quick_validate.py` 校验 Skill。

总结候选进入 AgentBridge 后：

1. 使用当前 Agent 的 `SkillManager.is_skill_enabled()` 检查 Skill。
2. Skill 未启用时返回明确提示，不继续使用旧的通用历史链路伪装总结。
3. Skill 已启用时，本轮 `agent.run_stream()` 传入：

```python
skill_filter=["wechat-group-chat-summary"]
```

4. 本轮系统提示只暴露总结 Skill，模型按既有 mandatory skill 规则读取其 SKILL.md。
5. 保存 Skill 配置后调用 `AgentBridge.refresh_all_skills()`，确保已存在的 Agent 实例立即刷新。

### 5.3 时间范围解析与校验

LLM 在 Skill 指引下生成结构化范围，推荐结构：

```json
{
  "intent": "group_chat_summary",
  "range_text": "今天6点到现在",
  "start_at": "2026-07-13T06:00:00+08:00",
  "end_at": "2026-07-13T14:57:24+08:00",
  "confidence": 0.99,
  "needs_clarification": false
}
```

新增服务端范围解析/校验模块，至少覆盖：

- `今天 6 点到现在`
- `今天上午`
- `今天下午`
- `今天`
- `昨天`
- `昨晚`
- `刚才`
- `最近 N 分钟`
- `最近 N 小时`
- `从 HH:mm 到现在`
- 显式年月日与时分范围

校验规则：

- 使用当前消息时间作为相对时间基准。
- 使用服务器本地时区并保留明确偏移，不接受 LLM 自行切换时区。
- `start_at < end_at`。
- `end_at <= request_time`。
- 范围不得超过 `max_range_hours`。
- 对常见明确表达使用确定性解析结果覆盖或复核 LLM 结果。
- 模糊表达且置信度不足时返回 `needs_clarification`，不得猜测后查询。
- 服务端最终把实际使用的标准化范围回传给 Agent，最终回复必须使用该范围，而不是复述未经校验的 LLM 文本。

### 5.4 精确归档查询

扩展 `WechatGroupArchive`，新增精确时间范围接口，不复用 `get_recent_messages()`、`search_messages()` 或 `get_messages_for_distill()`：

```python
get_messages_in_range(
    room_id,
    since_ts,
    until_ts,
    cursor=None,
    limit=200,
    exclude_message_id="",
)
```

查询约束：

- 使用 `(stable_room_id = ? OR room_id = ?)` 的既有兼容规则。
- 优先使用 stable room scope。
- 使用 `created_at ASC, id ASC` 保证时间顺序稳定。
- `until_ts` 固定为当前请求快照时间，新到群消息不进入本轮总结。
- 游标至少包含上一页 `created_at + id`，避免同秒消息遗漏或重复。
- 支持超过 500 条的分页读取，不能先 `LIMIT 500` 再做 Python 过滤。
- 增加范围内总数与类型计数接口，供完整性声明和超限判断使用。
- 不修改现有 SQLite 表，不做数据迁移。

### 5.5 当前群绑定工具

新增：

```text
channel/wechat_group/wechat_group_summary_service.py
channel/wechat_group/wechat_group_summary_tools.py
```

工具名固定为：

```text
wechat_group_chat_history
```

工具构造参数由服务端注入：

- 当前 `stable_room_id`
- 当前 `stable_member_id`
- 当前请求 `message_id`
- 当前请求时间
- 当前 Skill 运行配置

模型可提供的参数仅包括：

```json
{
  "range_text": "今天6点到现在",
  "start_at": "2026-07-13T06:00:00+08:00",
  "end_at": "2026-07-13T14:57:24+08:00",
  "cursor": ""
}
```

禁止提供或覆盖：

- `room_id`
- `stable_room_id`
- 数据库路径
- 任意文件路径
- 任意 SQL
- 超出配置上限的 page size

工具返回建议结构：

```json
{
  "range": {
    "start_at": "2026-07-13T06:00:00+08:00",
    "end_at": "2026-07-13T14:57:24+08:00",
    "label": "今天 06:00 至 14:57"
  },
  "counts": {
    "total": 358,
    "text": 320,
    "media": 38
  },
  "page": {
    "returned": 200,
    "next_cursor": "opaque-cursor",
    "complete": false
  },
  "messages": [
    {
      "time": "06:35:12",
      "sender": "群昵称",
      "type": "text",
      "text": "安全处理后的消息正文"
    }
  ]
}
```

### 5.6 数据清洗与隐私边界

在工具返回给 LLM 前统一处理：

- 排除当前总结命令。
- 默认排除 `wechat_group_assistant_replies`，尤其是历史总结回复。
- 使用既有 `project_wechat_message_type()` 识别历史误标的媒体传输载荷。
- 图片、贴纸、视频、文件和撤回消息只保留安全语义占位符。
- 不返回 `message_id`、`sender_id`、`stable_member_id`、`runtime_sender_id`。
- 不返回 `media_path`、本机路径、base64、原始 XML、`aeskey`、`cdnthumburl` 等字段。
- 群昵称只使用当前群记录，不跨群回退别名。
- 链接可保留可见 URL，但不得在未调用网页工具的情况下补充网页内容。
- 日志只记录请求 ID、范围、数量、分页数、耗时和截断状态，不记录完整群聊正文。

### 5.7 隔离旧会话与临时工具结果

这是本次修复的必要条件，不能只靠 Skill 提示模型“忽略历史”。

总结轮次必须支持“隔离历史但不清空会话”：

- 本轮 Agent 执行时不把旧 user/assistant/tool 消息放入推理上下文。
- 不调用现有破坏性 `clear_history=True` 清空持久会话。
- 本轮结束后仍把用户原始总结请求和最终 assistant 总结追加到原会话。
- 原始群聊工具结果只在本轮内存中存在，不写入 conversation store。
- 分页工具调用和大段 transcript 不得残留在 `agent.messages`，避免下一轮上下文膨胀和群聊数据重复暴露。
- 继续沿用 `wechat_group_context_persist_raw_user_only`，持久化用户原文而不是增强块。

如需要扩展 `Agent.run_stream()`，应增加只影响当前执行副本的参数，例如 `isolated_history=True`，并用测试确保原会话历史未被删除、当前最终问答仍正确追加。

### 5.8 分页、容量与总结策略

首版不建设独立摘要缓存，采用受控分页：

1. 工具先返回范围总数。
2. 总数超过 `max_messages` 时停止并要求用户缩小范围，不得静默丢弃。
3. 总数在上限内时，按稳定游标读取所有页。
4. Skill 要求 Agent 对每页提取临时主题、参与者、结论、行动项和未决事项。
5. 所有页读取完成后再合并最终总结。
6. 任一页失败时明确说明未完整覆盖，不得输出“完整总结”。
7. 估算输入字符或 token 超过 Agent 上下文预算时，返回范围过大提示；不得依靠模型上下文截断。

首版输出建议结构：

```text
范围：今天 06:00-14:57
数据：358 条，其中文本 320 条、媒体 38 条，完整覆盖

主要话题
1. ...
2. ...

形成的结论/决定
- ...

待办或未决事项
- ...
```

事实约束：

- 只基于本轮工具证据。
- 区分事实、玩笑、猜测和未确认说法。
- 不因为某条消息靠近当前时间就提高为主要话题。
- 话题覆盖应按整个时间区间判断，不固定只输出 5 条。
- 无结论或行动项时明确省略，不编造。

### 5.9 总结专用回复长度

当前 `cleanup_wechat_group_reply_text()` 默认直接截断到 800 字符且不提示。总结请求改为：

- 当 `wechat_group_summary_intent=true` 时使用 Skill 配置中的 `max_output_chars`。
- 默认 1800 字符，后端限定安全范围。
- 提示模型在生成阶段遵守长度，减少发送阶段硬截断。
- 仍超长时优先在完整段落或条目边界截断。
- 截断后追加明确标记，例如“内容已按配置长度截断”。
- 首版不自动拆成多条群消息，避免刷屏；后续如确有需求单独规划。

### 5.10 Web 技能配置

现有 `/api/skills` 和技能卡只支持启用/禁用。首版不开发通用动态 Skill Schema 引擎，只为 `wechat-group-chat-summary` 增加最小配置抽屉。

配置持久化职责：

- 启用状态继续保存在 workspace `skills/skills_config.json`。
- 运行参数保存在根配置的 `skills.wechat-group-chat-summary`。
- 不在两处重复保存 `enabled`。

建议配置结构：

```json
{
  "skills": {
    "wechat-group-chat-summary": {
      "default_range_minutes": 120,
```

## 八、测试矩阵

### 8.1 意图识别

- 同时包含总结动作词和群聊对象词时命中。
- 只有“总结”或只有“群聊”时不进入专用链路。
- “不要总结群聊”不执行总结。
- “总结群聊功能怎么实现”不读取真实归档。
- 普通 @ 问答、自由回复、图片消息和引用消息不回归。

### 8.2 时间范围

- `今天6点到现在` 使用当天 06:00 和当前消息时间。
- `今天上午` 使用 06:00 至 12:00。
- `最近2小时` 正确跨小时和跨日期。
- `昨天`、`昨晚` 和显式日期范围正确。
- 未来结束时间被收敛或拒绝。
- 开始晚于结束时拒绝。
- 超过 `max_range_hours` 时不查询归档。
- 模糊时间无法可靠解析时要求澄清。

### 8.3 归档与工具

- 精确返回区间内 358 条消息和 320 条文本。
- 不返回前一天旧消息。
- 不返回其他 `stable_room_id` 的消息。
- 不返回当前总结命令。
- 超过 500 条时分页无丢失、无重复且顺序稳定。
- 同秒消息按 `id` 稳定排序。
- 模型无法通过参数切换群。
- 输出不包含 XML、base64、媒体路径或内部 ID。

### 8.4 Agent 与 Skill

- 候选命中后只暴露总结 Skill。
- Skill 禁用时不挂载历史工具。
- 旧 user/assistant/tool 历史不进入总结 turn。
- 原会话不会被清空。
- 最终用户请求和 assistant 总结正常持久化。
- 原始 transcript 和分页工具结果不持久化。
- Agent 运行异常后工具和 system suffix 正确恢复。

### 8.5 输出与 UI

- 完整读取时显示 `complete=true` 对应文案。
- 缺页、超限或工具失败时不得显示完整覆盖。
- 标准模式不会固定只输出最后几条话题。
- 总结可超过普通回复 800 字符但不超过 Skill 配置上限。
- UI 可启停 Skill、读取配置、保存合法配置。
- 非法枚举、负数、超大数和错误布尔值被拒绝且无配置副作用。
- Skill 配置保存后无需重启即可生效。

## 十、验收标准

### 10.1 功能验收

- “总结 + 群聊对象”候选能够稳定进入专用 Skill。
- `今天6点到现在` 能转换为精确时间戳范围。
- 工具真实读取当前群范围内全部消息，并返回可核验计数。
- 最终总结不依赖焦点栈、recent transcript、本地旧摘要或上一轮 assistant 总结。
- 普通群成员可读取并总结当前群，但不能跨群或触发任何写入能力。
- Web 技能页可启停和配置，配置立即生效。

### 10.2 质量验收

- 真实基线区间 358 条消息能够完整覆盖，最终回复明确显示 358/320 等实际计数。
- 主要话题按整个区间的重要性组织，不被最后一分钟高密度消息支配。
- 不把玩笑、猜测、引用旧新闻或撤回占位符写成已确认事实。
- 数据不完整、范围超限或工具失败时明确披露，不输出误导性的完整总结。

### 10.3 安全验收

- 所有查询强绑定当前 `stable_room_id`。
- 工具 schema 不接受 room、文件路径或 SQL 参数。
- Prompt、工具结果、日志和最终回复均不泄露 XML、媒体路径、内部 ID 或其他群内容。
- 临时 transcript 不写入 Agent 持久会话、群记忆或知识库。

## 十一、风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 正则误命中开发讨论 | 只做候选标记，Skill/LLM 做最终意图确认；覆盖否定和元讨论测试 |
| LLM 时间解析偏差 | 常见表达由服务端确定性复算；严格校验起止、时区和最大范围 |
| 旧总结继续污染 | 总结 turn 隔离旧会话；事实仅允许来自当前工具结果 |
| 高活跃群上下文溢出 | 消息数和 token 双上限；超过时要求缩小范围，不静默截断 |
| 分页遗漏同秒消息 | 使用 `created_at + id` 稳定游标 |
| 新消息导致范围漂移 | `end_at` 固定为请求消息时间 |
| 跨群数据泄漏 | 服务端构造工具时绑定 stable room，schema 不暴露 room 参数 |
| 工具结果污染后续会话 | transcript 标记临时，运行结束后从内存和持久化消息中剔除 |
| 详细总结被 800 字截断 | 总结专用输出上限和显式截断标记 |
| UI 配置破坏 config | 白名单、类型、范围校验完成后再原子保存 |
| Skill 关闭后继续调用工具 | AgentBridge 每轮检查启用状态，关闭时不挂载工具 |

## 十二、回退方案

- 通过 Web 技能管理页关闭 `wechat-group-chat-summary`，立即停止专用总结链路。
- 代码回退只需移除总结候选、当前群工具、Skill、UI 配置和对应测试。
- 归档只增加查询接口，不修改表结构，不需要数据库回滚或数据迁移。
- 保留现有 `wechat_group_recent_context_*`、归档证据、焦点栈和普通群聊行为。
- 如单轮历史隔离影响通用 Agent，可先仅撤回隔离参数接入，不清理或重置现有会话数据库。
