# 内置技能运行路径通用修复实施计划

> **面向执行 Agent：** 实施时必须使用 `superpowers:test-driven-development`，并按任务逐项更新本文复选框与实际结果；如需分任务执行，使用 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans`。

**目标：** 取消内置技能启动复制造成的路径和来源错位，确保所有内置技能始终从项目内置目录执行，工作区同名历史副本不能覆盖内置技能，同时保持自定义技能、Skill Hub 技能和 Skill Runner 隔离边界不变。

**架构：** `skills/` 是内置技能唯一代码来源，`agent_workspace/skills/` 只保存用户或 Hub 安装的技能。运行时先加载内置技能，再加载工作区技能；工作区技能仅能覆盖其他非内置工作区来源，不能覆盖已经存在的内置名称。升级时不主动删除历史副本，而是在加载、配置同步和各展示入口中将其识别为无效同名副本。

**技术栈：** Python 3.10、`unittest`、LightAgent `SkillLoader` / `SkillManager`、Click CLI、Docker。

## 二、设计决策

### 2.1 必须保持的约束

1. 内置技能始终以项目根目录下的 `skills/<name>` 为真实 `base_dir`。
2. 工作区同名目录不能覆盖内置技能，不论目录来自历史同步、手工复制还是第三方安装。
3. 不自动删除历史工作区副本，避免升级启动阶段执行不可回退的数据删除。
4. 非同名自定义技能继续从 `agent_workspace/skills/` 加载，现有启停配置、依赖隔离和快照机制不变。
5. 不向全局 Bash 环境注入 `/app`，不改变 `skill_run` 对 `PYTHONPATH` 和 `LIGHTAGENT_*` 的隔离规则。
6. 不硬编码 Docker 路径到通用 Python 逻辑，本地源码运行和 Docker 使用同一加载规则。
7. 不修改生图输出目录；Docker 仍使用 `/home/agent/lightagent/images` 持久化生成图片。
8. 所有安装和创建入口必须在写文件前拒绝内置保留名称，不能出现“文件已安装或创建，但运行时被加载器忽略”的假成功。

### 2.2 明确不采用的方案

- 不采用全局 `PYTHONPATH=/app`：只能覆盖兼容 Bash，不能覆盖 Runner，且扩大所有子进程的导入面。
- 不采用工作区符号链接：Windows、Docker bind mount、备份恢复和权限兼容性不稳定。
- 不只修补 `generate.py`：只能解决当前生图脚本，不能修复其他或未来内置技能的同类路径问题。
- 不在启动时批量删除工作区同名目录：本次修复只让其失效，不做破坏性迁移。

```python
from pathlib import Path


RESERVED_BUILTIN_SKILL_NAMES = frozenset({
    "image-generation",
    "knowledge-wiki",
    "skill-creator",
})


class BuiltinSkillNameError(ValueError):
    pass


def get_builtin_skill_names(builtin_dir=None):
    root = Path(builtin_dir) if builtin_dir else Path(__file__).resolve().parents[2] / "skills"
    names = set(RESERVED_BUILTIN_SKILL_NAMES)
    if root.is_dir():
        names.update(
            path.name
            for path in root.iterdir()
            if path.is_dir() and (path / "SKILL.md").is_file()
        )
    return names


def ensure_not_builtin_skill_name(name, builtin_dir=None):
    if str(name or "") in get_builtin_skill_names(builtin_dir):
        raise BuiltinSkillNameError(
            f"skill '{name}' is a protected LightAgent builtin name"
        )
```

## 六、风险与回滚

### 风险

- 旧工作区同名目录仍占用磁盘，但不会参与运行；这是为避免自动删除用户文件而接受的兼容成本。
- 某些用户可能曾依赖修改工作区内置副本来覆盖官方实现；该行为本来会被每次启动同步覆盖，修复后将被明确禁止。需要自定义时必须使用新的技能名称。
- CLI 或聊天命令若仍存在绕过 `SkillManager` 的直接目录扫描，可能出现“运行用内置、展示为自定义”的不一致，因此任务 4 必须完成。
- 旧 CLI 和 Cloud 安装入口当前允许把内置同名文件写入工作区；若只修改加载器而不完成任务 5，会产生“安装成功但永不执行”的假成功，因此任务 5 是上线前置条件。

### 回滚

代码回滚只需恢复 `app.py` 的启动同步调用、加载器覆盖规则和对应文档；无需迁移配置或数据库。由于本方案不删除历史工作区副本，回滚后旧行为可以恢复，但生图路径异常也会随之恢复。

远端部署、容器重建和真实生图验收不在本计划的默认执行权限内；只有用户另行明确授权时才实施。
