# 群友画像自主学习页面修复计划

> 状态：已完成
>
> 日期：2026-07-29
>
> 范围：Web 控制台“群聊 -> 群友画像 -> 自主学习”，不修改历史桌面端，不改变画像生成算法和数据库结构。

## 1. 问题背景

画像自主学习能力从旧群永久记忆页面迁入群友画像后，页面仍沿用了“固定高度画像双栏 + 底部折叠区”的组合。自主学习展开后，新增内容会与上方占满剩余高度的双栏争抢空间，容易造成内容溢出、滚动区域错乱和视觉重叠。

当前自主学习区使用原生 `details`，但展开状态没有进入前端状态。加载配置、执行学习、查看差异或回滚时会重建整个群聊页面，导致折叠区关闭、滚动位置跳动，已加载的详情也可能被隐藏。配置表单仅存在于 DOM，重绘还会丢失尚未保存的输入。

## 2. 修复目标

1. 自主学习区展开后进入群友画像页面的正常文档流，由群聊主区域统一滚动，不挤压或覆盖画像列表与详情。
2. 展开状态、当前操作状态和配置草稿在必要的异步重绘中保持稳定。
3. 群切换后旧请求不得覆盖新群状态；执行、详情、回滚和刷新不得产生重复请求。
4. 加载、保存、执行、查看详情和回滚具备明确且互斥的按钮状态与错误恢复入口。
5. 保持稳定群作用域、既有 API 和画像学习算法不变。

## 3. 计划改动

### 3.1 页面布局

- 调整群友画像根容器和画像双栏高度约束，移除会让底部折叠内容溢出的固定高度竞争。
- 为自主学习区增加明确的面板边界、展开指示和稳定的状态摘要。
- 在窄屏使用单列布局，在桌面维持画像列表与详情双栏；长运行 ID、失败原因和差异正文允许安全换行。
- 所有交互控件保留可见焦点，主要按钮维持至少 44px 高度，并兼容浅色、深色主题。

### 3.2 前端状态与请求

- 在 `groupsProfilesState` 中保存自主学习展开状态、配置草稿和当前操作类型。
- 在折叠切换、表单输入和群切换时同步状态，异步重绘后恢复展开位置和输入值。
- 统一自主学习请求的开始/结束流程；保存、执行、详情和回滚期间禁用冲突操作并显示对应进度。
- 消除执行或回滚完成后的隐式加载与显式强制加载叠加，确保每次成功操作只触发一轮状态刷新。
- 继续使用请求序号和当前 `stable_room_id` 双重校验，防止旧群响应覆盖当前群。

### 3.3 测试与验收

- 扩展前端契约测试，覆盖正常滚动流、展开状态持久化、配置草稿保存、操作互斥和单次刷新。
- 运行群友画像及 Web API 定向测试，并执行 JavaScript 语法检查。
- 使用当前仓库 `python app.py` 启动本地环境，验证 375、768、1024、1440 宽度下的展开、滚动、表单与按钮状态。
- 检查浅色/深色主题、键盘焦点、横向溢出和控制台错误；临时截图仅用于本地验收，不提交到仓库。

## 4. 风险与回退

- 本次不改画像学习执行器、存储表或配置键，后端风险限制在既有接口契约复核。
- 页面仍复用现有 Tailwind utility、颜色和 Font Awesome 图标，不引入新依赖或新设计体系。
- 若布局回归，可独立回退群友画像渲染与状态改动，不影响画像数据和群记忆入口。

## 6. 实际改动与验证结果

### 6.1 根因复现

- 本地 `python app.py` 实际页面中，展开自主学习后，桌面与 375px 视口的画像网格计算高度均变为 `0px`；网格子项继续以最小高度绘制，自主学习内容从同一位置开始，形成直接覆盖。
- 查看运行差异会触发整个群聊页重绘，原实现没有保存 `details.open`，因此详情数据虽然已写入 state，外层面板却自动关闭。
- 配置输入仅存在于 DOM；输入“空闲分钟 17”后查看差异，重绘会恢复为服务端值 10。
- 手动执行成功后，隐式 `ensureGroupsProfilesLoaded()` 与显式强制刷新同时运行，配置、状态和记录接口各发送两次；画像列表本身没有失效，学习结果无法立即显示。

### 6.2 实际修复

- `buildGroupsProfilesPanel()` 移除固定高度 Flex 竞争，桌面画像双栏使用 `clamp(360px, 46vh, 560px)` 稳定高度，窄屏保持自然单列；自主学习面板位于其后的正常文档流，由群聊 `main` 统一滚动。
- 自主学习面板新增稳定 ID、展开指示、状态摘要、按操作区分的加载反馈、错误重试、运行状态本地化和最近运行区；长 ID、失败原因及差异 JSON 均可换行或横向安全滚动。
- `groupsProfilesState` 新增展开、草稿、脏状态和操作状态；自主学习改为首次展开时加载，异步重绘继续保持展开位置和未保存值，策略未保存时阻止直接执行。
- 保存、执行、差异和回滚统一使用请求序号与当前稳定群校验；执行/回滚成功后只触发一轮状态刷新，并按实际更新数量刷新当前画像。
- 回滚入口只展示给最新可回滚且确有画像更新的成功运行；执行结果为 `skipped` 时显示无新消息，不再误报完成。
- `refreshGroupsProfilesData()` 增加独立请求序号，并同时校验捕获的 `stable_room_id` 和查询词，迟到响应不再覆盖当前群。
- 新增 UI 契约回归，覆盖布局约束、展开和草稿状态、单次刷新、画像刷新、跨群迟到响应与回滚入口。

### 6.3 验证结果

- `python -m unittest tests.test_wechat_group_memory_ui tests.test_wechat_group_web`：131 项通过。
- `python -X utf8 -m unittest discover -s tests`：1211 项通过，1 项按条件跳过。
- `node --check channel/web/static/js/console.js`：通过。
- `git diff --check`：通过，仅有仓库既有的 Windows 换行符提示。
- Playwright 在 375、768、1024、1440 宽度和浅色/深色主题下验证：画像区与自主学习区重叠为 0，页面无横向溢出，键盘 Enter 可展开，按钮为 44px，开关标签点击区不少于 44px，浏览器无脚本错误。
- 交互验证：关闭状态不请求自主学习接口；首次展开后配置、状态和记录各请求一次；差异查看保留展开状态与“17”草稿；保存后草稿转为已保存值；执行后状态接口各刷新一次、画像接口刷新一次，页面显示更新后的画像。
