# 微信群技能管理管理员门禁实施计划

## 目标

在“群聊 -> 群与管理员 -> 管理员门禁能力”中增加独立的技能管理权限，使普通群成员是否可以新增、修改、删除技能由 `wechat_group_admin_required_permissions` 显式控制，并继续按 `stable_room_id + stable_member_id` 判断当前群管理员身份。

## 现状

- 当前权限矩阵没有独立的技能管理项；`self_evolution` 仅覆盖自主进化和技能沉淀意图。
- Agent 的 `write`、`edit`、`bash` 由 `workspace_write` 统一过滤，不能单独表达“允许普通文件写入但禁止修改技能”。
- `/skill install`、`uninstall`、`update`、`rollback` 已有固定的所有者/管理员校验，但未接入可配置的微信群权限矩阵。
- `/skill enable`、`disable` 会修改技能配置，但当前没有调用技能管理员校验。
- 技能列表、搜索、详情、更新检查和校验属于只读操作，不应被技能管理门禁阻断。

## 建议权限语义

新增权限 ID：`skill_manage`，默认开启门禁。

开启时，普通群成员不得执行：

- 安装或创建技能；
- 更新、回滚、启用、禁用或直接编辑技能；
- 卸载或删除技能。

关闭时，仅放开当前微信群中的上述技能管理操作；其他渠道仍沿用现有所有者/管理员安全校验。只读技能操作始终保持可用。

## 实际改动

- 新增一个默认开启的 `skill_manage` 开关，覆盖安装、创建、更新、回滚、启用、禁用、直接编辑和卸载技能。
- 通道意图识别覆盖自然语言及 `/skill` 变更命令，普通成员命中后沿用静默管理员门禁。
- `/skill enable` 和 `/skill disable` 补齐与其他变更命令一致的管理员校验。
- Agent 工具执行前按 workspace 技能根目录识别 `write`、`edit` 和具有修改行为的 `bash` 调用；普通文件写入不被 `skill_manage` 扩大阻断。
- Web 控制台沿用现有权限矩阵交互和保存机制，仅增加一项权限定义。
