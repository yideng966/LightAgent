# 放宽微信群自由回复过期抑制计划

## 任务背景

当前 `observe_only` 自由回复在发送前只要检测到同群 room revision 发生任何变化，就会记录 `stale ambient reply suppressed` 并放弃发送。多人群聊中，模型生成期间出现少量新消息很常见，完全按零容忍处理会让本来仍有价值的接话频繁丢失。

本次计划增加一个可配置的“允许过期消息数”，在 Web 控制台「群聊 -> 自由回复」中管理，默认值为 `5`。

## 拟定行为边界

1. 新配置键使用 `wechat_group_free_reply_stale_message_tolerance`，默认值为 `5`，允许范围为 `0–100`。
2. 配置值只统计请求上下文快照之后、同一 `stable_room_id` 新增的真实入站消息记录，不使用全局自增 ID 的差值代替消息数量。
3. 新增同群入站消息数小于或等于配置值时，`observe_only` 自由回复仍可发送；超过配置值时才抑制。
4. 配置为 `0` 时恢复当前严格行为：只要新增同群入站消息就抑制。
5. 若快照之后已经产生新的机器人回复，仍立即抑制当前 `observe_only` 回复，不受容忍条数影响，避免重复接话或回复乱序。
6. `new_thread`、`resume_thread`、显式 `@` 和引用机器人等定向请求继续保持现有行为，不套用 ambient stale 抑制。
7. room revision 查询或实际计数失败时继续保守抑制，不放宽异常路径。

## 验收标准

1. 默认配置下，快照后同群新增 `1–5` 条入站消息时，`observe_only` 自由回复仍进入确认发送链路。
2. 新增第 `6` 条同群入站消息时回复被抑制，日志包含新增条数、阈值、前后游标和 request ID。
3. 配置为 `0` 时保持当前零容忍行为。
4. 其他群产生的消息不会计入当前群的过期条数。
5. 新机器人回复出现后仍抑制旧的 `observe_only` 候选。
6. Web 设置可读取、修改、边界校验、保存并正确回显默认值 `5`。
7. 定向请求、发送确认和失败回滚边界不发生回归。

## 实施结果

实际改动：

- 新增 `wechat_group_free_reply_stale_message_tolerance`，默认值为 `5`，自由回复配置与 Web 保存接口统一裁剪到 `0–100`。
- 归档层新增同群入站精确计数；其他群造成的全局 ID 间隙不会计入当前群过期量，未绑定稳定群的 legacy 记录仍按原有严格回退条件读取。
- `observe_only` 只在实际新增入站消息数超过阈值时抑制；阈值内记录 tolerated 日志并继续发送。助手回复游标变化、游标回退、查询失败和无效 revision 仍保守抑制。
- Web 自由回复页新增紧凑数值字段、中英文短说明、数字键盘语义和响应式八列宽屏布局；移动端继续单列展示。
