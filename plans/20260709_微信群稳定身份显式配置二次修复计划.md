## 5. 实际改动

- `config.py` 与 `config-template.json` 新增 `wechat_group_free_reply_stable_room_ids`、`wechat_group_blocked_stable_member_ids`，不新增稳定身份总开关。
- `get_wechat_group_free_reply_config()` 优先读取自由回复 stable room 配置，并把旧 `wechat_group_free_reply_room_ids` 作为 `legacy_room_ids` 快照返回。
- `WechatGroupChannel._should_enqueue_free_reply_message()` 黑名单优先使用 stable member，同时保留旧 runtime sender fallback。
- Web extra 返回自由回复 stable/legacy room 字段和管理员黑名单 stable/legacy 字段；`/api/channels` 允许保存并规范化两个新 stable 键。
- Web 控制台保存自由回复群范围时写 `wechat_group_free_reply_stable_room_ids`，并根据 stable->runtime 映射保留旧 `wechat_group_free_reply_room_ids` runtime 快照。
- Web 控制台兼容旧 legacy runtime 自由回复配置：渲染勾选态时将 `legacy_room_ids` / runtime room 映射到 stable room；保存时区分控件是否存在，用户明确取消勾选不会被旧 legacy 字段恢复。
- 迁移脚本将旧自由回复 runtime room 转换到 stable room 配置；单群场景下将可解析的旧 blocked sender 转换到 stable member 配置，旧字段原样保留用于审计和 fallback。
- 迁移脚本改为合并已有 stable 配置；未映射 free reply room 和歧义 blocked sender 进入人工确认报告，不把 runtime ID 写入 stable 字段。
- 迁移脚本扫描 SQLite `media_path` 并汇总缺失媒体清单，缺失文件不阻断其他迁移。
- sidecar 群列表通过 identity service 解析 stable account/room；Web 未解析群明确标记 `identity_unresolved`，不再把 runtime room 伪装为 stable room。
- Web 和桌面端只允许选择已确认 stable room；待确认 room 进入身份恢复视图，room confirm 成功后同步更新运行中绑定状态。
- `wechat_group_names` / `wechat_group_free_reply_names` 仅保留候选发现和显示语义，不再直接放行消息与自由回复。
- 复查期间补充 `_record_inbound_message()` 媒体路径 metadata：写入 `runtime_media_path`、`stable_media_path` 和 `media_path_storage`，明确当前未物理重排时为 `runtime_legacy`。
- 群列表额外暴露 stable account 状态，Web 身份恢复增加账号确认卡片；服务端强制 account -> room -> member 确认顺序并校验实体所属关系，确认时间写真实 Unix 时间。
- sidecar 在线成员列表解析 stable member 和确认状态；管理员选择只接受 confirmed stable member，迁移管理员先标记 `legacy_imported`，成员确认后同步更新并持久化配置。
- legacy runtime room/member 跨 stable account 歧义时返回未解析；当前运行中成员列表优先使用本账号 room 的 stable 映射。
- scheduler Agent/Skill session 使用 stable receiver，send/tool delivery context 使用 stable `notify_session_id`，runtime receiver 只用于真实投递。
- 通道层管理员硬门禁、humanized 降级管理员策略和 recent transcript 改为 stable scope；生图额度按 stable room 连续计数。
- `wechat_group_assistant_replies` 与 `wechat_group_image_create_usage` 增加 stable/runtime 双字段和索引，保留 runtime 审计快照。
- inactive account/room/member candidate alias 在重复解析时继续保持 suspected，不再因目标 stable 实体已 confirmed 而自动放行。
- 本轮 alias 待确认时，通道硬门禁、Prompt 管理员角色、Agent 工具过滤和人设跳过判断统一按普通成员处理。
- identity store 新增可信历史 room alias 查询和非 active 历史 alias 确认能力；画像过滤只展开 active 或有明确确认事件的 room alias，`suspected` alias 不进入 stable 群 scope。
- `WechatGroupProfileService` 的画像列表、群内昵称和别名选择统一使用 stable room 及可信历史 runtime room scope；Web、运行中通道和 Agent 画像工具均注入同一 identity-aware profile service。
