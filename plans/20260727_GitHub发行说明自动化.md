# GitHub 发行说明自动化实施计划

## 目标

- 为 LightAgent GitHub Release 建立统一、面向用户的中文发行说明格式。
- 推送 `v*` 标签后，由现有桌面发布工作流创建或更新对应 GitHub Release。
- 发布前校验发行说明，避免空说明、占位符、版本错配或纯提交列表直接上线。
- 为当前 `v2.1.6` 标签补建首个采用新格式的 GitHub Release。

## 已确认口径

- GitHub 仓库固定为 `yideng966/LightAgent`。
- Release 标题固定为 `LightAgent <去掉 v 前缀的版本号>`。
- 发行说明源文件固定为 `docs/releases/<完整标签>.md`，例如 `docs/releases/v2.1.6.md`。
- 正文使用简体中文，先写定位与版本摘要，再按实际内容使用“新增功能”“优化改进”“Bug 修复”“破坏性变更”等分类，最后提供安装方式和文档入口。
- 空分类必须删除；正文不得直接复制 Git 提交列表、测试日志、文件清单或内部计划。
- 桌面构建产物存在时附加到 GitHub Release；Docker 镜像继续由既有工作流发布。
- 预发布标签包含连字符时标记为 prerelease，不覆盖稳定版 Latest。

## 验证标准

- `python scripts/validate_release_notes.py --tag v2.1.6 docs/releases/v2.1.6.md` 通过。
- 校验脚本能拒绝缺少必需结构、包含占位符或文件名与标签不匹配的说明。
- 标签发布任务只读取与当前标签同名的说明文件，并使用 `--verify-tag` 防止意外创建标签。
- 工作流重跑时更新同一 Release，而不是创建重复 Release；桌面安装包存在时可覆盖上传同名资产。
- `AGENTS.md` 明确发布说明的证据来源、内容结构、禁写内容和标签前检查项。
- `v2.1.6` Release 在线正文、标题和标签均正确。
