# 安卓手机侧边栏入口修复

> 状态：已完成开发验证
> 日期：2026-08-01

## 目标

修复荣耀 Magic 7、华为 Mate 30 Pro 等 Android 手机登录 Web 控制台后，顶部导航栏被浏览器动态视口或输入框自动聚焦带出可视区，导致无法打开左侧侧边栏的问题。

## 已确认现象

1. iPhone 13 Pro 可正常看到移动端导航入口，荣耀 Magic 7 与华为 Mate 30 Pro 不可见，问题不由物理分辨率或 `1024px` 响应式断点直接导致。
2. 移动端侧边栏本来就默认收起，入口位于顶部导航栏左侧。
3. 页面根容器当前使用 `100vh`，登录完成后 `initApp()` 会无条件聚焦底部聊天输入框。
4. 浏览器 `focus()` 默认会将目标滚入可视区；Android 底部浏览器栏与动态可视视口组合后，可能把顶部导航栏移出屏幕。

## 实施范围

1. 为 Web 控制台根容器增加 `100dvh` 高度，并保留 `100vh` 兼容回退。
2. 移动端初始化时不再自动聚焦底部聊天输入框，桌面端保留快捷输入体验。
3. 将移动端导航按钮调整为至少 44 x 44 像素，并同步 `aria-expanded` 状态。
4. 新增静态回归测试，约束动态视口、移动端焦点门禁与导航按钮语义。
5. 同步中英文 Web 控制台说明和 `CHANGES.md`。

使用 Playwright 分别按 iPhone 13 Pro、荣耀 Magic 7 和华为 Mate 30 Pro 的窄屏视口检查：

1. 顶部导航栏和菜单按钮位于首屏可视区域。
2. 菜单按钮触控区域不小于 44 x 44 像素。
3. 点击菜单按钮后侧边栏进入视口，遮罩显示，再次关闭后状态恢复。
4. 页面初始化后移动端聊天输入框不自动获得焦点。

## 实际结果

### 已完成

1. 为 `body`、`#app` 与 `#main-content` 统一增加动态视口容器，使用 `100vh` 回退和 `100dvh` 实际高度，并补齐内容区最小高度约束。
2. 移动端初始化不再自动聚焦聊天输入框；桌面端保留自动聚焦，并通过 `preventScroll` 避免焦点改变页面位置。
3. 顶部菜单按钮稳定为 44 x 44 像素，补充侧边栏关联与展开状态；抽屉打开、关闭和桌面断点恢复时状态一致。
4. 中英文 Web 控制台文档已补充移动端导航说明，根目录 `AGENTS.md` 已固化移动端布局约束，`CHANGES.md` 已记录本次修改。

### 验证结果

- 新增 4 项回归测试，旧实现下全部按预期失败，修复后全部通过。
- `python -X utf8 -m unittest tests.test_web_console_mobile tests.test_wechat_group_web tests.test_wechat_group_memory_ui tests.test_knowledge_web`：135 项通过。
- `node --check channel/web/static/js/console.js` 与 `git diff --check`：通过。
- Playwright 在 390 x 844、432 x 912、424 x 865 三种移动视口及各自缩短 180 像素的模拟地址栏场景中，全部确认顶栏位于首屏、根文档无纵向偏移、菜单触控区为 44 x 44 像素、移动端输入框未自动聚焦、抽屉与遮罩开关正确。
- 人工检查荣耀 Magic 7 尺寸的关闭与展开截图，未发现顶栏、侧边栏、聊天内容或底部输入区重叠。

### 剩余事项

- 代码无剩余事项；部署更新后需在真实荣耀 Magic 7 或华为 Mate 30 Pro 上刷新页面确认浏览器已加载新资源。
