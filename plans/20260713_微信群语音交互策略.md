# 微信群语音交互策略实施计划

## 一、任务背景

微信群语音已经能够通过自定义 ASR 完成转写，但转写文本会再次经过群聊前缀和 @ 门禁。普通语音没有前缀时会被丢弃，导致后续 Agent 与 TTS 回复链路没有执行。

本次在 Web 控制台“群聊”中新增“语音交互”菜单，让管理员选择语音消息的触发策略：

- `force_reply`：识别成功后强制回复，作为默认值。
- `free_reply`：识别文本进入现有自由回复本地评分、群范围、冷却与 LLM 判定链路，通过后才回复。

## 二、实施边界

- 只修改 Web 控制台，不修改 Electron 桌面端。
- 复用现有 `ChatChannel`、微信群自由回复 Worker、Agent、ASR 与 TTS 链路。
- 不新增独立语音 Agent 或独立自由回复实现。
- 保留现有 `wechat_group_voice_reply_enabled`，不改变旧配置语义。
- 新增 `wechat_group_voice_interaction_mode`，无效或缺失值统一回退为 `force_reply`。

## 四、行为约定

### 4.1 强制回复

ASR 成功后，转写文本携带 `wechat_group_force_reply = true` 和 `wechat_group_trigger_source = voice_message`，直接进入既有 Agent 回复链路。`voice_reply_voice` 仍负责决定是否把最终文本转为语音发送。

### 4.2 依赖自由回复规则

ASR 成功后，转写文本作为自由回复候选进入现有 `_should_enqueue_free_reply_message()` 和 `WechatGroupFreeReplyWorkerPool`。只有本地规则及 LLM 判定均通过时才构造文本上下文；该上下文保留语音来源和 `desire_rtype`，避免重复 ASR，并继续支持语音输出。

当自由回复功能未开启、当前群未启用或规则拒绝时，本轮语音不回复，行为与普通自由回复候选一致。

## 六、实施结果

已完成：

- `config.py` 与 `config-template.json` 新增默认值 `force_reply`。
- `ChatChannel` 新增 ASR 转写后处理钩子，默认实现保持原行为；`WechatGroupChannel` 覆盖该钩子实现两种策略。
- 自由回复模式把转写结果按文本参与现有规则判定，判定通过后复用原 Worker 回调并保留语音输出偏好。
- Web API 返回 `extra.voice_interaction.mode`，保存时仅接受两种合法语义；Web 群聊侧栏新增“语音交互”菜单和单选设置。
- 已更新自动化测试和 `CHANGES.md`。

验证结果：

- 新增 8 个核心针对性用例通过。
- 微信群定向回归通过，203 个测试 OK。
- 全量回归通过，768 个测试 OK。
- Python 语法、JSON 格式、JavaScript 语法及差异空白检查通过。

剩余人工验证：手动重启项目后，在目标微信群分别选择两种模式发送真实语音，确认强制模式必回、自由回复模式按现有规则决定是否回复，并在 `voice_reply_voice = true` 时确认最终发送语音消息。
