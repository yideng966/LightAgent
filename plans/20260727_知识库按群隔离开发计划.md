# 知识库按群隔离开发计划

## 背景

GitHub Issue #19 反馈：Web 控制台“知识”页当前只展示工作区 `knowledge/` 下的全局 Markdown 知识库，个人微信群虽然已有按群存储的永久群记忆，但没有在“知识”入口中体现作用域，使用者无法直观查看和管理某个群的知识；同时需要确认微信群 Agent 的群知识召回始终绑定当前群，不能由模型传入其他群 ID 越界查询。

Issue 地址：<https://github.com/yideng966/LightAgent/issues/19>

## 现状梳理

### 全局知识

- `agent/knowledge/service.py` 直接管理 `agent_workspace/knowledge/` 下的 Markdown 文档、目录、导入和知识图谱。
- `channel/web/web_channel.py` 的 `/api/knowledge/*` 接口只服务全局知识。
- `channel/web/chat.html` 与 `channel/web/static/js/console.js` 的“知识”视图只渲染全局文档树和图谱。
- 全局知识会由 `MemoryManager` 以 `source=knowledge`、`scope=shared` 建立索引，现有非群聊使用方式保持不变。

### 群知识

- `WechatGroupKnowledgeStore` 已使用 SQLite 表 `wechat_group_group_memories` 保存群永久记忆，并在所有读写条件中带 `room_id`。
- 长期群作用域优先使用 `wechat_group_stable_room_id`；runtime room ID 只承担已存在的兼容路径。
- `WechatGroupContextService` 在当前群消息进入 Agent 前按当前群查询，并把结果装配进 `<wechat-group-memory>`。
- `WechatGroupMemorySearchTool` 在服务端构造时绑定当前群，工具 schema 不暴露 `room_id`，模型不能主动切换群作用域。
- 群管理页已有群记忆查询、新增和停用接口，可以复用，避免新增平行存储或重复 API。

## 目标

1. 保留现有全局知识的文档、导入、图谱和 API 行为。
2. 在 Web 控制台“知识”页增加“全局知识 / 群知识”作用域切换。
3. 群知识视图只列出已配置的稳定群，支持按群查询、搜索、新增和停用群知识。
4. 服务层提供语义明确的群知识查询入口，并保留现有群记忆方法兼容调用方。
5. 微信群 Agent 的自动上下文和主动工具检索都绑定当前 stable room，工具参数不得接受任意群 ID。
6. 补充跨群隔离、Web 接口和界面合同测试，防止后续回归。

## 非目标

- 不迁移或重写现有 `wechat_group_knowledge.db`。
- 不把群知识改造成 Markdown Wiki，也不为群知识生成知识图谱。
- 不改变全局知识对非微信群渠道的既有行为。
- 不新增第三方依赖，不修改 Electron 桌面端。
- 不扩展自动学习、画像、梦境蒸馏或其他与 Issue #19 无关的群聊能力。

## 设计方案

### 1. 作用域模型

| 作用域 | 存储 | 管理入口 | Agent 查询 |
| --- | --- | --- | --- |
| 全局知识 | `agent_workspace/knowledge/**/*.md` | 现有知识文档树、导入和图谱 | 现有 `read` / `memory_search` |
| 群知识 | `wechat_group_group_memories`，按 stable room ID 隔离 | 知识页“群知识”视图 | 当前群绑定的 `wechat_group_memory_search` |

群知识沿用现有群永久记忆数据，不复制到全局 `knowledge/`，从物理存储和查询条件两层避免跨群混入。

### 2. Web 知识页

- 在标题区增加紧凑的分段控件，默认保持“全局知识”。
- 切到“群知识”后显示群选择器、搜索框、新增按钮和当前群知识列表。
- 群列表只使用后端返回的已选择稳定群；没有可用群时展示明确空状态。
- 列表展示内容、来源和更新时间；停用属于破坏性操作，执行前确认，提交时禁用按钮并显示反馈。
- 群知识模式隐藏全局文档/图谱操作；切回全局后恢复现有界面和状态。
- 沿用现有颜色、字体、圆角、暗色模式和 Font Awesome 图标，不引入新的视觉主题。

### 3. Agent 检索契约

- 在 `WechatGroupKnowledgeService` 增加语义明确的 `search_group_knowledge()`，内部仍调用严格带群条件的存储查询；原 `search_group_memories()` 保留为兼容别名。
- `WechatGroupContextService` 与 `WechatGroupMemorySearchTool` 统一调用该入口。
- AgentBridge 继续优先绑定 `wechat_group_stable_room_id`，仅在缺少稳定字段的旧消息中使用 runtime room ID。
- 工具 schema 继续不暴露 `room_id`，从协议层阻止模型指定其他群。

## 风险与回退

- 风险：知识页同时承载两种数据形态，状态切换处理不完整可能让全局操作误作用到群知识。通过独立面板、独立状态和接口路径隔离。
- 风险：历史配置只有 runtime room ID。后端继续保留既有身份解析兼容，但新 UI 只以稳定群配置为主，不扩大匹配范围。
- 兼容：全局知识 API、文件布局和默认视图不变；现有群管理页与 `search_group_memories()` 调用继续可用。
- 回退：本次不迁移数据，可整体回退代码提交恢复旧知识页，现有全局知识和群记忆数据均不受影响。
