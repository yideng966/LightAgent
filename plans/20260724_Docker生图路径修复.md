# Docker 生图路径修复开发计划

## 背景与诊断结论

当前确定性生图入口由 `channel/channel.py` 启动 `skills/image-generation/scripts/generate.py`。子进程工作目录固定为项目根目录，而脚本在未设置 `IMAGE_OUTPUT_DIR` 时使用 `<cwd>/images`：源码运行时写入仓库根目录 `images/`，Docker 中则写入未挂载的 `/app/images`。

当前 Docker Compose 只持久化：

- `./config -> /home/agent/.lightagent`
- `./data -> /home/agent/lightagent`

因此 Docker 生图结果不在持久化卷中，容器重建后会丢失；Web 文件服务默认也只允许用户主目录和 `agent_workspace`，无法读取 `/app/images`。此外，Web SSE 对确定性生图返回的本地 `ReplyType.IMAGE` 只发送普通 `done` 文本事件，前端不会把绝对路径渲染为图片。

现有日志中的 Provider HTTP 400/503 发生在文件保存之前，属于模型、账号或上游服务配置问题。本次只修复仓库内可控的输出路径和发送链路，不修改私有 `config.json`、API Key 或第三方 Provider 配置。

同步审计语音识别后确认不存在同类 `/app` 路径问题：微信群原始语音位于 `/home/agent/.lightagent/wechat_group/media`（宿主机 `./config/wechat_group/media`），其他渠道临时语音位于 `/home/agent/lightagent/tmp`（宿主机 `./data/tmp`）。微信侧扩展名为 `.sil` 的现有媒体实际为 MP3，当前魔数嗅探和 `pydub + ffmpeg` 转换可以生成 16 kHz 单声道 WAV；该链路无需代码修改。旧卷迁移后仍需关注子目录所有权，避免 sidecar 无法写入新媒体。

## 目标

1. 确定性生图默认输出到 `<agent_workspace>/images`。
2. Docker 显式约定 `IMAGE_OUTPUT_DIR=/home/agent/lightagent/images`，确保结果位于 `./data/images`。
3. Web SSE 能把本地生图结果作为图片事件发送，并以 `done` 事件正常结束当前请求。
4. 保留显式 `IMAGE_OUTPUT_DIR` 覆盖能力，不影响非 Docker 部署的自定义目录。
5. 增加回归测试，防止输出重新落到 `/app/images` 或 Web 只显示本地路径文本。

## 验收标准

1. Docker 生图输出解析为 `/home/agent/lightagent/images`，宿主机可在 `docker/data/images` 持久化查看。
2. 输出文件位于 Web 文件服务允许的 `agent_workspace` 范围内。
3. Web SSE 收到一个可访问的 `image` 事件和一个终止请求的 `done` 事件。
4. 微信群仍直接发送同一容器内的本地图片路径。
5. 显式设置 `IMAGE_OUTPUT_DIR` 时不被代码覆盖。
6. 相关回归及全量测试通过，工作区只包含本任务文件。

## 风险与回退

- Provider 400/503 不由本次代码改动解决；部署后仍需选择实际支持 `/images/generations` 的 Provider 和模型。
- 输出目录从源码根目录 `images/` 迁移到 `agent_workspace/images`，属于有意的持久化位置修正；不迁移历史图片。
- 若 Web SSE 调整出现回归，可独立回退 `channel/web/web_channel.py`，不影响微信群本地图片发送。
