# 修复无标签思考泄漏并发布 2.1.20 计划

> **状态：** 已完成
> **创建日期：** 2026-07-29
> **上一稳定版本：** `v2.1.19`
> **目标版本：** `v2.1.20`
> **目标分支：** `master`

## 1. 问题证据

- 远端容器已运行 `v2.1.19` 对应 `latest` 镜像，17:23 的微信群请求仍泄漏内部分析。
- 同一轮请求的主模型处于 429 熔断状态，从备用候选开始生成。
- 会话数据库中的助手正文由 3 个空行分隔块组成：前两块是“用户…先看看上下文”“我应该…”内部分析，第三块才是最终答复。
- 持久化正文不包含 `<think>` 标签，说明 `v2.1.19` 的标签解析无法覆盖无标签内部分析。

## 2. 修复目标

- 微信群不发送、不通过事件暴露、也不持久化高置信度无标签内部分析前言。
- 带标签思考继续跨 SSE 分片过滤；标准 `reasoning_content` 继续与正文隔离。
- Web 保持现有流式思考展示，其他渠道行为不扩张。
- 普通多段回答、技术说明和类似标签的字面文本不得被截断。

## 4. 风险控制

- 只识别以用户观察块开头、随后存在明确自我决策块、最后存在安全答复块的高置信度结构。
- 不按固定段数或“只取最后一段”截断普通回复。
- 无法从高置信度内部分析结构中找到最终答复时按 fail closed 返回空，不把不确定内容发送给群成员。
- 不向自定义 OpenAI 兼容请求体盲目新增未验证的 `thinking` 字段，避免第三方 Provider 拒绝请求。
- 不连接、部署或重启远端 Docker 容器；标签推送成功即完成触发，不等待构建终态。

## 6. 实际改动

- `agent/protocol/agent_stream.py` 新增微信群无标签内部分析前言净化，并优先使用当前请求上下文判断渠道。
- 微信群 `message_update` 延迟至完整正文净化后发送；带工具调用的中间文本继续由既有群处理器丢弃。
- 过滤仅接受“用户观察行 + 至少一个自我决策行 + 最终答复”结构，支持空行和单换行分段，并保留最终答复的原始换行。
- `tests/test_agent_stream_thinking_filter.py` 覆盖线上复现、单换行、残留 Web 渠道状态和正常多段答复。
- 同步更新项目协作约束、变更记录、版本来源和版本化发行说明。
