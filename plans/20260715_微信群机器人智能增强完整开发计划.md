2. 当前 `AGENTS.md` 和已完成计划继续作为硬约束；本计划不能凭“最高优先级”自行覆盖历史需求。确需改变历史行为时，必须在本节列出旧要求、变更后的行为和批准结论。

4. stable identity 不新增总开关，也不允许退回 runtime ID 作为长期主键；紧急回滚依赖离线备份恢复和行为层 legacy，而不是新增运行时兼容读或重新启用不安全的主键语义。
5. 实施 Phase 3 至 Phase 6 时，必须同步回写本计划和上下文子计划，不能只更新其中一份。

- 允许一个受控、异步、默认关闭的滚动摘要 LLM 调用例外，但只能复用 `AgentLLMModel(Bridge())` 做上下文预处理，不能形成第二套回复 Agent。
- 普通成员消息可以被动参与当前群 scoped 记忆、画像和受限进化，但仍不能主动命令写入、运行进化、修改技能、全局记忆、workspace、scheduler 或微信群配置。
- canonical-only 切换后，无法唯一迁移的数据允许立即不可见；不为此增加新的运行时兼容切换层。

### 0.3 关键决策

- 不更换主模型作为首要解法。
- 不照搬 BaiLongmaPro 每轮固定注入 100 条历史的做法。
- 不在 Wechaty sidecar 中新增模型调用、Agent loop、记忆系统或工具执行器。
- 不在微信群意图路由器中新增回复执行器；除现有通用确定性路径外，最终回复继续进入 `Bridge.fetch_agent_reply()`。
- 不用增加自由回复频率代替上下文准确率。
- 先修 stable 历史数据，再做 timeline、judge 和摘要；依赖顺序不得颠倒。
- 结构化任务与拟人化最终回复使用不同的温度和超时策略。
- 所有新增能力先有失败测试，再实现，再做离线回放和真实群灰度。

## 1. 目标、非目标与完成指标

### 1.1 业务目标

1. 机器人能正确承接群友的省略句、短追问、引用和机器人上一句。
2. 机器人能在当前群准确召回群记忆和当前成员画像，不因重登或 runtime ID 变化失忆。
3. 自由回复能识别谁在对谁说、问题是否已被回答、候选是否已过时，减少乱插话和迟到回复。
4. 总结、当前/引用图片理解、生图和表情包等已有高频能力具有稳定、可解释的路由结果。
5. 结构化 LLM 调用在 JSON、超时、错误 envelope 和 Provider 故障下具有确定性降级。
6. 在提升连续性的同时维持 stable room/member 隔离、管理员硬门禁、媒体安全投影和原文持久化清洗。

### 1.2 技术目标

- 建立 `stable account -> stable room -> stable member` 的历史数据迁移闭环。
- 建立包含 inbound 与 assistant 的统一关系型 room timeline。
- 将 `include_history: bool` 替换为 `current_only / recent / contextual / recall` 策略。
- 将 Agent 历史恢复明确为 `fresh / interactive_session / observe_only`。
- 为 judge、画像抽取、滚动摘要和可选意图分类提供统一结构化输出协议。
- 让 `LLMRequest.temperature` 和 timeout 等请求级参数真正到达 Provider。
- 建立离线回放、运行指标、canary 灰度和逐能力回滚机制。

### 1.3 非目标

- 不开发完整社交工作台、群战报、跨群身份合并市场或复杂人设市场。
- 不修改桌面端 UI；本计划涉及的配置和状态仅修改 Web 控制台。
- 不新增第三方数据库、消息队列或模型 SDK。
- 不把滚动摘要写入群永久记忆，也不让摘要直接生成或发送群回复。
- 不让普通成员主动命令记忆/画像写入、运行自主进化、修改技能、全局记忆、workspace、scheduler 或微信群配置；普通消息仍可进入默认关闭、可审计的 scoped 被动学习链路。
- 不在本次计划中重排历史媒体物理目录。
- 不顺手重构其他渠道的会话、模型或工具体系。

## 2. 硬约束与设计原则

1. **稳定身份优先。**长期配置、权限、归档查询、记忆、画像、风格、焦点、情绪、摘要和 scheduler 只使用 stable scope；runtime 字段只用于真实收发和审计快照。
2. **当前原文优先。**权限、管理员身份和系统配置始终是硬规则；普通事实按时间与来源判断，当前用户消息 > 更新且可追溯的原始 timeline > 较旧的群记忆/成员画像 > 滚动摘要 > 焦点摘要 > 远期归档。管理员后来明确确认且时间更新的记忆可以覆盖更早消息；style、emotion 和 persona 不能覆盖事实。
3. **关系高于纯顺序。**timeline 必须表达 actor、addressee、quote 和 reply-to-assistant，不能只把若干消息按时间拼接。
4. **结构化任务低随机。**judge、画像抽取、摘要和分类使用 0 至 0.2 的低温度；最终拟人化回复使用独立的可配置温度。
5. **最终回复主链路唯一。**所有微信群能力继续复用 `ChatChannel -> Bridge -> Agent` 或既有确定性渠道适配；不得形成第二套最终回复 Agent。
6. **失败不推进状态。**迁移、摘要、画像抽取和游标处理失败时，不推进游标、不覆盖旧有效数据、不把错误 envelope 当正文。
7. **权限过滤后置兜底。**意图路由和工具预选不能扩大权限；最终仍必须经过现有管理员硬门禁和 Agent 工具过滤。
8. **历史最小化。**按策略注入有限上下文，设置条数、时间和字符三重预算，不固定暴露 24 小时全部聊天。
9. **测试数据隔离。**自动化测试不得写入当前真实微信群 SQLite、媒体目录、配置或 sidecar 登录态。
10. **可回滚。**行为能力使用独立开关；身份数据迁移使用离线备份、dry-run、幂等 apply 和恢复清单。
11. **被动学习与主动写入分离。**普通成员消息可以进入当前群 scoped 自动学习候选和受限进化；普通成员不能主动触发写入或获得通用文件/技能修改工具。由普通成员轮次产生的进化只能使用当前群记忆和画像专用服务。

## 3. 目标架构

```text
Wechaty sidecar
  -> WechatGroupMessage 安全解析
  -> stable account/room/member 解析
  -> inbound archive
  -> canonical room timeline（inbound + assistant）
  -> ContextPolicy 选择 current_only/recent/contextual/recall
  -> trigger / free-reply local gate
  -> free-reply judge（关系型近场消息、低温 JSON、真实超时）
  -> 高频意图路由（只映射既有能力）
  -> HumanizedContextBuilder
       -> 权限、mention、addressee、reply policy、persona
       -> archive / rolling summary / focus / recent timeline
       -> stable group memory / member profile / style / emotion
       -> reference / multimodal
  -> AgentHistoryMode（fresh / interactive_session / observe_only）
  -> 权限过滤后的意图相关工具集合
  -> AgentLLMModel（请求参数透传、熔断、错误分类）
  -> 回复清洗与真实发送
  -> assistant reply 写回 timeline
  -> 情绪、continuation capsule、指标与审计
```

### 3.1 Stable scope 契约

| 数据 | canonical key | runtime 允许用途 |
|---|---|---|
| 群配置/白名单 | `stable_account_id + stable_room_id` | 显示当前绑定快照 |
| 管理员/黑名单 | `stable_room_id + stable_member_id` | 真实 mention、发送和 legacy 审计 |
| 群永久记忆 | `stable_room_id` | 禁止用 runtime fallback 跨群查询 |
| 群友画像 | `stable_room_id + stable_member_id` | 保存来源 alias，不作为查询主键 |
| timeline/摘要/焦点/风格/情绪 | `stable_room_id` | 保存消息发生时 runtime room 快照 |
| Agent continuation | `stable_room_id + stable_member_id` | 不持久化 runtime session 主键 |

未确认、歧义或跨账号命中的 identity 必须保持 unresolved；不得按最近记录或同名任取。

### 3.2 Room timeline 事件契约

```text
source_type: inbound | assistant
source_row_id
stable_room_id
actor_type: member | assistant
actor_stable_member_id       # 仅服务端使用，不进入 prompt
actor_display_name
addressee_display_names[]
quote_actor_display_name
quote_excerpt
is_reply_to_assistant
is_directed_to_assistant
created_at
safe_text
message_type
```

prompt 只渲染安全显示名、关系和 `safe_text`；原始 message/runtime/stable ID、XML、媒体路径、base64、完整引用 payload 和内部数据库游标不得进入 prompt。服务端可用真实 ID 做精确路由，但渲染时必须换成 `current_image`、`quoted_image`、`recent_image_1` 等当轮临时标签。

### 3.3 上下文模式

| 模式 | 场景 | timeline | 摘要 | 焦点 | 归档 | Agent history |
|---|---|---:|---:|---:|---:|---|
| `current_only` | 完整、独立的直接问题 | 否 | 否 | 否 | 否 | 默认 `fresh` |
| `recent` | 省略句、短追问、普通自由接话 | 12 条 | 否 | 否 | 否 | free reply 为 `observe_only` |
| `contextual` | 引用、图片、继续、什么意思 | 20 条 | 是 | 相关焦点 | 否 | 明确追问才 `interactive_session` |
| `recall` | 总结、谁说过、历史约定、查证 | 20 条 | 是 | 是 | 是 | 仅回指机器人旧回答时恢复 |

### 3.4 Agent history 模式

- `fresh`：不恢复旧 Agent 消息，但继续加载系统 prompt、权限、工具和当前群上下文。
- `interactive_session`：只在同一 stable room/member 的明确继续、引用机器人或短时追问中恢复。
- `observe_only`：生成前隔离旧 Agent 历史；运行后保留审计和自主进化观察，但不参与后续回复恢复。

### 3.5 LLM 调用配置

| 调用类型 | 推荐温度 | 超时/失败行为 |
|---|---:|---|
| 最终群聊回复 | 0.5，允许配置 | 使用现有 fallback/熔断；失败不伪装成正常回复 |
| 自由回复 judge | 0.0 | 短超时；失败保守拒绝，不进入最终生成 |
| 画像抽取 | 0.0 | 失败不推进画像游标 |
| 滚动摘要 | 0.0 至 0.1 | 后台低优先级；失败保留旧摘要与游标 |
| 模糊意图分类 | 0.0 | 仅作为规则路由的可选补充；失败回主 Agent |

### Task 1.3：定义保守映射和合并规则

#### Room 级数据

- [ ] 只接受 confirmed active alias 或唯一历史 alias。
- [ ] 多个 runtime room 映射到同一 stable room 时合并数据，但保留来源 runtime 列表。
- [ ] 群记忆仅对完全相同的规范化内容和来源做去重；非完全相同内容全部保留。
- [ ] 多个学习游标合并时选择不会跳过未处理消息的保守游标；允许有限重放，不允许直接取最大值导致漏学。
- [ ] 历史 run/diff 保持审计顺序，不把失败 run 改写为成功。

#### Member 级数据

- [ ] runtime sender 在当前 stable room 内唯一映射到 stable member 时才自动迁移。
- [ ] 一个旧画像唯一对应一个 stable room/member 时，复制为 canonical stable 画像并保留 before/after 审计。
- [ ] 同一个旧 runtime profile 命中多个 stable room/member 时，不盲目克隆可能跨群混合的兴趣、别名和风格；标记 `ambiguous_cross_room_profile`，由房间内 archive 重新学习。
- [ ] 无 confirmed alias 时不按昵称猜测，不继承管理员、黑名单或敏感权限。
- [ ] canonical stable 画像已存在时使用字段级、证据级合并；新 stable 数据优先，legacy 数据不能覆盖更新时间更晚或置信度更高的字段。

## 18. 手工验收场景

### 场景 A：隐式承接

群内连续讨论一个部署问题，成员直接 @ 机器人说“那怎么办”。

预期：进入 `recent` 或 `contextual`，回答当前部署话题；不恢复更早的无关 Agent 对话。

### 场景 B：机器人上一句

机器人刚说“可能是缓存没刷新”，成员随后说“那重启就行？”。

预期：timeline 能看到 assistant reply，正确承接缓存和重启。

### 场景 C：两人互聊

A @ B 询问配置，B 引用 A 回答。

预期：judge 识别 addressee/quote，机器人不自由插话。

### 场景 D：问题已被回答

成员提出问题，judge 运行期间另一成员给出明确答案。

预期：旧候选 stale cancel，不发送迟到重复答案。

### 场景 E：模型慢但群未变化

judge 和 Agent 总耗时超过软阈值，期间无新消息。

预期：不能只因时间经过而取消。

### 场景 F：stable 记忆连续性

同一微信账号重登后，在目标群询问已保存约定和当前成员偏好。

预期：召回 stable 群记忆和当前群画像；不出现其他群别名或资料。

### 场景 G：跨群同名成员

两个群存在同名显示名，但 stable member 不同。

预期：画像、style、focus、summary 和 memory 完全隔离。

### 场景 H：结构化模型故障

judge 返回 fenced JSON；摘要返回 503 envelope；画像调用超时。

预期：judge 正确解析 fenced JSON；摘要/画像不保存错误正文、不推进游标；迟到结果被丢弃。

### 场景 I：滚动摘要与近场

群内累计大量讨论后要求总结。

预期：摘要承接较早结论，最近原文提供最新细节，同一消息不重复出现。

### 场景 J：observe-only

同一 session 先有 direct reply，再有 free reply，随后提出独立 direct 问题。

预期：free reply 不看到旧 direct history；下一轮 direct 不恢复 observe-only；审计和 scoped 进化仍有清洗后的观察轮次。普通成员观察只能影响当前群记忆/画像，不能修改技能、全局记忆或 workspace。

### 场景 K：高频意图

分别请求总结当前群、理解引用图片、生图和找表情包。

预期：命中唯一正确 action；无重复发送；无当前媒体时简短澄清，不误用旧群媒体。

### 场景 L：风格

管理员批准一条当前群 style，另一个群没有批准。

预期：只在当前群轻度影响措辞；关闭后立即回到 persona-only；不改变事实和权限。

### 场景 M：兼容回滚

layered 或 intent router 出现异常。

预期：切回 legacy、关闭 rolling/router/style 后直接 @ 仍正常；stable 数据不回退 runtime 主键，也不删除新数据。

## 19. 风险与控制

| 风险 | 控制 |
|---|---|
| legacy 画像跨群混合 | 多 stable member 映射不自动克隆，保留审计并按房间重学 |
| 迁移漏数据 | 保守游标、dry-run、备份、manifest、verify、幂等二次检查 |
| 迁移错误继承权限 | 歧义 identity 不迁移管理员/黑名单，权限始终要求 confirmed pair |
| adapter 修复改变其他渠道 | 请求级字段仅在非 None 时转发，运行跨渠道回归 |
| timeout 线程泄漏 | Provider timeout + 有界 executor + 丢弃迟到结果，不按请求无限建线程 |
| recent/summary 重复 | 双游标、近场尾巴和 source key 去重 |
| 摘要固化玩笑或旧事实 | 观点归属、不确定性、recent 优先、摘要不进永久记忆 |
| observe-only 污染缓存 Agent | session 锁、快照、`finally` 恢复、异常/取消测试 |
| router 扩大权限或误删管理员工具 | 角色门禁先过滤、route 再缩小、最终再次过滤；`pass_to_agent` 保留完整 `role_allowed_tools` |
| router 重复发送 | 路由器不直接执行回复；仅复用已有通用确定性路径的 completion 状态 |
| style 放大不良内容 | 默认人工审核，自动启用最后灰度，安全过滤和 room 上限 |
| 后台摘要争抢 Provider | 低优先级、用户 turn 让路、退避、可关闭 |
| 测试再次污染生产 DB | temp data dir 强制守卫和真实 DB mtime 非回归测试 |

## 20. 回滚方案

### 20.1 数据迁移回滚

1. 停止后端和 sidecar。
2. 根据 migration manifest 校验备份哈希。
3. 恢复所有 SQLite、配置和 scheduler 备份，不能只恢复其中一张表。
4. 运行 `--verify` 和最小稳定身份测试后再启动。
5. 不手工编辑 production SQLite 修补单行。

### 20.2 行为回滚

按以下顺序关闭：

1. `wechat_group_intent_router_enabled=false`
2. `wechat_group_style_auto_apply_enabled=false`，必要时禁用 active style
3. `wechat_group_rolling_summary_enabled=false`
4. `wechat_group_context_policy_mode=legacy`
5. 关闭 free reply，保留 @/引用必回

### 20.3 不允许的回滚

- 不把 stable 配置重新写成 runtime room/member。
- 不清空全部 Agent 会话或微信群数据库。
- 不删除 migration conflict 记录掩盖歧义。
- 不通过放宽管理员门禁恢复旧行为。

## 21. 完成标准

只有全部满足以下条件，本计划才能标记为完成：

1. stable scope dry-run、apply、verify、幂等和恢复演练全部通过。
2. 可唯一迁移的群记忆、画像和游标进入 canonical stable scope；歧义项保持隔离。
3. 真实 canary 的 memory/profile 注入不再为 0，且跨群泄露为 0。
4. `LLMRequest` temperature/timeout 在 primary 和 fallback 中真实生效。
5. judge、画像、摘要使用统一结构化协议；结构化调用至少 200 次，`invalid_json` 最多 1 次。
6. room timeline 同时包含 inbound 和成功发送的 assistant reply，并表达关系字段。
7. 四种 context mode 和三种 history mode 有确定性测试。
8. free reply 的两人互聊和迟到回复各至少 100 条样本，且各最多 1 条失败。
9. rolling summary 失败不推进游标，默认不与 recent 尾巴重复。
10. style 只在当前 stable room 的 active 状态下生效。
11. 首轮高频意图仅覆盖总结、当前/引用图片、生图和表情包；每类至少 100 条样本且路由准确率 >= 95%，无重复发送、无权限扩大、无管理员授权工具丢失。
12. 测试不再写入真实数据目录，污染清理有独立备份和审计。
13. 微信群最低回归、安全测试和全量 Python 测试全部通过。
14. 真实群完成场景 A 至 M 的 canary 验收，场景 K 不包含视频内容理解、通用图库或公共图片搜索。
15. `AGENTS.md`、`CHANGES.md`、本计划和上下文子计划全部按实际结果回写。
16. legacy 回滚至少演练一次，stable scope 不因行为回滚而退化。
