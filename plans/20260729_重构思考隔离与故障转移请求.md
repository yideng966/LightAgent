# 重构思考隔离与故障转移请求计划

> **状态：** 已完成
> **创建日期：** 2026-07-29
> **关联提交：** `44ed6819d2d7e8139ed4a5943a10cb563044b68c`、`446776503c682b2046829586ed7017a299a3d984`

## 1. 背景与结论

- `44ed6819` 为流式 `content` 增加了跨分片 `<think>` 解析，但实现与渠道输出策略耦合在 `AgentStreamExecutor` 内。
- `44677650` 增加了微信群无标签思考正则、请求级渠道判断和群消息延迟事件。
- 线上新样本证明无标签正则存在漏判；本地反例证明它也会截断正常技术回答，甚至产生空回复。
- 故障转移另有独立缺陷：候选模型共享可变的 `request.messages` / `request.tools`。主候选若原地改写请求后失败，备用候选会收到污染后的内容。该问题来自更早的基础实现，不是上述两个提交引入，但本次一并修复。
- 不直接执行两个完整提交的 `git revert`。完整回退会倒退 `AGENTS.md`、`CHANGES.md`、版本号和已发布的发行说明；本计划采用功能代码原子替换，保留发布历史。

## 2. 目标

- 每个模型候选都从路由前的规范化请求快照独立构造请求，候选之间不得共享可变请求对象。
- 备用模型接收与主模型语义等价的原始 Agent 请求，不接收主模型生成正文或主模型适配后的 Provider 请求体。
- 标准 `reasoning_content` 与最终 `content` 始终分离。
- 只按明确协议边界处理 `<think>` 等结构化思考，不再用自然语言正则猜测内部分析和最终答复。
- 微信群在完整响应确认前不发送正文事件；工具调用轮次的中间正文不得发送或作为最终答复持久化。
- 普通多段答复不得被截断；无法可靠区分思考与正文时，在请求源头禁用思考并约束只输出最终答复，不做语义截取。

## 3. 回退与重构范围

### 3.1 撤换旧实现

- 从 `agent/protocol/agent_stream.py` 删除 `_UNTAGGED_REASONING_START_RE`、`_UNTAGGED_REASONING_DECISION_RE` 和 `_strip_untagged_reasoning_preamble`。
- 撤换 `44ed6819` 引入的旧 `_ThinkTagStreamFilter` 及散落在取消、流结束路径中的重复净化逻辑，改为单一的结构化流响应规范化边界。
- 重写两次提交新增的思考过滤测试，保留行为目标，不保留对旧实现细节的断言。

### 3.2 候选请求隔离

- 在 `AgentLLMModel.call()` / `call_stream()` 进入候选循环前创建规范化请求快照。
- 每次调用候选时深拷贝 `messages`、`tools` 和请求级选项，由候选 Bot 自行转换成 Provider 请求格式。
- 保留“候选尚未输出任何分片时才允许故障转移”的约束，禁止拼接两个模型的流式正文。
- 增加主候选主动修改请求后返回 429、备用候选仍收到原始请求的回归测试。

### 3.3 思考与正文边界

- 将标准 `reasoning_content` 归一为思考事件和思考历史块，禁止进入最终正文。
- 将显式 `<think>...</think>` 作为协议标记进行有状态解析，覆盖标签跨 SSE 分片和未闭合场景。
- 微信群正文继续完整缓冲，最终只发送规范化后的 `content`。
- 微信群工具调用轮次只保留工具协议所需的 `tool_use` / `tool_result`；中间自然语言正文不发送，也不作为下一轮可见答复回放。
- 删除所有根据“用户要求我”“我应该”“让我”等自然语言句式截取段落的逻辑。

### 3.4 微信群候选策略

- 微信群请求不得依赖事后语义正则兜底。
- 主模型和所有已配置备用模型继续使用同一候选顺序，不新增“微信群兼容”显式信任字段，也不按 Provider 类型跳过候选。
- 每个候选都在请求源头禁用思考，并追加只输出最终答复、工具调用前不输出过程说明的系统约束；不向未知第三方 API 盲目增加其未声明支持的请求字段。
- 无标签 `content` 没有可验证的协议边界，仍按正文处理；通过请求约束和工具调用轮次隔离降低过程内容进入最终答复的风险，不用不可证明正确的自然语言规则误删正常答复。
- 该策略不改变原始用户消息、群上下文、历史和工具结果的组装规则。

## 4. 验证用例

- `<think>` 开闭标签及标签本身跨任意 SSE 分片。
- 未闭合 `<think>` 在微信群 fail closed，Web 按既有思考展示策略处理。
- `reasoning_content` 不进入群回复或最终正文。
- 主候选修改请求后返回 429，备用候选收到未修改的规范化请求快照。
- 主候选熔断打开时不调用主候选，首个已配置备用候选仍收到完整原始 Agent 请求。
- 主候选已输出任意正文分片后发生错误时不切换候选。
- 工具调用轮次的中间正文不发送到微信群，不污染下一轮最终答复。
- “用户请求中的上下文……我需要先区分……”等正常多段技术答复完整保留。
- 运行 Agent 流式、事件处理、模型故障转移、微信群持久化和群回复清理相关回归，最后运行全量 Python 测试。
