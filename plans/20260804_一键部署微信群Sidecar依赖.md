# 一键部署微信群 Sidecar 依赖实施计划

## 目标

完善 Linux/macOS `run.sh` 与 Windows `scripts/run.ps1` 的个人微信群源码部署流程：选择 `weixin` 渠道时检查 Node.js/npm，按锁文件安装 sidecar 生产依赖，并在依赖不可用时停止生成配置和启动服务。

## 实施步骤

- [x] 修正 `run.sh` 的 Node.js 安装权限、版本检查、npm 检查、锁文件安装和失败返回。
- [x] 修正 `scripts/run.ps1` 的版本/npm 检查、锁文件安装和失败返回。
- [x] 增加安装脚本静态回归测试，覆盖关键失败门槛和锁文件安装命令。
- [x] 同步 README、中文和英文手动安装文档。
- [x] 更新 `CHANGES.md`，执行脚本语法、定向测试、sidecar 测试和差异检查。

## 边界

- 不修改微信群 sidecar 协议、运行逻辑或 npm 依赖版本。
- 不在 Windows 脚本中静默安装系统级 Node.js；缺失或版本不符时明确失败并要求安装 LTS 后重试。
- Docker 镜像继续使用现有内置 Node.js 和 `npm ci` 流程。

## 进度与结果

当前状态：已完成。

实际改动：

- 选择 `weixin` 时，两端脚本均要求 Node.js 18+、npm、`package.json` 和 `package-lock.json`，使用 `npm ci --omit=dev`，并验证五个 sidecar 运行时依赖。
- Linux/macOS 的 Node.js 安装支持 root、sudo、apt、yum 和 Homebrew；Windows 缺少 Node.js 或 npm 时明确失败，不再继续生成配置。
- 安装失败或模块验证失败时，两端均在写入配置和启动服务前停止。

验证结果：

- 安装器合同测试、Docker 部署合同测试：11 项通过。
- PowerShell UTF-8 解析、Git Bash 语法检查、配置模板 JSON 解析、`git diff --check`：通过。
- `npm ci --omit=dev --dry-run`、五个核心模块导入和 sidecar Node 测试：锁文件验证通过，61 项测试通过。
- 本机实际 `npm ci` 曾因现有 Node 进程占用 `leveldown` 原生文件返回 Windows `EPERM`；未终止用户进程，使用 `npm install --omit=dev` 修复了本地生成依赖目录。

剩余事项：

- 未在缺少 Node.js、低版本 Node.js 或 npm 网络失败的真实交互安装环境中运行完整一键流程；这些分支由脚本合同测试和静态语法检查覆盖。
