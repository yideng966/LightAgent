# 微信群“闭嘴”禁言自由回复开发计划

## 1. 任务背景

个人微信群中，普通群消息可按自由回复规则进入本地评分和大模型二次判定。需要增加一个群内即时静默命令：任何群成员精确 `@` 机器人并发送“闭嘴”后，暂停当前群的普通自由回复一段时间；暂停时长可在 Web 控制台配置，默认 10 分钟。

## 2. 行为边界

- 仅处理文本消息，且必须由微信侧确认本轮真实 `@` 机器人。
- 去除机器人 `@` 前缀后，文本必须精确等于“闭嘴”；“请闭嘴”“闭嘴一下”等不触发。
- 命令由通道层静默消费，不进入 Agent、LLM 或自由回复 worker。
- 禁言仅作用于当前 `stable_room_id`；稳定身份不可用时才回退当前 runtime room ID，不影响其他群。
- 禁言默认只暂停普通非 `@` 自由回复；开启 `wechat_group_free_reply_mute_mentions_enabled` 后，禁言有效期内的新 `@` 消息也静默忽略，引用机器人回复和拍一拍仍不受影响。
- 命令对所有群成员开放，不提升任何管理员权限，也不修改持久化权限配置。
- 命令触发前已排队的自由回复候选，在最终发送前必须再次检查禁言状态并丢弃。
- 禁言状态为进程内运行时状态，通道重启后清空；配置时长持久化到现有配置文件。
- 配置键使用 `wechat_group_free_reply_mute_minutes`，默认 10，服务端与 UI 均限制为 1–1440 分钟。
- `wechat_group_free_reply_mute_mentions_enabled` 默认为 `false`，保持旧行为兼容；命令识别必须先于 @ 禁言门禁执行，确保重复发送“闭嘴”仍可续期。
