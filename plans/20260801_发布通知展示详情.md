# GitHub 发布通知展示详情

## 目标

GitHub `release` Webhook 通知除现有仓库、动作、操作者、标题和链接外，追加 Release 正文，使微信群可以直接看到版本摘要与变更详情。

## 实施步骤

- [x] 核对现有 Webhook 格式化链路与 GitHub Release 字段契约。
- [x] 仅对白名单中的 `release.body` 做多行文本清理并追加到通知。
- [x] 保持现有消息长度上限，避免影响其他事件的正文安全边界。
- [x] 补充格式化与入队回归测试。
- [x] 同步用户文档与 `CHANGES.md`，完成最小验证。

## 风险与边界

- Issue、PR、讨论、评论等事件仍不转发正文。
- Release 正文只来自已验签且仓库名称匹配的 Webhook payload。
- 通知总长度继续受 `wechat_group_response_cleanup_max_chars` 限制。

## 实施结果

- Release 通知会追加纯文本发行摘要，跳过匹配当前仓库名的项目定位引用，并在 Markdown 分隔线处停止。
- Markdown 标题与无序列表标记会被移除，正文换行保留；安装命令和文档章节不会进入群消息。
- 非字符串正文被忽略，消息继续受 200-4000 字符范围限制；其他事件正文策略不变。
- `python -X utf8 -m unittest tests.test_github_webhook_events tests.test_github_commit_webhook tests.test_scheduler_wechat_group_delivery`：43 项通过。
- Python 编译检查与 `git diff --check` 通过。
