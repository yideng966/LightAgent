# 微信群自由回复图片识别失败静默开发计划

## 任务目标

微信群处于自由回复模式时，如果当前回复依赖图片识别，但视觉模型没有返回可用的图片摘要，则静默结束本次自由回复，不再进入 Agent、聊天模型或发送链路。

## 已确认的代码现状

1. `WechatGroupChannel.handle_text()` 对非明确触发的图片消息先检查 `wechat_group_free_reply_image_understanding_enabled`，随后只把脱敏占位文本 `[image]` 交给自由回复本地规则、Worker 和 LLM Judge；此阶段不会提前调用视觉模型。
2. Worker 批准后进入 `WechatGroupChannel._submit_free_reply_after_judge()`。图片消息会被转换为文本问题 `请根据这张图片作出简短回应。`，并通过 `_compose_context()` 进入统一多模态上下文构建。
3. `WechatGroupMultimodalContextService._get_image_summary()` 在 `Vision().execute()` 异常、返回失败状态或成功但正文为空时，分别产生“图片理解失败”或“图片理解未返回内容”的摘要，不会抛出到渠道层。
4. 多模态服务已经通过 `wechat_group_multimodal_diagnostics.summary_generated` 表示是否取得可用摘要，并通过 `matched_image_message_id` 表示本次确实选中了图片。该诊断会由 `WechatGroupHumanizedContextBuilder` 写入 Context。
5. 当前 `_submit_free_reply_after_judge()` 不检查上述诊断。只要 Context 构造成功，就会设置自由回复标记、调用 `free_reply_state.mark_triggered()`，最后执行 `produce(context)`。
6. 因此，识图失败摘要会继续连同通用图片问题交给 Agent。Agent 可能生成“无法识别图片”等兜底文本并发送到群内，同时本次失败还会占用自由回复冷却和连续回复计数。

当前链路如下：

```text
非 @ 图片/自由回复图片追问
  -> 本地规则与 Worker/Judge 批准
  -> _compose_context()
  -> Vision.execute()
  -> 失败摘要 + summary_generated=False
  -> mark_triggered()
  -> produce(context)
  -> Agent/模型生成兜底回复
  -> 群内发送
```

## 需求边界

- 仅约束 `wechat_group_is_free_reply=True` 的自由回复链路。
- 覆盖两类场景：非 @ 图片消息的自由回复，以及自由回复文本追问命中最近图片后发生的识别失败。
- 视觉调用异常、工具失败状态、空正文、当前图片缺少可用媒体路径，均按“没有可用图片摘要”处理。
- 明确 `@`、引用机器人、拍一拍等显式交互保持当前行为，不在本次改动中静默。
- 普通纯文本自由回复没有选中图片时保持现状，不因诊断中的默认 `summary_generated=False` 被误抑制。
- 图片引用歧义属于“未唯一选中图片”，不是视觉模型识别失败，本次不改变其现有提示逻辑。
- 不新增配置项，不修改 Web 控制台，不修改视觉 Provider、图片摘要缓存或 sidecar 媒体下载协议。

## 开发方案

### 1. 增加自由回复图片失败判定

在 `channel/wechat_group/wechat_group_channel.py` 增加一个小型判定函数，复用现有 `wechat_group_multimodal_diagnostics`：

- 当前消息本身是自由回复图片时，只有命中原图 `reason=current_image` 且 `summary_generated is True` 才允许继续；诊断缺失、构建异常、未找到媒体、误回退到历史图片或摘要不可用均按失败关闭。
- 自由回复文本追问最近图片时，仅在匹配图片列表非空且 `summary_generated is not True` 时抑制；该条件兼容没有 `message_id` 的历史归档图片。
- 没有选中图片的普通文本自由回复返回 `False`，继续原链路。

无需修改 `WechatGroupMultimodalContextService` 的返回协议；现有诊断字段已经能区分成功、失败和未尝试三类情况。

### 2. 在 Agent 入队和冷却记录前静默短路

在 `_submit_free_reply_after_judge()` 完成 `_compose_context()` 后、写入自由回复触发标记前执行判定。命中失败时：

- 不调用 `produce(context)`，因此不进入 Agent、聊天模型、插件回复和发送链路。
- 不调用 `free_reply_state.mark_triggered()`，避免失败请求占用冷却、小时额度和连续回复计数。
- 不发送“识别失败”“请重试”等用户可见文本。
- 将最后一次自由回复决策更新为 `triggered=False`，追加内部抑制原因 `image_understanding_failed`，并记录一条不含本地媒体路径的结构化日志，便于排障。

该门禁只存在于自由回复提交函数中，因此显式交互链路天然不受影响。

### 3. 补充回归测试

在 `tests/test_wechat_group_channel.py` 增加以下测试：

- 非 @ 图片经 Worker/Judge 批准后，`Vision.execute()` 抛异常：不调用 `produce()`，不调用 `mark_triggered()`，最后决策包含 `image_understanding_failed`。
- 非 @ 图片视觉工具返回失败状态：同样静默。
- 非 @ 图片视觉工具成功但摘要为空：同样静默。
- 自由回复文本追问命中最近图片且识别失败：静默，不进入 Agent。
- 自由回复图片识别成功：保持现有 `produce()`、上下文注入和不 mention 行为。
- 普通纯文本自由回复未选中图片：保持正常回复。
- 明确 @ 图片识别失败：保持当前显式交互行为，防止把静默范围扩大到用户明确请求。

现有 `tests/test_wechat_group_multimodal_context_service.py` 继续验证失败摘要脱敏和 `summary_generated=False`，无需改变服务层兼容行为。

## 实际改动

- 在 `WechatGroupChannel._submit_free_reply_after_judge()` 完成 Context 构造后增加自由回复识图结果门禁。
- 当前图片自由回复要求 `reason=current_image` 且 `summary_generated=True`，避免媒体缺失时误用历史图片；文本自由回复只有实际匹配到图片且摘要不可用时才静默，普通文本不会误判。
- 静默时不进入 `produce()`，不调用 `mark_triggered()`，最后一次自由回复决策记录 `image_understanding_failed`，日志不包含媒体路径。
- 多模态服务协议、图片缓存、Web 配置和显式图片回复链路均未修改。

## 风险与回退

- 风险较低，改动只位于微信群自由回复批准后的单一提交点，不触达跨渠道公共逻辑。
- 最大风险是把“未使用图片的普通文本自由回复”误判为失败；通过“当前消息为图片”或“确实存在匹配图片列表”双条件隔离。
- 回退时删除该提交点的静默判定即可恢复现状，不涉及配置迁移或持久化数据变更。
