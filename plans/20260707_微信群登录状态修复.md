# 微信群登录状态修复开发计划

> 状态：已完成  
> 目标：只修复个人微信群通道登录态判断，避免 sidecar 进程启动后、微信扫码登录完成前，Web 通道管理页面误显示“已接入”。  
> 范围：仅修改微信群登录状态链路，不修改消息处理、Agent 主链路、群记忆、图片能力、配置项或 sidecar JSON Lines 协议。

## 现有登录链路复盘

当前登录链路如下：

1. Web 控制台选择“个人微信群”后，前端调用 `POST /api/channels`，参数为 `action=connect`、`channel=wechat_group`。
2. `ChannelsHandler._handle_connect()` 将 `wechat_group` 写入 `channel_type`，并启动后台线程调用 `ChannelManager.start(["wechat_group"])`。
3. `ChannelManager.start()` 创建 `WechatGroupChannel` 实例，并在线程中执行 `WechatGroupChannel.startup()`。
4. 当前 `startup()` 只要执行 `self.client.start()` 拉起 Node.js sidecar，就立即调用 `report_startup_success()`。
5. `WechatGroupClient.start()` 通过 `subprocess.Popen()` 启动 `wechaty-sidecar.mjs`，再由 stdout 读取线程把 sidecar JSON Lines 事件转给 `WechatGroupChannel.consume_sidecar_event()`。
6. 当前 sidecar 事件处理已有状态常量 `idle`、`starting`、`qr_ready`、`logged_in`、`connected`、`error`，但状态推进不完整：`qr` 会设置 `qr_ready`，`status` 会覆盖状态，`rooms` 只更新群列表，不会明确推进到 `connected`。
7. `WechatGroupQrHandler.GET()` 当前直接读取运行实例的 `status`，返回二维码和群列表。
8. `ChannelsHandler.GET()` 当前通道列表的 `active` 主要来自配置里的 `channel_type`，即只要配置已包含 `wechat_group`，页面就容易显示为已接入。

核心问题：

- `channel_type` 表示“配置启用”，不等于“微信已登录”。
- `report_startup_success()` 表示 sidecar 进程启动成功，不等于“扫码登录成功”。
- Web 通道管理页把配置启用和真实登录态混用，导致扫码前误显示“已接入”。

## 修复目标

- 保留现有接入入口和 sidecar 协议。
- 明确区分 sidecar 进程状态与微信登录状态。
- 通道管理列表中：
  - `configured` 表示配置已包含 `wechat_group`。
  - `active` 只在微信已登录后为 `true`。
- QR 登录接口能返回当前登录态、二维码、二维码图片、群列表和错误信息。
- 登录前错误进入 `error`；登录后非致命 sidecar 错误不把通道降级为未接入。

## 状态语义

| 状态 | 含义 | Web 是否显示已接入 |
| --- | --- | --- |
| `idle` | 通道未运行或已停止 | 否 |
| `starting` | Python 通道已开始启动 sidecar，尚未拿到二维码或登录态 | 否 |
| `qr_ready` | sidecar 已返回二维码，等待扫码 | 否 |
| `logged_in` | 微信扫码登录完成，群列表可能尚未刷新 | 是 |
| `connected` | 已登录且已收到群列表 | 是 |
| `error` | 启动或登录阶段发生致命错误 | 否 |

## 文件修改计划

### 1. `channel/wechat_group/wechat_group_client.py`

职责：让真实 sidecar client 能暴露启动失败或进程退出错误，供 channel 登录态查询使用。

计划修改：

- 在 `WechatGroupClient.__init__()` 增加 `_last_error`：

```python
self._last_error = ""
```

- 在 `start()` 每次启动前清空旧错误，避免历史错误污染本轮登录：

```python
self._last_error = ""
```

- 在 `start()` 捕获 `subprocess.Popen()` 异常，记录 `_last_error` 后继续抛出：

```python
try:
    self.process = subprocess.Popen(...)
except Exception as e:
    self._last_error = str(e)
    raise
```

- 新增 `poll_error()`：

```python
def poll_error(self) -> str:
    if self._last_error:
        return self._last_error
    if self.process and self.process.poll() is not None:
        return "wechat group sidecar exited with code {}".format(self.process.returncode)
    return ""
```

### 2. `channel/wechat_group/wechat_group_channel.py`

职责：维护个人微信群通道的登录状态机。

计划修改：

- 在 `__init__()` 增加：

```python
self.last_error = ""
```

- 新增 `get_login_status()`：

```python
def get_login_status(self) -> str:
    error = self.client.poll_error() if hasattr(self.client, "poll_error") else ""
    if error and self.status not in (self.STATUS_IDLE, self.STATUS_LOGGED_IN, self.STATUS_CONNECTED):
        self.status = self.STATUS_ERROR
        self.last_error = error
        self.report_startup_error(error)
    return self.status
```

- 调整 `startup()`：

```python
def startup(self):
    self.status = self.STATUS_STARTING
    self.last_error = ""
    try:
        self.client.start()
    except Exception as e:
        self.status = self.STATUS_ERROR
        self.last_error = str(e)
        self.report_startup_error(self.last_error)
        return

    error = self.client.poll_error() if hasattr(self.client, "poll_error") else ""
    if error:
        self.status = self.STATUS_ERROR
        self.last_error = error
        self.report_startup_error(error)
        return

    self.report_startup_success()
```

- 调整 `consume_sidecar_event()` 状态推进：
  - `QR`：`status = qr_ready`，保存 `qr_code`。
  - `STATUS`：使用 sidecar 返回的状态；当状态为 `logged_in` 或 `connected` 时清空 `last_error`。
  - `ROOMS`：更新 `rooms`；如果当前为 `starting`、`qr_ready`、`logged_in` 或 `error`，推进到 `connected` 并清空 `last_error`。
  - `ERROR`：如果尚未 `logged_in/connected` 且没有群列表，设置 `status = error`、写入 `last_error` 并调用 `report_startup_error()`；如果已经登录或已有群列表，只记录 warning，不降级通道状态。

### 3. `channel/web/web_channel.py`

职责：让 Web 通道管理接口使用真实登录态，而不是只看 `channel_type`。

计划修改：

- `_get_channel_status(channel_name)` 优先调用运行实例的 `get_login_status()`：

```python
status_getter = getattr(ch, "get_login_status", None) if ch else None
if callable(status_getter):
    status = status_getter()
    if isinstance(status, str):
        return status
```

- 新增 `ChannelsHandler._get_wechat_group_status_info()`：

```python
@classmethod
def _get_wechat_group_status_info(cls) -> dict:
    running_ch = cls._get_running_wechat_group_channel()
    if not running_ch:
        return {
            "configured": "wechat_group" in cls._active_channel_set(),
            "login_status": "idle",
            "runtime_active": False,
            "connected": False,
            "message": "",
        }

    status_getter = getattr(running_ch, "get_login_status", None)
    if callable(status_getter):
        login_status = status_getter()
        if not isinstance(login_status, str):
            login_status = getattr(running_ch, "status", "unknown")
    else:
        login_status = getattr(running_ch, "status", "unknown")

    message = getattr(running_ch, "last_error", "") or ""
    if not isinstance(message, str):
        message = str(message)

    return {
        "configured": "wechat_group" in cls._active_channel_set(),
        "login_status": login_status,
        "runtime_active": True,
        "connected": login_status in ("logged_in", "connected"),
        "message": message,
    }
```

- 在 `ChannelsHandler.GET()` 组装 `wechat_group` 卡片时：
  - 默认 `active` 仍可按普通通道逻辑初始化。
  - 对 `wechat_group` 覆盖为 `active = status_info["connected"]`。
  - 合并 `configured`、`login_status`、`runtime_active`、`connected`、`message`。
  - 保留现有 `extra = _wechat_group_extra()`。

- 在 `WechatGroupQrHandler.GET()` 中：
  - 优先调用 `running_ch.get_login_status()`。
  - 返回 `message = running_ch.last_error`。
  - 继续返回 `rooms`、`extra`、`qrcode_url`、`qr_image`。

## 风险与回退

- 风险：`active` 从“配置启用”改为“真实登录成功”后，扫码前通道不会出现在已接入列表；这是本次修复的目标行为。
- 风险：登录后 sidecar 的非致命错误不会降级通道；通过日志和 `last_error` 保留排查信息。
- 回退：仅恢复 `channel/wechat_group/wechat_group_client.py`、`channel/wechat_group/wechat_group_channel.py`、`channel/web/web_channel.py` 和对应测试改动，不涉及配置迁移或数据迁移。
