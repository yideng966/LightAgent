# 微信群入群欢迎与离群通知开发计划

**状态：** 开发完成，待真实微信链路验收

**创建日期：** 2026-07-28

**任务类型：** 个人微信群成员事件接入与 Web 配置功能

## 1. 任务背景

当前仓库实际安装的 `wechaty 1.20.2` 与 `wechaty-puppet-wechat4u 1.14.14` 已提供 `room-join` 和 `room-leave` 事件，但 LightAgent sidecar 只监听 `scan`、`login`、`logout`、`message` 和 `error`，JSON Lines 协议与 Python 通道也没有成员进出群事件。因此底层能够识别部分入群和被移出通知，当前 LightAgent 却不会收到、配置或响应该事件。

本次目标是在不引入独立机器人链路、不调用 LLM/Agent、不扩大群权限边界的前提下，将 `room-join` 与 `room-leave` 接入现有 sidecar -> JSON Lines -> Python 微信群通道链路，并在 Web 控制台增加统一的“进退群消息”配置：

- 入群欢迎、离群通知分别启停和编辑。
- 两类消息都支持全局默认与按稳定群覆盖。
- 每类消息均支持文本或本地图片二选一。
- 文本模式可通过白名单占位符引用事件中实际可获得的可读信息。

## 2. Wechaty 事件能力分析

### 2.1 两类事件的公共信息

两类事件都可以直接或通过现有 sidecar helper 获得：

| 信息 | 来源 | 计划中的用途 |
|------|------|--------------|
| runtime 群 ID | `room.id` | 向原群发送消息、解析稳定群 |
| 群名称 | `await room.topic()` | 日志、模板变量、稳定群解析 |
| 涉及成员列表 | `Contact[]` | 获取 runtime ID、显示名、群昵称和微信号候选 |
| 操作者 | `inviter` / `remover` | 模板变量和诊断日志 |
| 事件时间 | `date?: Date` | 模板变量、去重键与时效判断 |
| 当前登录账号 | `state.self` | 识别机器人自己进出群，补充稳定账号/群指纹 |

这些信息仍是 Wechaty runtime 数据，不包含 LightAgent 的 `stable_account_id`、`stable_room_id` 或 `stable_member_id`。长期配置和群作用域必须在 Python 层复用 `WechatGroupIdentityService` 补齐。

### 2.2 `room-join` 能提供的信息

Wechaty 公共回调签名：

```javascript
bot.on('room-join', (room, inviteeList, inviter, date) => {})
```

底层 puppet 原始 payload：

```text
roomId
inviteeIdList
inviterId
timestamp
```

Wechaty 会先按这些 ID 查找 `Room` / `Contact`，同步群成员，再组装公共事件对象。现有 `buildRoomMemberPayload()` 可以继续复用，用于提取 `sender_id`、`sender_nickname`、`room_alias` 和 `wechat_id`。

当前 wechat4u 仅从微信群 `SYS` 系统消息中按中文/英文文本规则识别以下场景：

1. 当前账号邀请其他成员入群。
2. 其他成员邀请当前账号入群。
3. 其他成员邀请另一成员，或同时邀请当前账号和另一成员入群。
4. 成员扫描当前账号或其他成员分享的二维码入群。

高层事件会统一给出 `inviter`，但不会保留“邀请入群”还是“扫码入群”的可靠来源枚举。因此不得提供 `{join_method}` 占位符，也不在 UI 中展示无法稳定获得的加入方式。

### 2.3 `room-leave` 能提供的信息

Wechaty 公共回调签名：

```javascript
bot.on('room-leave', (room, leaverList, remover, date) => {})
```

底层 puppet 原始 payload：

```text
roomId
removeeIdList
removerId
timestamp
```

公共事件理论上可以提供离群成员列表、移除操作者和事件时间，但当前 `wechaty-puppet-wechat4u 1.14.14` 的解析范围明显窄于接口能力，仅覆盖：

1. 当前登录账号将某成员移出群聊。
2. 当前登录账号被另一成员移出群聊。

当前版本不能承诺识别：

- 其他成员主动退出群聊。
- 其他管理员将另一成员移出，而机器人仍留在群内。
- 微信未向当前账号下发、或文案不匹配现有正则的其他离群场景。

当当前登录账号自己被移出群聊时，LightAgent 可以识别事件并刷新群列表，但账号已经不在原群，不能再向原群发送离群通知。以当前 puppet 能力，能够实际触发离群通知发送的可靠场景主要是“当前登录账号移除了其他成员”。

### 2.4 无法稳定获得或需要补齐的信息

- 两类事件都没有原始微信系统消息 ID，也没有可直接使用的全局唯一事件 ID。
- 没有 LightAgent stable ID，必须由 Python 通道补齐。
- 没有可靠的入群方式或离群原因，不支持相关占位符。
- 不是历史同步接口：sidecar 离线期间发生的入群或离群不会在重启后补发。
- 解析依赖微信系统通知文案和 `roomMemberSearch()`。文案变化、操作者查找失败会导致事件缺失或转为 Wechaty `error`；无法解析的成员会从高层列表中过滤。
- `inviteeList` / `leaverList` 接口允许多成员，但当前 wechat4u 文案解析通常只能可靠解析一个或少量成员，不能承诺一次系统通知中的所有名字始终完整。
- 离群事件发生后，成员已经不在群成员列表，群昵称可能无法再次读取；应优先使用事件中已解析的 Contact 名称和既有身份别名，缺失时使用通用称呼，不回显 runtime ID。

本次不修改 `node_modules`、不复制依赖包正则作为旁路解析器，也不承诺离线补偿或完整主动退群识别。真实邀请、扫码、当前账号移除成员和当前账号被移出必须列入人工验收。

## 3. 目标行为与验收标准

### 3.1 事件接入

- sidecar 监听公共 `room-join` 与 `room-leave`，分别上报 `room_join`、`room_leave` JSON Lines 事件。
- payload 至少包含 runtime 群信息、当前账号信息、操作者、成员数组和秒级时间戳；不得伪造 stable ID。
- Python 通道使用现有稳定身份服务解析当前账号、群和成员。
- 机器人自己加入群时只刷新群列表与身份快照，不欢迎自己。
- 机器人自己被移出群时刷新群列表和运行态，不尝试向已退出的原群发送消息。
- 同一事件只触发一次；同一事件包含多名成员时合并成一条消息，避免刷屏。
- 两类事件均不创建 `Context`，不进入 `Bridge`、Agent、插件、技能、记忆学习、自由回复或 LLM 链路。

### 3.2 作用域与优先级

- “全局”仅表示所有已选择且稳定身份已确认的 `wechat_group_stable_room_ids`，不表示当前微信账号加入的所有群。
- 入群与离群分别维护全局默认和按群覆盖，互不影响。
- 按群配置只接受当前已选择的 `wgr_*` 稳定群 ID；runtime room ID、群名和未确认群不得持久化为覆盖项。
- 每类事件在每个群的策略均为：`跟随全局`、`自定义`、`关闭`。
- 两类事件分别按以下顺序解析：

```text
按群关闭 -> 不发送
按群自定义 -> 使用该群内容
无覆盖/跟随全局 -> 使用该事件类型的全局开关与内容
全局关闭且无按群自定义 -> 不发送
```

- 稳定账号或稳定群未确认、目标群未选中、payload 缺少 runtime 群 ID、成员列表为空时均 fail closed。
- 成员 stable ID 解析失败不扩大权限；只要稳定群已确认且成员 runtime ID 有效，可继续使用最佳可读名称发送通用文本，日志标记成员身份未确认。

### 3.3 文本模板与占位符

入群和离群文本均由管理员自由编辑，并在 UI 中通过“插入变量”菜单插入事件占位符。占位符只暴露适合发送到群里的可读信息；runtime/stable ID、微信号、指纹和原始系统消息不作为模板变量。

通用占位符：

| 占位符 | 值 | 缺失时行为 |
|--------|----|------------|
| `{room_name}` | 当前群名称 | 使用“当前群” |
| `{member_name}` | 成员列表第一人的最佳可读名称 | 入群使用“新成员”，离群使用“群成员” |
| `{member_names}` | 全部成员可读名称，以 `、` 连接 | 同上，不回显原始 ID |
| `{member_count}` | 当前事件解析到的成员数量 | 至少为 `1` 才允许发送 |
| `{event_time}` | 事件时间，按服务端本地时区格式化为 `YYYY-MM-DD HH:mm:ss` | 使用消费事件时的当前时间 |
| `{bot_name}` | 当前登录微信账号显示名 | 使用“机器人” |

入群专用占位符：

| 占位符 | 值 | 缺失时行为 |
|--------|----|------------|
| `{inviter_name}` | 邀请人最佳可读名称 | 使用“群成员” |

离群专用占位符：

| 占位符 | 值 | 缺失时行为 |
|--------|----|------------|
| `{remover_name}` | 移除操作者最佳可读名称 | 使用“群管理员” |

模板规则：

- 入群默认文本建议为 `欢迎加入群聊！`；发送时把全部 invitee runtime ID 作为 `mention_ids`，由现有 sidecar 在正文前生成真实 mention 和可见兜底。
- 入群模板仍可使用 `{member_name}` / `{member_names}`。真实 mention 与模板正文彼此独立，UI 预览必须表现最终会出现的 mention 前缀，避免管理员误判重复姓名。
- 离群默认文本建议为 `{member_names} 已离开群聊。`。
- 离群成员已经不在群内，离群文本不得把 leaver runtime ID 作为 `mention_ids`，只渲染可读名称。
- `{inviter_name}` 只允许用于入群模板，`{remover_name}` 只允许用于离群模板；跨类型使用在保存时返回明确错误。
- 变量只做逐项文本替换，不使用 `eval`、表达式、属性访问、循环或任意 `str.format()`；未知变量在保存时返回明确错误。
- 文本去除首尾空白并限制长度，建议最大 500 个字符；启用文本模式时内容不能为空。
- 同一原始事件只渲染一次。多人事件由 `{member_names}` / `{member_count}` 表达，不循环逐人发送。

### 3.4 图片消息

- 入群和离群均可选择图片模式；图片模式只发送图片，不隐式补发文本或 mention，符合“文本或者图片”二选一。
- 图片使用现有 `WechatGroupClient.send_image()` 和 sidecar `FileBox.fromFile()` 投递。
- 两类图片共享持久化目录：

```text
agent_workspace/images/wechat_group_membership/
```

- 配置只保存相对路径，例如 `images/wechat_group_membership/<sha256>.png`，不保存 Web 临时上传目录、绝对路径或外部 URL。
- 新增专用且需要 Web 登录鉴权的上传/预览接口；不直接复用把文件写入 `agent_workspace/tmp` 的通用 `/upload`。
- 首版允许 `JPEG`、`PNG`、`GIF`、`WEBP`，建议最大 5 MiB；同时校验扩展名、Pillow 实际解码格式、非空内容和尺寸，不允许 SVG。
- 文件使用 SHA-256 内容摘要命名，避免用户文件名路径穿越和重复存储；预览接口必须用 `realpath/commonpath` 限制在成员消息图片目录内。
- 配置启用时图片缺失、越界或格式失效则不发送且记录可读错误，不回退到其他范围或文本，避免发送用户未配置的内容。
- 首版不自动删除可能仍被全局、入群、离群或其他群引用的旧图片，避免误删；孤儿文件清理不属于本次范围。

## 4. 配置模型

为兼容现有 `config.json` 写入器的递归字典合并行为，入群和离群的按群覆盖都使用“对象列表”，避免清空字典时旧覆盖残留。新增配置建议如下：

```json
{
  "wechat_group_join_welcome_enabled": false,
  "wechat_group_join_welcome_content_type": "text",
  "wechat_group_join_welcome_text": "欢迎加入群聊！",
  "wechat_group_join_welcome_image_path": "",
  "wechat_group_join_welcome_room_overrides": [
    {
      "stable_room_id": "wgr_example_a",
      "policy": "custom",
      "content_type": "text",
      "text": "欢迎加入 {room_name}！",
      "image_path": ""
    }
  ],
  "wechat_group_leave_notice_enabled": false,
  "wechat_group_leave_notice_content_type": "text",
  "wechat_group_leave_notice_text": "{member_names} 已离开群聊。",
  "wechat_group_leave_notice_image_path": "",
  "wechat_group_leave_notice_room_overrides": [
    {
      "stable_room_id": "wgr_example_b",
      "policy": "disabled",
      "content_type": "text",
      "text": "",
      "image_path": ""
    }
  ]
}
```

归一化规则：

- 两类 `content_type` 只接受 `text` / `image`，非法值回退 `text`。
- 两类 `policy` 只持久化 `custom` / `disabled`；“跟随全局”通过删除该群对应覆盖表达。
- 覆盖项只接受当前选择集合中的 `wgr_*`，按 stable room ID 去重。
- Web 同一次请求同时更新目标群和两类覆盖时，服务端先归一化请求中的 `wechat_group_stable_room_ids`，再用该结果校验覆盖项，不能依赖集合遍历顺序或旧配置。
- 运行时与 Web 保存必须复用同一组配置归一化、事件类型占位符校验和图片路径校验函数。
- 两类总开关默认关闭，旧配置无须迁移，升级后不会自动向任何群发送消息。

## 5. 运行链路设计

### 5.1 入群链路

```text
微信 SYS 入群通知
  -> wechaty-puppet-wechat4u 解析 room-join
  -> Wechaty room-join(room, inviteeList, inviter, date)
  -> sidecar 规范化成员/邀请人并 emit("room_join")
  -> WechatGroupChannel 消费、去重并过滤 self invitee
  -> stable account/room/member 解析与 selected-room 门禁
  -> 解析入群按群覆盖/全局默认
  -> 安全替换入群占位符或校验图片路径
  -> send_text(..., mention_ids=invitee_ids) 或 send_image(...)
```

### 5.2 离群链路

```text
微信 SYS 移出通知
  -> wechaty-puppet-wechat4u 解析 room-leave
  -> Wechaty room-leave(room, leaverList, remover, date)
  -> sidecar 规范化成员/移除人并 emit("room_leave")
  -> WechatGroupChannel 消费并去重
  -> 若 leaver 包含 self：刷新群列表后结束
  -> stable account/room/member 最佳努力解析与 selected-room 门禁
  -> 解析离群按群覆盖/全局默认
  -> 安全替换离群占位符或校验图片路径
  -> send_text(..., mention_ids=[]) 或 send_image(...)
```

### 5.3 实现约束

- sidecar 的两类 payload 组装提取到 `wechaty-sidecar-core.mjs` 的可测试 helper，入口文件只负责注册事件和 emit。
- sidecar 在 join invitee 或 leave leaver 包含当前登录账号时刷新 `rooms`，使群列表和稳定身份快照反映当前登录态。
- 不因 self leave 自动删除 `wechat_group_stable_room_ids` 或按群配置，避免一次事件不可逆修改管理员长期配置；UI 刷新后显示该群当前不可用。
- Python 派生去重键包含事件类型、runtime 群 ID、排序后的成员 runtime IDs、操作者 runtime ID和 timestamp，维护有容量和 TTL 上限的内存缓存。上游没有消息 ID且不会补发历史事件，本次不为去重新增数据库。
- 两类消息都调用非阻塞的 `send_text()` / `send_image()`。不能在 sidecar stdout 读取线程中调用 `send_*_confirmed()`，否则等待 `send_result` 时会阻塞负责消费该结果的同一线程。
- `_consume_room_join()` / `_consume_room_leave()` 内部捕获并记录异常，单个事件失败不得改变已登录通道状态、阻塞后续 JSON Lines 或触发启动失败。
- 不因成员离群删除 stable member、群友画像、记忆或历史别名；这些属于历史数据，且本次事件不足以证明跨登录态身份应被清除。
- 日志只记录事件类型、稳定群、事件时间、成员数量、所用配置范围与发送结果线索；不输出完整模板、原始系统通知或不必要的微信标识。
- 本次不把成员事件伪装成普通聊天消息，不写入群消息归档或群友画像，不影响群聊报告统计。

## 6. Web 控制台方案

在现有“群聊”视图二级侧栏新增一个“进退群消息”入口，使用现有 Font Awesome 图标、颜色、暗色模式和主保存按钮，不为入群、离群各增加一个侧栏项，也不修改归档桌面端。

### 6.1 信息结构

1. 第一层使用分段控件切换“入群欢迎 / 离群通知”。
2. 第二层切换“全局默认 / 按群配置”。
3. 全局默认：该事件类型的启用开关、内容类型分段控件、文本编辑或图片上传/预览。
4. 按群配置：稳定群选择器、`跟随全局 / 自定义 / 关闭` 策略控件；仅在“自定义”时展开内容类型和内容编辑。
5. 文本区域根据当前事件类型展示不同的“插入变量”菜单和实时预览：入群显示真实 mention 前缀，离群只显示成员可读名称。
6. 图片区域提供上传、替换、移除草稿和固定尺寸预览；上传过程中禁用相关操作并显示状态。
7. 离群检测范围通过信息图标的可访问 tooltip 标明“当前 wechat4u 主要支持当前账号移除成员或当前账号被移出”，不增加大段常驻说明。

### 6.2 交互与可访问性

- 所有表单项使用显式 `<label>`，不能只依赖 placeholder。
- 开关用于启停，分段控件用于互斥模式，原生 select 用于群选择；触控高度至少 44px。
- 两层模式切换保持清晰层级和独立选中态；375px 下事件类型保留分段控件，配置范围可降级为原生 select，避免四组按钮拥挤或横向滚动。
- 切换事件类型、配置范围或目标群时保留两类独立草稿，不能互相覆盖或丢失未保存输入。
- 自定义内容按策略渐进展开，关闭或继承时字段禁用且状态清晰。
- 保存前做事件类型占位符、空内容、图片是否上传的就地校验；保存按钮展示 loading，结果通过现有 `groups-status`/`aria-live` 反馈。
- 图片预览声明稳定宽高约束并使用 `max-width: 100%`，防止加载后布局跳动和 375px 视口横向溢出。

重点自动化场景：

- sidecar 正确序列化两类事件的 room、members、operator、self 和 timestamp。
- 入群与离群分别覆盖全局文本、全局图片、按群自定义、按群关闭和无覆盖继承。

- self leave 会刷新群列表但保留长期 stable 配置，不删除历史成员身份、画像或记忆。
- 两类事件都不调用 Bridge/Agent，不写聊天消息归档，不影响正常 `message` 事件。

## 11. 风险、边界与回退

- **上游文案风险：** wechat4u 用正则解析微信 `SYS` 文案，微信改文案会漏报。通过真实链路验收和可读错误日志发现，不修改依赖包内部源码。
- **离群覆盖率风险：** 当前 wechat4u 主要识别当前账号移除成员或当前账号被移出，无法承诺普通主动退群和其他管理员操作；UI tooltip、README 与验收记录必须保持一致。
- **身份风险：** runtime ID 可能跨登录态变化。长期配置只用 stable room ID，未确认群 fail closed；离群不会删除历史身份数据。
- **重复发送风险：** 上游无消息 ID。使用包含事件类型且带 TTL/容量上限的派生键去重，并保持一事件一消息。
- **错误 mention 风险：** 入群使用 invitee runtime IDs 真实 mention；离群一律不传 leaver mention，避免对已不在群成员列表的对象发送无效或错误 mention。
- **模板安全风险：** 只允许事件类型白名单变量并做字面替换，不允许表达式、任意字段访问、内部 ID 或原始微信数据进入群消息。
- **读取线程风险：** 在 stdout reader 中等待 confirmed send 会死锁或超时；两类消息只排入现有非阻塞发送命令。
- **文件安全风险：** 不接受 URL和任意本地路径；上传、保存、预览、发送四处都限制在成员消息图片根目录。
- **兼容性风险：** 两类功能默认关闭，不改变消息回复、自由回复、群记忆、报告和其他渠道；不新增 Python/npm 依赖和数据库迁移。
- **回退：** 回退对应代码后旧版本会忽略新增配置键，成员消息图片留在持久化 workspace，不影响其他功能，可由管理员后续人工清理。

## 12. 实施前确认项

本计划按以下产品语义设计，开始编码前需要用户确认：

1. “全局”只覆盖 Web 中已选择的稳定微信群，而不是账号所在的全部群。
2. 同一次多人入群只发送一条欢迎，文本模式自动真实 mention 全部新成员。
3. 同一次多人离群只发送一条通知，离群文本仅使用可读名称，不 mention 已离群成员。
4. 入群和离群分别配置文本或图片；图片模式只发图片，暂不支持“文本 + 图片”组合。
5. 文本占位符只开放可读业务信息，不开放 runtime/stable ID、微信号、加入方式或离群原因。
6. 不做离线期间进出群补发，也不新增进退群历史、统计或主动退群旁路解析。
