# 微信群稳定身份自动恢复实施计划

> **供智能体执行：** 必须按测试驱动逐项实施；优先使用 `superpowers:test-driven-development`，完成后使用 `superpowers:verification-before-completion`。当前工作区已有稳定身份相关未提交改动，本计划在原工作区续做，不创建 worktree，也不擅自提交 Git。

**目标：** 取消微信群身份恢复的人工确认流程，在同一稳定账号下可信使用群名自动恢复 stable room，优先使用微信号自动恢复 stable member，并同步修复群名保存显示和被群筛选消息无 INFO 日志的问题。

**架构：** 保留现有 `stable_account_id -> stable_room_id -> stable_member_id` 和 runtime alias 双层模型。账号按强微信号或唯一 sidecar profile 自动恢复；群在同一 stable account 下按唯一完全相同群名自动恢复；成员只按非空强微信号自动继承旧 stable member，缺失或歧义时自动创建隔离 stable member，避免昵称冒充继承管理员权限。Web 不再提供人工确认入口，旧确认 API 返回“已改为自动恢复”，候选查询只保留为只读诊断兼容。

**技术栈：** Python 3、SQLite、Wechaty/Node.js sidecar、Web.py、原生 JavaScript、`unittest`、Node test runner。

### Task 2：实现账号、群和成员自动恢复状态机

- [x] **步骤 1：增加只读候选查询方法**

  在 store 中增加：

  - 按 `sidecar_memory_path + self_name` 返回唯一账号候选；
  - 按账号和精确群名返回全部群候选，调用方仅在唯一时复用；
  - 从 account/member 及 alias 的 JSON metadata 中读取 `wechat_id/weixin/wxid`，按作用域返回去重后的候选。

  微信号比较使用去空格和 `casefold()`；以 `@` 开头或纯长十六进制 runtime ID 不作为强微信号。

- [x] **步骤 2：实现账号自动恢复**

  `resolve_account()` 按顺序处理：强微信号唯一候选、当前 runtime alias、同 profile 唯一候选、创建全新账号。所有成功分支写 `status="confirmed"`，使用 `confidence="wechat_id" | "profile" | "runtime" | "auto_new"`，激活当前 runtime alias，返回 `requires_confirmation=False`。

- [x] **步骤 3：实现群名可信自动恢复**

  `resolve_room()` 按顺序处理当前 active alias、同 stable account 下唯一完全相同群名、创建新群。唯一同名命中时直接激活新 runtime room，写 `source_kind="auto_room_name"` 和绑定事件；多候选时不任取，创建新隔离 stable room。

- [x] **步骤 4：实现成员微信号优先和昵称隔离**

  `resolve_member()` 优先检查当前 `metadata.wechat_id` 的唯一候选，即使当前 runtime alias 曾被临时分配到其他成员，也应自动修正到强匹配 stable member。没有强微信号或强匹配歧义时，不调用名称候选继承旧 stable member，而是创建新的 confirmed 隔离成员；管理员配置仍只可能通过旧 stable member 的强微信号命中而继承。

## 三、验收标准

1. 同一账号重新扫码后，唯一同名群自动复用原 `wgr_...`，不再出现人工确认。
2. 群成员 runtime sender ID 变化且微信号相同，自动复用原 `wgm_...`；管理员权限随 stable member 自动恢复。
3. 微信号缺失或冲突时，同名成员不会继承旧管理员权限，而是自动获得隔离 stable member。
4. Web 控制台不再显示“身份恢复”页面或确认按钮，旧确认 API 不再执行写操作。
5. 群列表保存后，即使实时 rooms 暂时为空，也显示已保存真实群名，不显示“已保存群 1/2”。
6. 未选中群消息在 runlog 中有不含正文的 INFO 路由丢弃日志。
7. stable 配置仍只保存 `wgr_.../wgm_...`；runtime ID 仅作为发送和兼容快照。

### 实际改动

- `wechat_group_identity_store.py` 增加账号 profile/微信号、同账号精确群名多候选、群内成员微信号候选查询；兼容唯一空 profile 路径旧 alias 迁移，并让已 confirmed 实体的普通 inactive alias 不再进入待确认列表。
- `wechat_group_identity_service.py` 按强微信号、runtime alias、唯一 sidecar profile 的顺序恢复账号；按同账号唯一完全同名群恢复 stable room；按微信号恢复 stable member；缺失或歧义微信号时创建并稳定复用隔离成员；解析过程增加父级 confirmed 校验与进程级并发锁。
- `wechat_group_channel.py` 让自动恢复结果直接进入 stable 群筛选；用线程安全的当前登录会话群名/runtime 集合统一约束群列表和消息入口，新登录转换时清空、重复 `logged_in` 不清空；同名集合出现多个 runtime 后持续禁用群名恢复，并用同一 `RLock` 原子覆盖会话判断到 room 解析，避免瞬时失败重试或并发反序落库时误合并；群列表按不同 runtime ID 统计同名歧义，重复行仍可恢复唯一同名群；同时为 `unselected_room` 写不含正文和媒体路径的 INFO 日志。
- `web_channel.py` 将人工确认状态改为只读诊断，禁用三个确认 API 的写操作，并在保存时把可唯一解析的 runtime room ID 转换为 `wgr_...`。
- `console.js` 移除人工确认页面与交互，已保存群标签按“实时群名 -> `selected_room_names` -> 已保存群 N”回显；离线或未解析群保存时继续保留，只有明确取消或按 room ID 删除才移除。
- `test_wechat_group_profile_service.py` 的 suspected alias 安全用例改为显式构造候选，避免把新方案下已自动确认的同名群误当成待确认群。
