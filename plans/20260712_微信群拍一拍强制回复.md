# 微信群拍一拍强制回复实施计划

> 状态：已完成

## 目标

让个人微信群通道能单独识别 Wechaty 已上报的“拍一拍我”文本消息，并在目标为当前 bot 时按类似被 @ 的 direct reply 进入主回复链路。

## 设计取舍

- 不新增 sidecar 协议：当前日志证明 Wechaty 已把拍一拍作为 `message_type=text` 上报，文本形态为 `"一灯" 拍了拍我`。
- 不依赖 LLM 判断：在 Python 消息适配层解析固定语义，避免自由回复 judge 把它当普通群聊过滤掉。
- 只处理“拍了拍我”：目标为“我”时可认为拍的是当前登录账号，不处理 `"A" 拍了拍 "B"` 这类群友之间互动。
- 复用现有主链路：触发后仍走 `_compose_context()`、`produce()`、`Bridge` 和 Agent，不新增独立回复引擎。

## 涉及文件

  - 解析拍一拍文本，新增 `is_pat_self`、`pat_actor_name`、`pat_target_self` 等轻量字段。
- `channel/wechat_group/wechat_group_channel.py`
  - 将 `is_pat_self` 纳入 direct reply 判定。

- `CHANGES.md`

## 实际改动

- `WechatGroupMessage` 新增拍一拍解析：仅当文本匹配 `"发送者" 拍了拍我` 时设置 `is_pat_self = True`，并记录 `pat_actor_name`、`pat_target_name`、`pat_suffix`。
- `WechatGroupChannel.handle_text()` 将 `is_pat_self` 视作 direct reply，设置 `wechat_group_force_reply = True` 和 `wechat_group_trigger_source = "pat_self"`，跳过自由回复 worker。
- `WechatGroupChannel._build_reply_mentions()` 对 `pat_self` 回复返回空 mention 列表，避免把拍一拍系统消息里的群 ID 当作成员 ID。
- 新增测试覆盖消息解析、通道强制回复和拍一拍回复不误 mention 群 ID。

## 风险与边界

- 当前实现只基于已观测到的 Wechaty 文本输出，不推断未知 puppet 的其他原始 payload。
- 如果后续需要识别 `"A" 拍了拍 "小灯"` 或带后缀的 bot 昵称，需要单独增加目标名匹配规则和回归测试。
