# 生图代理域名配置计划

## 背景

切换到 Grok 生图模型后，上游会返回 `assets.grok.com` 图片地址。当前生图脚本会先下载远程图片到本地，再交给渠道发送；如果本机直连该域名失败，就会返回“图片生成失败，我这边没有拿到可发送的图片结果。”

## 目标

- 在 Web 控制台基础配置中提供代理地址配置，复用现有 `tools.web_fetch.proxy`。
- 在“图片与生图”配置页提供勾选项和域名列表，控制哪些生图结果图片域名走基础配置中的代理。
- 生图 skill 下载远程图片时读取上述配置；生成接口本身不强制走代理。
- 保持最小改动，不新增独立代理配置孤岛。

## 方案

1. 配置结构
   - `tools.web_fetch.proxy`: 代理地址，例如 `http://127.0.0.1:7890`。
   - `skills.image-generation.proxy_enabled`: 是否启用生图结果图片代理。
   - `skills.image-generation.proxy_domains`: 需要走代理的域名列表，例如 `["assets.grok.com", "*.grok.com"]`。

2. Web UI
   - “基础配置”新增代理地址输入框。
   - “图片与生图”新增“指定域名图片下载走代理”开关和域名列表输入框。
   - 文案说明代理地址来自基础配置。

3. 后端保存
   - 微信群配置接口保存 `tools.web_fetch.proxy` 与 `skills.image-generation` 代理字段。
   - 读取配置时返回给 Web UI。

4. 生图链路
   - `Channel._build_image_create_reply()` 把代理地址、开关和域名列表传给 `generate.py`。
   - `generate.py` 在下载远程图片 URL 时，只有 URL 域名命中配置列表且代理地址非空，才使用 `requests` / `urllib` 代理。

5. 验证
   - 增加脚本级测试：命中 `assets.grok.com` 时 `requests.get` 使用代理。
   - 增加通道测试：生图脚本 payload 包含代理配置。
   - 增加 Web 配置测试：保存和前端字段存在。
   - 运行相关 unittest。

- 更新 `config.py` 与 `config-template.json`：新增 `tools.web_fetch.proxy` 以及 `skills.image-generation.proxy_enabled` / `proxy_domains` 默认配置。

- 更新 `channel/web/web_channel.py` 与 `channel/web/static/js/console.js`：Web 控制台在基础设置展示代理地址，在图片与生图页展示生图结果域名代理开关和域名列表，并支持保存/回显。
