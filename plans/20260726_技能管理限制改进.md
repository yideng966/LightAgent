# LightAgent 技能管理限制改进

## 目标

在不引入自动更新、风险等级或安装审批的前提下，改善技能更新决策、原技能广场完整性、系统依赖准备、彻底卸载备份和脚本执行边界。

## 实施进度

- [x] Skill Hub Registry Schema v2：发布说明、破坏性变更、系统能力和结构化入口。
- [x] Schema v2 CI：拒绝未声明入口的脚本技能和正文直接执行脚本的说明。
- [x] `legacy_compat.json`：审核哈希、版本化依赖、分页审计报告和首次安装哈希锁定。
- [x] `skills.lock.json` v2：记录完整性来源、能力包、执行模式、入口和变更摘要。
- [x] 系统能力清单和探测：`office-documents`、`media-processing`、`browser-automation`。
- [x] Docker 能力包：`SKILL_CAPABILITY_PACKS`与 `skills-full` 发布变体。
- [x] `.laskill-backup`：scrypt + AES-256-GCM、一次性 10 分钟下载令牌、Web 导出/恢复/彻底卸载联动。
- [x] Skill Runner 第一阶段：请求快照入口、无 shell 参数执行、最小环境、保留环境变量拒绝、路径/超时/输出/内存/进程限制、POSIX 进程组终止与审计日志。
- [x] Web 状态和决策界面：完整性、能力、执行模式、发布说明、依赖/权限变化和加密备份。
- [ ] Linux/Docker 用户命名空间强隔离、域名代理与受限 Skill Executor：作为后续独立 PR，当前不宣称已具备完整沙箱。

## 兼容边界

- Registry v1 继续只读兼容；旧 lockfile 读取时自动补默认字段。
- 新发布的 Schema v2 脚本技能必须通过 `skill_run`；旧技能保留 compatibility 模式。
- 原技能广场清单外技能仍可直接安装，只能标记“首次安装锁定”，不得标记为官方签名。
- 系统包只在镜像构建或管理员部署阶段准备，技能运行时不执行 `sudo`、`apt` 或 `brew`。
- 更新始终由用户触发；后台只检查和提示。
